# dsh-result-clipper 设计

状态：设计树已收敛并逐项确认（2026-10-01 复核；2026-10-02 票 01 落入两条裁决——入口说明取样顺序见「原结果入口与保留」，memo 与隐私判断的先后见「隐私闸门」）。

`dsh-result-clipper` 同时提供工具结果摘要与隐私闸门。两项能力分别开关，默认关闭；摘要是主能力，隐私闸门是可选的尽力而为保护模式。两项同时开启时，隐私判断先于摘要。为摘要、隐私判断和摘要准入提供请求的模型统称**摘要模型**，它不执行主会话工具调用。

**作用范围**：两种模式都只介入本来会进入模型的工具结果内容。会话日志不是目标，只是继承已经替换过的投影的副作用；只进日志、不进模型的内容（例如 PTC 中途子调用副本）不处理。

## 摘要

摘要发生在工具结果进入主模型上下文之前。插件用程序结构化生成局部任务上下文（当前用户目标、当前步骤的助手意图、工具身份与参数、有上限的相关摘要），不复制整个主会话。

- **目标工具**：首版硬编码 `bash`、`web_fetch`、`read`（三者覆盖约 95% 的工具结果）。前提是目标工具**不得定义 `finalizeContent`**——已核实这三者都没有，全仓真正挂上该字段的只有 `terminal_*`、`job_*`（`tool-cordis` 的 API 目录里只出现该字段的类型声明文本，不是工具定义），因此这两类永久排除。
- **候选范围**：正文为文本、且估算长度 ≥ `minInlineTokens` 的结果。`bash`、`web_fetch` 另需 < `maxSummarizeTokens`（超过的交给 spill 接管）；**`read` 不设插件上界**——`read` 工具自身按 `readMaxBytes`（默认 50 KiB ≈ 12,800 估算单位）封顶，而 spill 硬编码豁免 `read`，所以只有被 spill 接管的工具才需要上界。含图片等非文本块的结果透传，不参与摘要与替换。
- **阈值单位**：DSH 估算器单位（4 字符/token）。沿用它是为了与 spill 的 `maxInlineTokens` 及既有阈值统计同单位；该启发式对中文低估约 2.5–3 倍，所以 1024 单位对纯中文正文大约相当于 2,500–3,000 个真实 token。`minInlineTokens` 默认 `1024`、可配，`0` 表示不设下限；`maxSummarizeTokens` 默认 `12500`、可配，只作用于 `bash`、`web_fetch`。上界是本插件自己的字段，**不读取 spill 的配置**；改它等于改谁来处理超大结果，部署把 spill 阈值改小时两者的交互必须在 README 写明。
- **摘要不缩短就透传**：摘要加入口说明不短于原文时，原文透传，且**不写 spill**（不产生无用的原文副本）。贴近 `minInlineTokens` 的结果常常落在这个区间：摘要输出上限 512 token 与 1024 估算单位的差距并不大。
- **摘要模型可以要求保留全文**：摘要与隐私两类请求都返回动作字段 `action: 'summarize' | 'keep'`。`keep` 表示这条结果本身就是要用原文的对象（典型是要逐行检查、照抄或对照的清单与文件内容——细节是用户点名的还是主模型自己接下来要用的都算）。**判据写在正文与调用形态上**：没有声明提取目标时，摘要请求里只有「本次调用」（工具名 + 关键参数）、估算大小、规则正文与工具正文，**没有用户原话**，所以旧版那条"用户明确要求逐字/逐行/完整查看"是观察不到的条件（实测 0/31 命中，见 `dsh-reasoning-effort-research.md`）；而"整文件读""同路径曾被摘过"这些形态现在由那份调用形态提供。程序保留原 `content`、不替换、**不写 spill**，与「不缩短即透传」共用同一条路径。判断「这次是否需要全文」由**摘要模型**承担——它是唯一同时看到正文与当前任务的组件；准入判断器看不到正文，只判断值不值得花一次调用，不承担这件事（两处术语分工见 `CONTEXT.md`）。
- **透传不是复述**：`keep` 只发一个信号，**不让模型把正文重新输出**。原文已在程序手里，复述只会重复付输出费、可能撞 512 token 输出上限被截断，并把逐字内容变成模型生成的近似物；隐私模式下更是让模型把整段正文再吐一遍。
- **去向必须可区分**：`unmodified` 的透传路径上，每条结果在 debug 记录里都有一条闭合的「动作 + 原因」取值（取值域见「干跑与诊断」）。判断结果（保留原文、未进入候选、摘要关闭等）与故障（调用失败、窗口不足）不得合并成一个布尔值，否则故障会被读成策略；`rejected` 只记动作、不附原因（`block` 下拦截本身在对话里可见）。
- **工作区指令与技能正文不经 `read`**：前者由 harness 在 `agent/pre-step` 直接注入成 user 消息，后者是 `skill` 工具自身的结果。前者完全不流经 `tools/post-execute`；后者是普通工具结果，**会**流经 `tools/post-execute`、因而仍落在隐私闸门的判断面上——「不经 `read`」只排除摘要候选，不排除隐私判断。因此不需要为「必须完整」的文件建立白名单或标记。模型主动 `read` 的文件才是同时暴露给摘要与隐私的面，靠 `keep` 动作与入口说明兜住。
- **重复读取判重**：隐私关闭时，同一会话内按**（工具名, 正文 hash）**判重——同一工具产出过同一份正文时，重复读取直接返回同一条摘要、不再调用模型（memo 在准入判断之前查找，命中即整条摘要路径短路；**只在隐私关闭时参与判重——隐私开启时不查找、不写入 memo**，两节对齐后的裁决与理由见「隐私闸门」的裁决 B）。key 不能用 `(path, offset, limit)`：`read → edit → read` 是高频序列，按参数命中会把修改前的摘要返给修改后的内容；加上工具名是避免把另一工具语境下的摘要复用到同名内容上。hash 变化即重新摘要。memo 会话内 LRU 200 条、会话结束清空；复用的摘要反映生成时的任务上下文，之后目标变化不会反映在旧摘要里（首版接受，代价记此）。**`keep`的结果不进 memo**：它没有摘要可复用，重复读取照常重新判断。
- **摘要准入判断**（独立开关，默认关闭）：摘要能力开启、摘要 memo 未命中、命中候选范围且隐私模式关闭时，先用不含工具正文的固定前缀请求一次只返回严格 `yes`/`no` 的判断。`yes` 才发起带正文的摘要请求；`no` 透传；其他输出、超时或失败按失败处理，直接发起带正文的摘要请求。隐私模式开启时跳过准入，直接走一次同时返回隐私结论与摘要字段的请求。
- **准入提示带上这次调用的形态与结果大小**：投给准入判断的固定前缀是两行——「本次调用：<工具名>：<关键参数>」（`read` 报整文件/分片与路径、shell 报 description 与命令头、`web_fetch` 报 url；字段口径与实测信号见 `dsh-reasoning-effort-research.md`）与这次结果的估算大小。两行都是元数据而非正文（命令头截到 120 字符），不违反「准入不读取工具正文」；**两行同时出现在摘要请求的固定前缀里**，以保持两次请求前缀逐字相同（汇总请求没有准入阶段，不加）。判断器仍然不知道剩余请求数，所以它判断的是相关性与体积，不是净收益——不要把它当成盈亏平衡计算。
- **准入与摘要的固定前缀缓存**只是性能观测，不是正确性前提；两次请求在语义上必须各自独立成立。
- **请求形态**：固定安全外壳 + 代码固定的结构化输出 schema；工具内容始终作为不可信数据分隔输入；页面只编辑规则正文与 few-shot 示例，安全外壳与 schema 改不掉。
- **规则正文的默认值与页面显示**：三份内置规则正文放在一个不 import 任何东西的 `src/rules.ts`，host 半拼装请求与浏览器半的文本域共用同一份文字（host 的 `summary.ts` / `admission.ts` / `privacy.ts` 都依赖 `@deepseek-ai/dsh-llm`，不能被打进客户端产物，抄一份到 `src/client/` 就会有漂移的第二份）。配置里的空串仍表示「没有覆盖」；文本域显示的是**当前生效正文**（有覆盖用覆盖，否则是内置默认）。文本域的编辑是**草稿**：点该行的「保存」才写回，失焦不写——所以改到一半离开设置再回来看到的是已保存的正文，没有半截改动；草稿与生效正文一致时「保存」禁用，草稿正好等于内置正文时保存走「清掉覆盖」而不是写一条逐字相同的冗余覆盖。「恢复默认」清掉覆盖、控件回落到内置默认。安全外壳与输出 schema 不进 `rules.ts`，页面改不到。
- **摘要请求的输入**：正文连同有上限、明确标注的 `additionalContexts` 一起送入（上限见“固定常量”），但只返回正文摘要；附加消息本身不被摘要，仍按 DSH 原有顺序进入后续请求。
- **失败语义**：模型不可用、超时、空结果、非法结果一律**原文透传**。任何路径都**绝不能抛**——`tools/post-execute` 抛错会把整个工具调用变成错误结果。
- **并发**：每条工具结果独立处理，不共享状态、不做全局串行；DSH 自己的工具调用并发池已经限制总数。

## 原结果入口与保留

- 被摘要的结果在替换前调用 `ctx.get('spillStore').saveText(...)`（`owner.sessionId`、`source{tool, toolName, callId}`、`suggestedName`、完整正文），把返回的 `locator` 与 `retrievalHint` 拼成入口说明**接在摘要正文之后**（**裁决 C，2026-10-05**：原先在最前）。顺序由上界与效果两头定：本替换结果只有几百字符，远低于旧结果裁剪器（`dsh-compaction-tool-result-pruner`，阈值默认 8192 字符）的触发线，而裁剪器同时保头 4096 与尾 1024，所以放末尾同样不会被裁；反过来，把路径放在开门第一句时，真实部署里 246 条带入口的结果有 47% 又被读回一次、其中 43% 是整文件一把读回——先让模型读到摘要、并自己声明「这是摘要、够用就别读、需要逐字核对时原文在此」更省往返。长度比较仍按裁决 A 在 `saveText` 之前做。
- **取样顺序（裁决 A，2026-10-02）**：长度比较发生在 `saveText` **之前**。程序先按「摘要正文 + 入口说明预留」与原文比较：不短就直接透传、不调用 `saveText`；只有严格更短才写盘并拼入口说明。入口说明的实际值由 `saveText` 的返回值给出（`locator` + `retrievalHint`），写盘前取不到，所以比较用它的**上界**——私有常量 `entryReserve`（默认 256 字符，按固定提示句加后端 locator 的保守宽度取值，不可配）。上界性质使「有写盘 ⟹ 实际总长严格短于原文」成立：`not-shorter` 只可能落在未写盘的一侧，因此「摘要含入口说明不短于原文时透传」与「`not-shorter` 路径不留下无人引用的存储副本」同时成立，也不存在先写后弃。代价是真实入口说明短于预留时，一小段本可替换的结果（至多预留与真实入口说明之差）被判为不缩短而透传，方向保守。顺序取反（先 `saveText`、再比较）在 `not-shorter` 一侧必然留下无引用的副本，故不采纳；写盘前取不到实际入口说明长度是这个上界存在的唯一理由，不是近似写法。**用例（本票固定，票 04 落地）**：摘要正文 + `entryReserve` ≥ 原文时，断言假存储的 `saveText` 零调用且 `content` 逐字不变；只有严格更短时才断言写盘一次、入口说明接在摘要正文之后。**假设（按 `AGENTS.md` 记录）**：`entryReserve` 是本部署入口说明的上界——默认本机后端是绝对路径加固定提示句，远低于该值；更长的远程 locator 不在首版验证面内。**假设失效时的行为**：若某后端突破该上界，实际总长可能不短于原文而结果仍被替换，这是该部署上的已知退化（首版只保证本机后端）；不加写后检测与回退路径，因为「写完发现不短再透传」正是不允许的先写后弃。
- **长度约束**：摘要加入口说明的总长度必须留在该裁剪器的阈值（默认 8192 字符）以内。当前摘要输出上限 512 token 天然满足；以后放宽摘要输出上限时必须重新检查这条。
- **保留与清理全部由 DSH 的 spill 后端负责**（本机后端：`cleanupPeriodDays` 默认 30 天、进程启动时扫一次，`0` 关闭）。插件不设条数上限、不自行清理、不解析 locator。
- **后端缺失或写入失败** → 该结果**透传不摘要**，以保住「没有入口就不摘要」的不变量。
- **入口确实可读**（已核实）：本机后端的 `locator` 是绝对路径，`retrievalHint` 是固定文案「Use read with offset/limit, or grep this path to search within it.」；fs 沙箱只限制写入（`writeText`/`editText`），读取不经沙箱，因此 read-only、workspace-write、danger-full-access 三种模式下模型都能读回原文。默认落盘位置是 OS 临时目录下的私有进程目录（`mkdtempSync(tmpdir(), 'dsh-spill-')`），沙箱部署无需搬家。
- `read` 读取摘要保存的入口时只跳过整个摘要路径（含准入判断，因而不发准入请求），仍经过隐私判断。**识别方式**：插件在会话内记住自己写出的每个 `locator`，一条 `read` 的 `file_path` 命中该集合即视为读回——只做字符串比对，不解析 `locator` 的结构或语义（「不解析 locator」与「记住自己写出的值」不冲突）；集合随会话失效，重启或 fork 后同一入口会被当作普通 `read`（会再摘要一次）。本条不能用摘要 memo 代替：读回后的正文是 `read` 的渲染结果，与被摘要前的正文 hash 不同。重读不得跳过 `fs/observed` 的真实 version 发射；验收覆盖「同一 turn 先 read 后 edit」与「read 被摘要后再 edit」两种顺序，都不得出现 `FS_NOT_OBSERVED`。

## 隐私闸门

- **判断面**：`await next()` 返回的决策内容与附加上下文，也就是**模型即将看到的内容**（spill 处理后的正文），含 PTC 子调用递延到外层结果的图片与附加上下文。原始结果先截断再判断会漏掉模型真正看到的部分，所以判断对象是下游处理后的投影，不是原文。
- **只判文本**：分类器只接收投影中的文本，不接收图片块；含图片的结果按其文本判定，图片内容不参与隐私判断，README 明确写出这一点。运行在本插件**外层**的其他监听器可能在我们的决策之后追加附加上下文，那部分不被判断。
- **不设附加消息上限**：隐私模式请求把完整投影交给本地 route；长度上限只约束摘要模式。
- **合并请求**：隐私模式固定返回 `privacyVerdict: safe | sensitive | uncertain`、`action: 'summarize' | 'keep'` 与 `summary: string | null` 三个字段。`action` 与 verdict 正交：`safe` + `summarize` 替换正文，`safe` + `keep` 保留原文；判定为 `sensitive` 或 `uncertain` 时 `action` 无意义，提示词要求 `summary` 为空，程序始终忽略该字段。**`uncertain` 因此连带取消摘要**：该结果既不摘要也不拦截，按失败策略放行原文。这是有意选择——不在未判断成功的前提下继续加工内容；代价是本地模型常拿不准时摘要收益下降。已否决「不确定时再单独发一次摘要请求」，它会在这种情况下稳定翻倍调用。
- **失败策略**（全局配置）：`sensitive` 始终拒绝；`uncertain` 与技术失败按 `passthrough`（**默认**）或 `block` 处理。默认选择 fail-open，因此**失效必须可见**（见下）。
- **窗口不足单列**：本地 route 的服务窗口可能小于投给它的投影长度（中文下 spill 的 12500 估算单位约合 3 万真实 token）。**不做超窗预检、不预先跳过请求**；底层报告上下文溢出时按「窗口不足」单独归类，在会话提醒与 debug 日志里与普通判断失败区分开，README 给出本地窗口的建议下限（32k 起步，中文场景 48k 更稳）。
- **拒绝形状**：使用原生 `{kind:'block', feedback:[固定文案]}`。结果按失败标记，反馈为固定、不可编辑的文案，工具附带的上下文一并丢弃；失败策略 `block` 与 `sensitive` 使用同一形状。模型只看到这段文本：DSH 不追加任何系统提示，`error.info` 也不持久化，所以下一步指引必须写在文本里。
- **拒绝文案三段**：① 陈述该结果经本地隐私判断被拦下、原文未提供，并带上工具名；② 明确不要重试，也不要换工具或改参数再取同一内容；③ 给出允许的下一步——确需该内容时用 `ask_user_question` 请用户决定，或在回复中说明。文案不写参数与正文，也不依赖 `error.info`。措辞照 DSH 既有模式（工具描述里的策略拒绝、会话修复消息都是「陈述事实 + 禁止盲重试 + 给出允许的下一步」）。
- **本地 route**：复用 DSH provider route；摘要、摘要准入判断与隐私闸门三个角色各有自己的 route，后两者未配置时跟随摘要 route。隐私模式要求用户在页面**明确确认隐私 route** 是本地的；插件只提交 `provider` 与 `model`，读不到端点的 `baseURL`，因此既无法自动证明，也不通过 `baseURL` 猜测。未确认视为配置失败，按失败策略处理并显示警告。该确认是对**具体 route** 的声明：隐私组的 provider 或 model 一改，确认随即作废（见「配置面与设置座位」一节），不会跟着新 route 继续放行。
- **失效可见性**：设置页插件卡片常驻警告只覆盖**静态配置状态**——隐私 route 未被用户确认为本地；该状态可从设置读取，不依赖运行期推送。运行期的失效放行**不**进卡片警告（设计文档不要求新增 host→client 瞬时状态通道）：按 `passthrough` 放行时，同一会话内**每类原因各追加一条**插件 user 消息（至多三条：未能判断 / 判断失败 / 窗口不足），同一类原因只提醒一次，文案按原因区分、不含任何正文。写法照 `dsh-navigator` 先例：`source`（含插件 kind）属于消息体，`append` 的第三个参数只接受 `surfaceOp` 与 `sourceEventSeqs`——把 `source` 放进第三参会**被类型检查直接拒绝**（`SurfaceIntent` 无该字段；`append` 自身只从第三参取这两项，不会因多余字段报错）。该消息不得伪装成真实用户消息——多个 DSH 消费方按 `source.kind === 'user'` 判定真实用户介入。
- **误拦的恢复**：拦截在对话里天然可见（一次失败的工具调用加拒绝文案）。用户在设置页关掉隐私开关即恢复；开关与参数用 volatile 声明，**保存后立即生效，不需要重启**。首版不做拦截记录面，也不做「本会话临时放行」按钮。
- **代价**：隐私判断不设长度门槛，所以**每个标准工具结果**都会加一次本地模型往返（不只目标工具；`grep`、`edit`、`ask_user_question` 的结果同样会过闸），`web_fetch` 默认除外（`webFetchPrivacyGate`，2026-10-05）。超时固定 20s；默认 fail-open 时超时等于静默放行，只由会话提醒与 debug 记录可见——同一类原因在该会话只提醒一次，之后的同类失效不再重复提醒。这代价是「不漏大结果」这一取舍的直接结果：缩短超时只会漏得更多，所以超时不开放配置，慢的部署应当换更快的本地模型。
- **memo 与隐私判断的先后（裁决 B，2026-10-02）**：「摘要」的重复读取判重条与上一条代价条对齐后的裁定是——**隐私开启时 memo 不参与判重**：程序在隐私模式下不查找、不写入 memo，每个标准工具结果都照常走一次隐私判断（请求形状见「合并请求」条），代价条因此逐条成立；隐私关闭时的 memo 语义不变（在准入判断之前查找、命中即整条摘要路径短路）。对齐依据：合并请求一次产出 `privacyVerdict` 与 `summary`，memo 命中若短路该请求就必然连带跳过本次隐私判断，与「每个标准工具结果各得一次隐私判断」冲突；若命中仍照发该请求，memo 便不省下任何一次调用。唯一能让两者并存的写法是命中时改发一次只要判断、复用 memo 摘要的请求——它只为省下摘要输出那段 token，却要新增第二种请求形状、并改「固定输出」的契约，按 `AGENTS.md` 的复杂度控制原则不采纳。**用例（本票固定，票 05 / 07 落地）**：隐私开启、同一工具同一正文连续出现两次时，断言两次各发一次隐私判断请求（假 route 计数为 2），第二次仍可被拦；隐私关闭时同一对结果只发一次摘要请求、第二次命中 memo。**适用范围**：票 05 的 memo 只在隐私关闭时生效，票 07 的隐私判断逐条进行。

## 监听器位置、PTC 与观察面

- **监听器位置**：注册为 `prepend`，并且**必须装载在 spill-policy 之后**。两个 `prepend` 监听器之间后注册的先跑，因此本插件这时位于 spill 外层：先 `await next()` 让 spill 完成截断，再对模型将看到的内容做判断。若装载顺序相反，行为退化为对原文判断——拦截偏保守、请求可能超出本地窗口，**退化方向是安全而非损坏**，但这是已知的装载顺序影响。
- **双视图**：监听器的第二个参数 `result` 是未经 post-execute 链处理的原始投影，用于**摘要资格判断**（原文长度必须 ≥ `minInlineTokens`，`bash`/`web_fetch` 还要 < `maxSummarizeTokens`）；`await next()` 的决策用于**隐私判断**。不这样分，一条超大结果在后 spill 视图里只剩头尾，会被误判为摘要候选，于是去摘要 spill 的预览、再把预览存一份，形成双重落盘。
- `exec.parent !== undefined` 是当前唯一可用的「非模型直连派发」判据：全仓唯一的产品级生产者是 PTC，仓库自身多处用同一谓词表达同一含义，也没有更精确的「不进模型」标志。残余风险是演化性的——若将来有别的复合工具转发该标记，那些结果会被静默跳过。
- **必须跳过 PTC 子派发**：子派发与普通派发走同一条 `tools/post-execute`，用 `exec.parent !== undefined` 识别后直接 `next()`（spill 使用同一判据）。理由是子派发的结果只是程序内部的中途值：对它返回 `block` 会让沙箱程序抛错，带 `value` 的决策会替换程序收到的值，替换 `content` 则会改写持久日志副本。插件只处理外层最终结果。
- **隐私判断覆盖 PTC 的外层 `run_code` 结果**：它是普通派发，走 `tools/post-execute`，是模型唯一能看到的 PTC 内容；子调用延迟给外层的图片与附加上下文也并入该结果的投影。只有 prepare、pre-execute 或守卫失败才走 `final-result` 旁路。
- 首版**不注册** `tools/ptc-dispatch-log`：那条接缝只改持久日志副本，不影响程序与模型，属于“不介入中途过程”。因此 PTC 中途子调用的正文仍会作为 `tool/ptc-dispatch` 事件进入会话日志并可能被上传——这是写进 README 的保护面缺口，不当作遗漏。
- 我们返回的决策是最终决策，spill 已在 `next()` 内跑完。因此判为敏感时，**spill 可能已经把全文写入本地存储**——`SpillStore` 只有 `saveText`、没有删除接口，插件撤不回。这些文件私有、按会话分组、只受后端保留期约束；模型看不到内容，也拿不到 locator。`read` 被 spill 硬编码豁免，因此不涉及。
- `finalizeContent` 在 `tools/post-execute` 之后执行，且是模型可见的最后一跳；只有 `terminal_*`、`job_*` 定义它，这正是目标工具必须逐个确认的原因。
- **诚实边界**：可观察范围是普通派发（含外层 `run_code`）的 `tools/post-execute` 结果；`final-result` 旁路（prepare、pre-execute、守卫失败）与 PTC 中途日志副本不保证；普通 `tool/result` 的 session-log 继承已经替换过的投影。这是尽力而为的保护目标，不是安全承诺。
- `final-result` 旁路产生的错误结果**会进入模型但本插件收不到**，其中常回显工具参数。本设计接受该缺口；若上游将来提供覆盖这些结果的接缝，插件可零结构改动接入——记为上游备忘，不阻塞首版，也不作为本插件的依赖。
- 元数据 `meta` 会进入持久化、界面或会话日志，不属于模型可见内容，插件不改动它。文档**不得宣称降低上下文占用**——`contextBreakdown` 没有工具结果这一维。

## 与默认组合的共存

默认 bundle 已启用 `ptc-runtime`、`workflow-ptc`、`spill-local`、`spill-policy`（`maxInlineTokens: 12500`）和 `dsh-compaction-tool-result-pruner`（`packages/bundle/base/cordis.patch.yml:390-421`）。

- 与 `dsh-reasoning-pruner` **正交**：它只读助手消息的重放信封与当前表面位置，不依赖任何工具结果内容，也不注册 `tools/post-execute` 或 `tool/result`；本插件只改工具结果 `content`，不会使它的裁剪目标失效。
- 与 `dsh-compaction-tool-result-pruner` 的交互只有一处：它只处理超过 `thresholdChars`（默认 8192）字符的当前工具结果，因此摘要通常不被改写；入口说明接在摘要正文之后、并守住长度约束（见「原结果入口与保留」）。
- 与 `spill-policy` 的相对位置是行为的一部分：本插件在它外层运行（两者都 `prepend`，本插件后注册），所以隐私判断看到的是 spill 截断后的正文。装载顺序相反时退化为判断原文，方向保守。
- 不检测、不读取其他插件的配置：共存约束以上述静态规则表达，不引入对别的插件配置的依赖。

## 配置面与设置座位

- 开关放在「设置 → 内置插件」；参数放在装它的那个包自己的详情页配置区。
- 座位：插件自身的 profile 条目即 settings 命名空间（`SettingsNamespace`，Host 侧由 `ctx.settings.describe()` 投影出表单）+ 浏览器半注册一个 `plugins.bundle.config` 配置区（keyed 槽位，键是包名 `@dsh-clipclop/dsh-result-clipper`；`view: 'page'`，经 `ctx.configForms.get(ns)` 取得该命名空间）。本插件按 profile bundle 装载（`dsh.bundle.patch` + `dsh.profile.bundles`），插件管理器给它的卡片是包卡片，而包详情页只渲染按包名索引的 `plugins.bundle.config`；注册到 `plugins.item` 会落在分组里的另一张「官方插件」卡片上，包卡片详情页仍是空的（`@deepseek-ai/dsh-client-ui-settings-web-search` 那条先例是内置插件、不按 profile bundle 装载，所以它的 `plugins.item` 座位不适用于本插件）。恢复默认按字段分两种语义：推理档位、摘要下限、摘要上限与三份提示词规则正文回到 schema 的内置默认（提示词以 `op: 'unset'` 清掉覆盖），其余字段回到上一次保存的值。需要「保存即生效」的字段在 schema 上声明 `volatile`。不需要 YAML 兼容路径。
- **固定常量**（页面只读展示，不开放配置）：摘要模型请求的超时 20s；相关摘要 ≤3 条、每条 ≤600 字符；`additionalContexts` ≤2,000 估算器单位；摘要输出 ≤512 token；重复读取 memo 上限 200 条。固定前缀的字段与长度上限由程序控制，页面不开放任意扩大上下文。
- **可配**：两项能力开关；摘要准入判断开关（默认关闭；**在准入组里勾选，未启用时整组收起**）；摘要 route 选择（`routeProvider` / `routeModel`）与准入、隐私两个角色的 route 选择（留空跟随摘要 route；**换 provider 时不属于新 provider 的 model 会被清空**）；「隐私 route 已确认为本地」确认位（仅隐私模式要求）；`minInlineTokens`（1024，按 token 估算）；`maxSummarizeTokens`（12500，只作用于 `bash`/`web_fetch`，按 token 估算）；失败策略（`passthrough` | `block`）；三类请求各自的推理档位（留空＝不推理，候选与可用性都来自该 route 声明的档位表，见「推理档位的取值与降级」）；摘要/隐私/准入提示词的规则正文；debug 开关与路径；干跑（默认关闭）。端点的 `baseURL`、协议与凭据不在插件配置里：它们由 LLM 适配器按 route 持有，「设置 → 模型」是配置入口；本插件只提交 `provider` 与 `model`。
- **provider 与 model 的候选来自 DSH 自己的模型目录**：卡片用 `remote.session.modelCatalog()`（「设置 → 模型」那一页的同一来源）填两个 `<select>`——provider 候选是目录里的 route，model 候选是该 route 的模型（换 provider 就换一批）。卡片每次挂载重读一次目录（用户通常是先去模型页建 route、再回来选它），装载时也读一次。**这层「读不到就用不上候选」只覆盖读失败**：`remote` 与 `remote.session` 是按 DSH 惯例硬声明的依赖（读某个 namespace 的业务包要自己同时声明 `remote` 与 `remote.<namespace>`，`docs/api-gateway.zh.md:60`；第一方先例 `ui-model-selection/src/client/index.ts:107` 同款），服务缺席时整个客户端半不装载（页签与卡片都不出现），走不到这里的退化路径。插件不为这次读新增客户端依赖：只用到一个方法、一个返回形状，就地声明最小结构（与 `ResultClipperSettingOp` 同一取舍）。
- **候选之外的值不丢，也不把部署锁死**：候选是 `<select>` 而不是 `datalist`——`datalist` 只按输入内容过滤，选好之后展开只剩当前那一项（票 12 跟进 #6 的实测反馈）；而纯 `<select>` 会把「目录暂不可用 / 目录查失败 / 私有 model id」这三种情况变成不可配置，所以每一行另有「自定义…」入口切到文本输入，再从「从目录里选」切回来。目录读不到（候选为空）时控件直接是文本输入，与加入候选前逐字相同；当前值不在目录里时它作为一条带「（不在目录里）」后缀的选项保留，不会因为渲染而被清掉。**目录外的值也能清掉**：置空项与「不在目录里」那条选项并存，前者永远在第一位。
- **一行放得下，控件照搬「设置 → 模型 → 提供商」那一页**：每个角色分组的 route 行是三格——provider、model 与推理档位并排；摘要的两个阈值是独立的两格一行。输入类控件（单行输入、下拉、文本域）共用一份 `INPUT_STYLE`，取值逐条抄 `ModelsSection.module.css` 的 `.input`：`height: 32px`、`0.5px solid var(--dsw-alias-border-l4)`、`var(--dsw-radius-md)`、`var(--dsw-alias-bg-layer-1)`、`14px/22px`。下拉另加 `.selectInput` 那三样：`appearance: none`（替掉系统箭头）、`background-image` 用同一枚 12px 雪佛龙数据 URI 内缩到 `right 12px center`、`max-width: 240px`（枚举值都短，整格宽的枚举框读起来像待填文本框）。**这是本卡片唯一一处抄外部样式的决定**，理由是用户直接点名那一页好看，控件长得像同一套卡片才不像半成品。两处已知代价：① 没有 CSS 管线，伪类（`:focus` / `::placeholder`）内联不了，焦点态留给浏览器的默认焦点圈（那一页是用 `border-color` 换来的，本卡片拿不到）；② jsdom 不保留 `background-position: right 12px center`（cssstyle 不支持「关键字 + 长度 + 关键字」），所以「雪佛龙内缩 12px」只能对着那一页的 CSS 逐字核对，测试里断言不到。**按钮不在这两处代价里**：四个按钮（每组的「保存 / 恢复默认」与两处「自定义… / 从目录里选」）用 `ui-primitives` 的 `Button` 原子（两组 `outline`，两处小入口 `ghost` + `sm`），`:hover` / `:active` / `:disabled` 由包里那份 CSS module 提供，`.button` 与输入框同一档圆角（`--dsw-radius-md`）——它与页签的 `Switch` 是同一条路：同一个平台模块表，不是本插件新增的依赖。分组标题下的说明是**用户逐字定死的三段原文**，只讲这个设置带来什么（摘要：节省缓存计费、上下文更干净、可提升模型效果，清空等于请求不发、结果原样透传；准入：省下不值得摘要的结果的 token 费用、强烈建议跟随摘要模型、不启用会直接走摘要模型；隐私：判定敏感在进主模型之前拦下、敏感内容不会发往外部网络、应该设成本地模型）——不再有「好处：/怎么设：」这类层级，「只留」是用户的原话。provider 与 model 的下拉第一项是**置空项**（摘要组「不设置（清空）」、准入与隐私组「跟随摘要模型（清空）」）：选中它、点该组「保存」，字段回空串——准入与隐私回空串即回到跟随摘要模型，摘要回空串即摘要不生效（`src/index.ts:249` 的 `provider === '' || model === ''` 直接 `unchanged('failed')`：请求不发、结果原样透传，这与 `failurePolicy` 无关，那是隐私路径的字段），没有单独的「撤销」通道。
- **换 provider 时 model 跟着走，隐私组的确认位跟着 route 作废**：model 属于某一对 (provider, model)，换 provider 后旧的 model id 通常在新 route 上不存在——那样会留下一个「（不在目录里）」的孤儿取值，host 侧只会当失败路径处理。所以 provider 改动时若当前 model 不在新 provider 的候选里就清空它（provider 被清空时同样清空）；目录读不到（候选为空）时不猜，保留手填值，免得把「手工填 provider + model」的部署变成不可配置。同一条 helper 还负责隐私组的「已确认为本地」：那个确认是对**具体 route** 的声明，而 host 侧只读这个裸布尔（`src/index.ts:313`，不校验它对应哪条 route），所以隐私组 provider 或 model 一变，确认位就在草稿里清掉、必须重新勾选——否则换一条没确认过的 route 会沿用旧确认继续放行，把敏感正文发往外部网络。判据在 `card.tsx` 的 `changeRoute`（三个角色共用一份；`confirm` 只有隐私组传）。写入用的是同一次原子保存：确认位与被改的 route 一起落库，不存在「route 生效了、确认还没失效」的中间态。
- **端点与凭据为什么不进插件配置**（票 12 核实）：`GenerateOptions` 只有 `provider`、`model`、`reasoningEffort` 等字段，**没有 `baseURL` 或 `apiKey`**（`packages/llm/llm/src/types.ts:511-553`），所以插件无法把一个端点塞进某次请求；route 由适配器按自己的 profile 建立，pi-ai 适配器的 profile 才带 `baseURL`、`api` 与 `apiKeyEnv`（`packages/llm/llm-pi-ai/src/config.ts` 的 profile schema；`packages/llm/llm-pi-ai/src/index.ts` 的 `resolveApiKey` 走 credentials seam），而 GUI 的「设置 → 模型」页就是给自定义 route 填 `baseURL` 与 API key 的入口（`packages/client/ui-settings-models/src/client/CustomProviderCard.tsx`）。要三个角色用不同端点，就在那里建三条 route，再在插件里按角色各选一条。
- **三个角色各自成组**：配置区按「摘要模型 / 摘要准入判断模型 / 隐私闸门模型 / 诊断」分组，每个角色的 route（`provider` 与 `model` 并排）、推理档位与提示词规则正文同属该组；摘要的两个阈值也归摘要组，组间用一条横线隔开。分组是座位约定的一部分：看一个角色的设置不需要跨组找控件。
- **摘要准入判断的启用位在准入组里，不在页签**：它是「先有一条 route 才有意义」的开关，所以跟它的 route、档位与提示词同组——未启用时整组收起（收起＝不启用，整组设置不渲染），勾选后展开，改动随该组的原子保存写回。这样同一个字段只有一条写入路径（页签那套是立即写 `set`，两处并存会让同一字段有两套语义）。页签因此只剩摘要、隐私、debug、干跑四个开关。
- **每组是「草稿 + 保存」**：控件只改本组草稿，点该组的「保存」才把**该组全部改动**作为一次原子写入提交——底层是 `ConfigForm.mutate(ops)`，多个 op 共用一个 revision 栅栏、一次 Host 校验与一次持久化决定，所以不存在「一半字段生效」；被拒时整组不生效、该组显示失败，草稿保留（用户改完可以直接重试）。页签那四个能力开关仍是 `set` 的立即写：它们是能力开关，不是参数。
- **「恢复默认」的两种语义**：推理档位、摘要下限、摘要上限与三份提示词规则正文回到**内置默认**（提示词的默认是内置规则正文，草稿回到它时保存以 `unset` 清掉覆盖，不写一条与内置正文逐字相同的覆盖）；provider、model、隐私确认位、失败策略与 debug 路径回到**上一次保存的值**（即丢弃未保存的改动）。前者不能「回落到已存值」，否则改坏的阈值与提示词没有一键恢复的路径；后者不能「回落到空」，否则确认位与 route 会被清掉。草稿在 Host 侧取值变化时（保存被接受，或别处写入）整体重新播种。
- **推理档位的取值来自 route，插件不内置候选词表**：档位 id 由每条 route 声明（DSH 的 `LlmModelReasoningInfo { efforts, defaultEffort? }`；适配器只承诺"展示顺序"，不承诺升序）。配置里**留空＝「不推理」**，请求前按该 route 的档位表解析：`off` → `none` → 已知次序（`off`/`none` < `minimal` < `low` < `medium` < `high` < `xhigh` < `max`）里最低的那一档 → 声明的第一个（表里全是未知 id 时才走这一档）。显式值在表里就下发；不在表里时它发出去只会被拒，所以按「不推理」解析（与卡片上显示的生效档位一致，而不是留一个发不出去的值）。档位表按 provider+model 缓存（`src/efforts.ts`）：一条 route 每进程只成功解析一次，之后都是内存查表；解析失败**不缓存失败**（下次再试）；设置写入清空缓存。**表读不到时**显式值原样下发，并保留票 09 的一次性重试（`UNSUPPORTED_REASONING_EFFORT` 在 provider I/O 之前抛出 → 去掉该字段重发，即按该 route 的默认档位发；route 声明了 `defaultEffort` 时就是这个默认档位，这是「去掉字段 ≠ 一定不推理」的固有边界）。卡片的候选来自模型目录里的 `reasoning.efforts`（与「设置 → 模型」同源），标签直接用 route 给的名字，所以用户看不到也不需理解各家词表的差异（cline-pass 是 `none`、deepseek 是 `off`）。根因与实测见 `.scratch/dsh-result-clipper/design-draft-reasoning-effort.md`。
- 页面加一句静态警告：摘要与隐私分别把工具正文发送给各自所选 route。

## 干跑与诊断

- **干跑**：走完整条流水线（准入、隐私、摘要），但绝不替换任何内容、绝不 append 会话事件、**也不调用 `saveText`**（写盘同样是改变状态，且会在共享存储里留下无人引用的文件）、**也不写 memo**（否则会改变随后真实运行的行为）、**也不查找 memo**（查找会刷新最近使用次序，同样是会改变随后真实运行行为的写入），只在 debug 日志里记录「本应发生什么」（本应替换 / 本应拦截 / 本应跳过及原因）。干跑记录在 debug 的字段形状上多一个 `dryRun: true` 标记，动作与原因就是预报值——同一个日志里真实记录与干跑记录因此可分辨，且真实记录的字段形状不变。干跑记录受 debug 的同一条禁写约束，所以「本应替换」只记动作与原因，不记摘要文本，也不记入口（入口由 `saveText` 产生，干跑不调用它）。它要求 debug 开关已开启且路径已配置：两者缺一时干跑不生效并在页面提示，因为干跑的产出就是这条日志（这条同时也保住了「debug 关闭时零写盘」的不变量——干跑不是它的例外）。
- **debug** 默认关闭。开启后路径必填，插件创建父目录并以追加方式写入 metadata JSONL（工具名、结果大小、准入结论——隐私模式跳过准入时记为不适用、结果取值、调用耗时、缓存观测、判断器输入 token 数）。**两个观测字段的口径**：`缓存观测` 记这条结果的各次模型请求里命中前缀缓存的输入 token 数之和（没发请求或底层没报告用量时为 `0`）；`判断器输入 token 数` 记准入判断那次请求的输入规模（未缓存、缓存读、缓存写三种输入 token 之和；没发准入请求时为 `null`）。**结果取值是封闭的两段式**：动作取 `summarized` / `rejected` / `unmodified` 之一，`unmodified` 必须附原因（`not-candidate` / `admission-no` / `kept` / `not-shorter` / `read-back` / `uncertain` / `summary-off` / `failed` / `failed-window`）；**窗口不足与普通失败必须是不同取值**，判断结果与故障也不得合并；`kept`（摘要模型要求保留全文）与 `read-back`（插件识别出按入口读回而主动跳过摘要）也不得合并。不写原文、摘要正文、完整提示词、凭据；不自动切换到临时路径。

## 当前范围与非目标

- 首版只做固定的目标工具（`bash`、`pwsh`、`web_fetch`、`read`；`pwsh` 是 Windows 上 shell 的注册名，2026-10-05 补入）；不做按工具声明的可重取性（需要 DSH 新接口）。
- 不做「同一会话内记住已判敏感的调用并确定性重拦」。分类器是概率性的，重试可能改变结果，但尚无证据表明模型会靠重试绕过；先用拒绝文案的「不要重试」约束，实测出现重试钓鱼再加。
- 不在**读取层面**做去重（即不因为「这段区间此前读过」就跳过读取或省掉隐私判断）。若以后要做，判据是「本次区间被同一文件版本的已读区间**完全覆盖**」（参数相同只是特例），且那次已读记录必须仍在模型可见历史里且未被改写，并且绝不跳过 `fs/observed` 的真实 version 发射。摘要本身的复用是另一件事，按正文 hash 判重（见「摘要」）。
- 不改造 spill-policy，不修改 DSH 源码或公开契约。
- 不做隐私请求的超窗预检，也不分块判断：超窗按「窗口不足」这一类失效处理并提醒，替代方案（用 route 的 `contextWindow` 预先跳过、或分块判断）留作后续项。
- 不把敏感内容从已落盘的 spill 存储里撤回：后端没有删除接口，本设计接受这一后果并写明。
- 提示词的具体措辞不在验收范围内，只验收「固定外壳与 schema 改不掉、可编辑段只替换规则正文与 few-shot」的拼接方式。
- 不额外做界面徽标：被拦截的可见面就是原生失败反馈，被摘要的可见面就是正文里的入口说明。

## 验收要点

- 目标工具逐个确认不定义 `finalizeContent`，并有守护测试（`pwsh` 的工具包只在 Windows 部署里存在，所以守护测试覆盖本机装得到的那几个）。
- **PTC 子派发被跳过**：用带父派发的夹具断言监听器不改变子派发结果，程序不会因 `block` 抛错。
- **双视图生效**：原文 ≥ `maxSummarizeTokens` 且被 spill 截断的结果不被判为摘要候选，不发生双重落盘；`read` 的大结果（无插件上界）正常进入候选。
- **重复读取判重按（工具名, 正文 hash）**：隐私关闭时同内容复用同一条摘要、不额外调用模型；文件被修改后 hash 变化、重新摘要；隐私开启时不查 memo，每条结果各判一次（裁决 B）。
- **摘要没有缩短**（含入口说明也不短于原文）时原文透传，且不发生 spill 写入。
- **`action: 'keep'` 生效**：模型要求保留全文时正文逐字不变、不写 spill；`keep` 的结果不进 memo，再次读取照常重新判断。
- **去向与原因取值互不相同**：准入判 `no`、`keep`、按入口读回、摘要没变短、未进入候选、`uncertain` 放行、普通失败与窗口不足在 debug 记录里可分辨；动作与原因的两段式取值覆盖 privacy 路径的放行、`rejected` 拦截与摘要关闭。
- **准入前缀与摘要前缀逐字相同**（含调用形态与结果大小那两行）。
- **窗口不足可区分**：底层报告上下文溢出时，归类为「窗口不足」而不是普通判断失败，并按失败策略处理。
- 摘要失败、空结果、非法结果、超时一律原文透传；任何路径都不得抛出。
- `sensitive` 一律拒绝；失败策略 `passthrough` 与 `block` 各自生效。
- `read` 的两种顺序都不出现 `FS_NOT_OBSERVED`；按入口读回（路径命中本会话写出的 `locator`）时不再次摘要但仍过隐私判断，会话失效后同一路径按普通 `read` 处理。
- spill 后端缺失或 `saveText` 失败时透传且不留入口。
- **替换后的落盘内容被 token 计量器读到**，自动压缩的触发随之推迟（旧调研把它列为必须验证的一项）。
- 干跑不改变任何模型可见内容、不 append 会话事件、不调用 `saveText`，并在 debug 日志里留下「本应发生什么」的记录；debug 开关关闭或路径为空时干跑不生效。
- debug 日志不含原文、摘要正文、完整提示词与凭据。
