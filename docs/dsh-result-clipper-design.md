# dsh-result-clipper 设计

状态：设计树已收敛并逐项确认（2026-10-01 复核；2026-10-02 票 01 落入两条裁决——入口说明取样顺序见「原结果入口与保留」，memo 与隐私判断的先后见「隐私闸门」）。

`dsh-result-clipper` 同时提供工具结果摘要与隐私闸门。两项能力分别开关：**摘要默认开启**（默认只摘要主模型主动请求摘要的那些结果），隐私闸门默认关闭；摘要是主能力，隐私闸门是可选的尽力而为保护模式。两项同时开启时，隐私判断先于摘要。为摘要、隐私判断和摘要准入提供请求的模型统称**摘要模型**，它不执行主会话工具调用。

**行为层面的判据（一次结果什么时候发请求、什么时候透传、debug 每个取值对应哪条出口）记在 [`docs/dsh-result-clipper-pipeline.md`](dsh-result-clipper-pipeline.md)**；本文件讲设计取舍与依据。

**作用范围**：两种模式都只介入本来会进入模型的工具结果内容。会话日志不是目标，只是继承已经替换过的投影的副作用；只进日志、不进模型的内容（例如 PTC 中途子调用副本）不处理。

## 摘要

**摘要默认开启（票 42）**，默认只摘要主模型主动请求摘要的那些结果（`ruleSummary` 关着）。依据是 exp10 的逐题配对实测
（8 题 × 3 轮 × 开/不开两臂，各 24 run）：主模型输入 token −24%（均值差 −284,207，t = −1.99）、交付给模型的 tool 结果字符
−20%（t = −2.89）、步数 −13%、整读 −18%，而插件自己那 5 次/run 摘要请求的输入约为主模型输入的 1.6%。默认开启的代价只在
「没配摘要 route」的部署上：工具 schema 多一个必填的 `extract`、候选结果各记一行 `failed`，正文仍原样透传——发不发请求由
route 是否配出来决定，插件不替用户把正文发出去。证据与装置见 `.scratch/dsh-result-clipper/exp10/RESULT.md` 与设计稿 §41
（收益结论的读法——配对显著性偏边缘——也记在那里）。

摘要发生在工具结果进入主模型上下文之前。插件用程序结构化生成局部任务上下文（当前用户目标、当前步骤的助手意图、工具身份与参数、有上限的相关摘要），不复制整个主会话。

- **目标工具**：首版硬编码 `bash`、`web_fetch`、`read`（三者覆盖约 95% 的工具结果）。前提是目标工具**不得定义 `finalizeContent`**——已核实这三者都没有，全仓真正挂上该字段的只有 `terminal_*`、`job_*`（`tool-cordis` 的 API 目录里只出现该字段的类型声明文本，不是工具定义），因此这两类永久排除。
- **候选范围**：正文为文本、且估算长度 ≥ `minInlineTokens` 的结果。`bash`、`web_fetch` 另需 < `maxSummarizeTokens`（超过的交给 spill 接管）；**`read` 不设插件上界**——`read` 工具自身按 `readMaxBytes`（默认 50 KiB ≈ 12,800 估算单位）封顶，而 spill 硬编码豁免 `read`，所以只有被 spill 接管的工具才需要上界。含图片等非文本块的结果透传，不参与摘要与替换。
- **阈值单位**：DSH 估算器单位（4 字符/token）。沿用它是为了与 spill 的 `maxInlineTokens` 及既有阈值统计同单位；该启发式对中文低估约 2.5–3 倍，所以 1024 单位对纯中文正文大约相当于 2,500–3,000 个真实 token。`minInlineTokens` 默认 `1024`、可配，`0` 表示不设下限；`maxSummarizeTokens` 默认 `12500`、可配，只作用于 `bash`、`web_fetch`。上界是本插件自己的字段，**不读取 spill 的配置**；改它等于改谁来处理超大结果，部署把 spill 阈值改小时两者的交互必须在 README 写明。
- **摘要不缩短就透传**：摘要加入口说明不短于原文时，原文透传，且**不写 spill**（不产生无用的原文副本）。贴近 `minInlineTokens` 的结果常常落在这个区间：摘要输出预算的下限 1,024 token 与候选下限 1,024 估算单位相当，所以刚过线的那批结果很容易落进 `not-shorter`（白花一次调用、结果照旧透传）。
- **摘要模型可以要求保留全文**：摘要与隐私两类请求都返回动作字段 `action: 'summarize' | 'keep'`。`keep` 表示这条结果本身就是要用原文的对象（典型是要逐行检查、照抄或对照的清单与文件内容——细节是用户点名的还是主模型自己接下来要用的都算）。**判据写在正文与调用形态上**：没有声明提取目标时，摘要请求里只有「本次调用」（工具名 + 关键参数）、估算大小、规则正文与工具正文，**没有用户原话**，所以旧版那条"用户明确要求逐字/逐行/完整查看"是观察不到的条件（实测 0/31 命中，见 `dsh-reasoning-effort-research.md`）；而"整文件读""同路径曾被摘过"这些形态现在由那份调用形态提供。程序保留原 `content`、不替换、**不写 spill**，与「不缩短即透传」共用同一条路径。判断「这次是否需要全文」由**摘要模型**承担——它是唯一同时看到正文与当前任务的组件；准入判断器看不到正文，只判断值不值得花一次调用，不承担这件事（两处术语分工见 `CONTEXT.md`）。
- **`extract` 路径没有 `keep` 这个出口**（票 26）：主模型声明了提取目标时，摘要与隐私两类请求的输出契约里都只提供 `summarize`，规则正文也不再提保留全文。那条路径上"透传"只剩一种合法来源——结果长度低于 `minInlineTokens`，由程序直接透传、**一个模型请求都不发**（隐私闸门开着时只发那一次隐私判断，它是闸门不是摘要能力）；低于下限之外的结果都要交回短说明。原文有 spill 留档与入口可读回，不给这个出口不会丢东西。
- **逐字目标按原文透传（票 39）**：`extract` 的值明确要求逐字正文时（`verbatim`、`character-for-character`、`exactly as written`、`exact text|lines|wording`、`逐字`、`一字不差`、`原样`；**裸 `exact` 不算**——"exact conditions and codes" 要的是精确的概念），结果按原文透传、记 `exact-text`，并交回一条提醒（摘要只会改写正文；要逐字请改用 `offset/limit` 读那个区间）。放在候选判定之后，所以低于下限的结果仍记 `not-candidate`。它挡的是实测里那类"声明了逐字、结果被改写、模型随即又整读一次同一文件"的往返。
- **解析失败抢救（票 40）**：严格解析不成立时只抢救一种形状——输出以 `{"action":"summarize","summary":"` 开头且引号已闭合（正文写完、外壳没写完）。抢救出的正文照常走长度比较，退化成极短正文的那一侧由 `not-shorter` 兜住。引号没闭合说明正文确实被截过，不抢救。实测（exp9）那批解析失败里：两条是逐行清单撞满预算被截断（由 `truncated` 接住，同类目标现在也先被逐字那条路放行），一条是内容完整只少一个 `}`（抢救），只有一条真正无法归因。
- **读说明回到"先写目标"（0.1.6，票 48）**：`extract` 必填 + 哨兵落地时，三条工具说明只保留了"必填"与"要整份怎么写"，删掉了"通常该写目标"的劝说与形状例子，并且把"要逐字"也指向了哨兵。实测后果：同一口径下 `read` 候选的**哨兵率 82.5%**，而带劝说与例子的版本是 **27.9%**——必填字段带来的表态率提升（91.9% → 100%）掩盖了"表态内容几乎全是哨兵"这件事。0.1.6 只改文本、机制一行未动：把"你要什么"放回默认位置、给回形状例子（一行结论 / 一个值 / 是非 / 带行号的那几行）、点明整读是**例外且最贵**（正文会在后续每一步重发）；删掉"要逐字 → 写 `WHOLE_RESULT`"（逐字有 `exact-text` 旁路，两处说法原本互相打架）；`bash`/`web_fetch` 的同名说明同形补齐劝说。`exact-text` 的会话提醒里那句"不要声明提取目标"同步改成"把 `extract` 写成逐字要求"——在必填字段上那句是自相矛盾的。
- **`web_fetch` 说明改用 `read` 句式（0.1.7）**：把"需要结论时写目标；需要整页时写哨兵"的条件并列换成 `read` 那套强默认——`Pass extract with the information you want back, unless you truly need the page's text itself` 在前、`WHOLE_RESULT` 兜底、整页最贵的代价句；网页没有范围读，所以 `read` 的 `offset/limit` 那句没有对应物。**这次是外推不是实测**：27.9%/82.5% 那组数据只覆盖 `read` 候选，而 debug 日志里 `web_fetch` 至今零条记录，改前改后都没有可比口径。要点亮这条判据得先有调用量，口径就是 `whole-result /（声明 extract 且进候选）`。
- **`extract` 必填，`WHOLE_RESULT` 是"要整份结果"的唯一写法（票 40）**：参数说明与三条工具说明都要求每次调用都写这个字段，"要整份"只有一种写法——哨兵 `WHOLE_RESULT`（大小写不敏感），它按原文透传、**不发摘要请求**，且不受规则摘要开关影响（开关管的是"没声明时怎么办"）。必填与哨兵都是**模型可见的提示**：DSH 的 `tools.register` 只校验 `output.schema`，模型参数不由注册表统一校验，所以漏填不会变成工具调用失败。**漏填或空串**照默认处理（由 `ruleSummary` 决定摘要还是透传），同时交回一条提醒（`extract-missing`，同会话同类一条），让模型下次把字段填上；模型下一次把字段填对就把这条名额放回，之后再漏填是新的一次失误、仍会提醒；低于 `minInlineTokens` 的结果不提醒——那不是候选，本来就不该有人填。取值的词表：显式哨兵记 `whole-result`，漏填写进 `rule-summary-off`（规则摘要关）或 `summarized`（开着），两者靠提醒与 `extract` 字段区分。
- **摘要输出预算随输入放大（票 40）**：`maxTokens = clamp(输入估算 / 8, 1,024, 1984)`。下限 1,024（票 42 从 512 抬起：exp10 的包内探针里 10 次「撞满预算」有 6 次卡在这个下限上），原文在 8,192 估算单位以下时预算就是下限；上限由「长度约束」反推。为什么要放大：固定 512 对 4,096 估算单位是八分之一、对 12,800 单位的 `read` 只有二十五分之一，越大的结果越容易撞满预算，而撞满的代价是最大那条结果反过来整条透传。**终止原因是 `max-tokens` 时按原文透传并记 `truncated`**（不再与"请求没做成"共用 `failed`），且**不做抢救**——切了一半的正文当摘要交回会把答案切掉；只有"正文写完、外壳没写完"（引号已闭合）才抢救（见「解析失败抢救」）。隐私请求按投影大小用同一把尺子（它的输出契约里除摘要还有判定字段）；准入请求固定用下限，它的输出只有一两个字段。
- **规则摘要开关 `ruleSummary`（**默认关闭**，票 26）**：关着（默认）时只有声明了 `extract` 的调用会被摘要，没声明目标的候选结果一律透传并记 `rule-summary-off`。它是为"量出「`extract` 为空时按摘要提示词摘要」本身有没有必要"而加的对照开关。它只管摘要提示词这条路——隐私闸门不读摘要提示词、因而不受它影响（见「隐私闸门」的独立性裁决）。判定顺序上它排在候选判定**之后**：不是候选的结果仍记 `not-candidate`，`rule-summary-off` 才恰好是"本该摘要却没摘"的那批。票 40 起 `extract` 是必填参数，所以这个取值同时就是"模型漏填"的计数（并伴随一条 `extract-missing` 会话提醒）。
- **透传不是复述**：`keep` 只发一个信号，**不让模型把正文重新输出**。原文已在程序手里，复述只会重复付输出费、可能撞满输出预算被截断，并把逐字内容变成模型生成的近似物；隐私模式下更是让模型把整段正文再吐一遍。
- **去向必须可区分**：`unmodified` 的透传路径上，每条结果在 debug 记录里都有一条闭合的「动作 + 原因」取值（取值域见「干跑与诊断」）。判断结果（保留原文、未进入候选、摘要关闭等）与故障（调用失败、窗口不足）不得合并成一个布尔值，否则故障会被读成策略；`rejected` 只记动作、不附原因（`block` 下拦截本身在对话里可见）。
- **工作区指令与技能正文不经 `read`**：前者由 harness 在 `agent/pre-step` 直接注入成 user 消息，后者是 `skill` 工具自身的结果。前者完全不流经 `tools/post-execute`；后者是普通工具结果，**会**流经 `tools/post-execute`、因而仍落在隐私闸门的判断面上——「不经 `read`」只排除摘要候选，不排除隐私判断。因此不需要为「必须完整」的文件建立白名单或标记。模型主动 `read` 的文件才是同时暴露给摘要与隐私的面，靠 `keep` 动作与入口说明兜住。
- **重复读取判重**：隐私关闭时，同一会话内按**（工具名, 正文 hash）**判重——同一工具产出过同一份正文时，重复读取直接返回同一条摘要、不再调用模型（memo 在准入判断之前查找，命中即整条摘要路径短路；**只在隐私关闭时参与判重——隐私开启时不查找、不写入 memo**，两节对齐后的裁决与理由见「隐私闸门」的裁决 B）。key 不能用 `(path, offset, limit)`：`read → edit → read` 是高频序列，按参数命中会把修改前的摘要返给修改后的内容；加上工具名是避免把另一工具语境下的摘要复用到同名内容上。hash 变化即重新摘要。memo 会话内 LRU 200 条、会话结束清空；复用的摘要反映生成时的任务上下文，之后目标变化不会反映在旧摘要里（首版接受，代价记此）。**`keep`的结果不进 memo**：它没有摘要可复用，重复读取照常重新判断。
- **摘要准入判断**（独立开关，默认关闭）：摘要能力开启、摘要 memo 未命中、命中候选范围且隐私模式关闭时，先用不含工具正文的固定前缀请求一次只返回严格 `yes`/`no` 的判断。`yes` 才发起带正文的摘要请求；`no` 透传；其他输出、超时或失败按失败处理，直接发起带正文的摘要请求。隐私模式开启时跳过准入，直接走一次同时返回隐私结论与摘要字段的请求。
- **准入提示带上这次调用的形态与结果大小**：投给准入判断的固定前缀是两行——「本次调用：<工具名>：<关键参数>」（`read` 报整文件/分片与路径、shell 报 description 与命令头、`web_fetch` 报 url；字段口径与实测信号见 `dsh-reasoning-effort-research.md`）与这次结果的估算大小。两行都是元数据而非正文（命令头截到 120 字符），不违反「准入不读取工具正文」；**两行同时出现在摘要请求的固定前缀里**，以保持两次请求前缀逐字相同（汇总请求没有准入阶段，不加）。判断器仍然不知道剩余请求数，所以它判断的是相关性与体积，不是净收益——不要把它当成盈亏平衡计算。
- **准入与摘要的固定前缀缓存**只是性能观测，不是正确性前提；两次请求在语义上必须各自独立成立。
- **请求形态**：固定安全外壳 + 代码固定的结构化输出 schema；工具内容始终作为不可信数据分隔输入；页面只编辑规则正文与 few-shot 示例，安全外壳与 schema 改不掉。
- **规则正文的默认值与页面显示**：三份内置规则正文放在一个不 import 任何东西的 `src/rules.ts`，host 半拼装请求与浏览器半的文本域共用同一份文字（host 的 `summary.ts` / `admission.ts` / `privacy.ts` 都依赖 `@deepseek-ai/dsh-llm`，不能被打进客户端产物，抄一份到 `src/client/` 就会有漂移的第二份）。配置里的空串仍表示「没有覆盖」；文本域显示的是**当前生效正文**（有覆盖用覆盖，否则是内置默认）。文本域的编辑是**草稿**：点该行的「保存」才写回，失焦不写——所以改到一半离开设置再回来看到的是已保存的正文，没有半截改动；草稿与生效正文一致时「保存」禁用，草稿正好等于内置正文时保存走「清掉覆盖」而不是写一条逐字相同的冗余覆盖。「恢复默认」清掉覆盖、控件回落到内置默认。安全外壳与输出 schema 不进 `rules.ts`，页面改不到。
- **摘要请求的输入**：正文连同有上限、明确标注的 `additionalContexts` 一起送入（上限见“固定常量”），但只返回正文摘要；附加消息本身不被摘要，仍按 DSH 原有顺序进入后续请求。
- **失败语义**：模型不可用、超时、空结果、非法结果一律**原文透传**。任何路径都**绝不能抛**——`tools/post-execute` 抛错会把整个工具调用变成错误结果。
- **并发**：每条工具结果独立处理，不共享状态、不做全局串行；DSH 自己的工具调用并发池已经限制总数。

## 原结果入口与保留

- 被摘要的结果在替换前调用 `ctx.get('spillStore').saveText(...)`（`owner.sessionId`、`source{tool, toolName, callId}`、`suggestedName`、完整正文），把返回的 `locator` 与 `retrievalHint` 拼成入口说明**接在摘要正文之后**（**裁决 C，2026-10-05**：原先在最前）。顺序由上界与效果两头定：本替换结果只有几百字符，远低于旧结果裁剪器（`dsh-compaction-tool-result-pruner`，阈值默认 8192 字符）的触发线，而裁剪器同时保头 4096 与尾 1024，所以放末尾同样不会被裁；反过来，把路径放在开门第一句时，真实部署里 246 条带入口的结果有 47% 又被读回一次、其中 43% 是整文件一把读回——先让模型读到摘要、并自己声明「这是摘要、够用就别读、需要逐字核对时原文在此」更省往返。长度比较仍按裁决 A 在 `saveText` 之前做。
- **取样顺序（裁决 A，2026-10-02）**：长度比较发生在 `saveText` **之前**。程序先按「摘要正文 + 入口说明预留」与原文比较：不短就直接透传、不调用 `saveText`；只有严格更短才写盘并拼入口说明。入口说明的实际值由 `saveText` 的返回值给出（`locator` + `retrievalHint`），写盘前取不到，所以比较用它的**上界**——私有常量 `entryReserve`（默认 256 字符，按固定提示句加后端 locator 的保守宽度取值，不可配）。上界性质使「有写盘 ⟹ 实际总长严格短于原文」成立：`not-shorter` 只可能落在未写盘的一侧，因此「摘要含入口说明不短于原文时透传」与「`not-shorter` 路径不留下无人引用的存储副本」同时成立，也不存在先写后弃。代价是真实入口说明短于预留时，一小段本可替换的结果（至多预留与真实入口说明之差）被判为不缩短而透传，方向保守。顺序取反（先 `saveText`、再比较）在 `not-shorter` 一侧必然留下无引用的副本，故不采纳；写盘前取不到实际入口说明长度是这个上界存在的唯一理由，不是近似写法。**用例（本票固定，票 04 落地）**：摘要正文 + `entryReserve` ≥ 原文时，断言假存储的 `saveText` 零调用且 `content` 逐字不变；只有严格更短时才断言写盘一次、入口说明接在摘要正文之后。**假设（按 `AGENTS.md` 记录）**：`entryReserve` 是本部署入口说明的上界——默认本机后端是绝对路径加固定提示句，远低于该值；更长的远程 locator 不在首版验证面内。**假设失效时的行为**：若某后端突破该上界，实际总长可能不短于原文而结果仍被替换，这是该部署上的已知退化（首版只保证本机后端）；不加写后检测与回退路径，因为「写完发现不短再透传」正是不允许的先写后弃。
- **长度约束**：摘要加入口说明的总长度必须留在该裁剪器的阈值（默认 8192 字符）以内。票 40 放宽输出上限时按这条反推：`(8192 - 入口预留 256) / 4 字符每 token = 1,984`，代码里就是 `SUMMARY_CEILING_TOKENS`（由 `PRUNER_THRESHOLD_CHARS` 与 `ENTRY_RESERVE` 算出），测试断言 `上限 × 4 + 预留 ≤ 8192`。改动这条上限或那个阈值时必须重新检查这条约束。
- **保留与清理全部由 DSH 的 spill 后端负责**（本机后端：`cleanupPeriodDays` 默认 30 天、进程启动时扫一次，`0` 关闭）。插件不设条数上限、不自行清理、不解析 locator。
- **后端缺失或写入失败** → 该结果**透传不摘要**，以保住「没有入口就不摘要」的不变量。
- **入口确实可读**（已核实）：本机后端的 `locator` 是绝对路径，`retrievalHint` 是固定文案「Use read with offset/limit, or grep this path to search within it.」；fs 沙箱只限制写入（`writeText`/`editText`），读取不经沙箱，因此 read-only、workspace-write、danger-full-access 三种模式下模型都能读回原文。默认落盘位置是 OS 临时目录下的私有进程目录（`mkdtempSync(tmpdir(), 'dsh-spill-')`），沙箱部署无需搬家。
- `read` 读取摘要保存的入口时只跳过整个摘要路径（含准入判断，因而不发准入请求），仍经过隐私判断。**识别方式**：插件在会话内记住自己写出的每个 `locator`，一条 `read` 的 `file_path` 命中该集合即视为读回——只做字符串比对，不解析 `locator` 的结构或语义（「不解析 locator」与「记住自己写出的值」不冲突）；集合随会话失效，重启或 fork 后同一入口会被当作普通 `read`（会再摘要一次）。本条不能用摘要 memo 代替：读回后的正文是 `read` 的渲染结果，与被摘要前的正文 hash 不同。重读不得跳过 `fs/observed` 的真实 version 发射；验收覆盖「同一 turn 先 read 后 edit」与「read 被摘要后再 edit」两种顺序，都不得出现 `FS_NOT_OBSERVED`。

## 隐私闸门

- **判断面**：`await next()` 返回的决策内容与附加上下文，也就是**模型即将看到的内容**（spill 处理后的正文），含 PTC 子调用递延到外层结果的图片与附加上下文。原始结果先截断再判断会漏掉模型真正看到的部分，所以判断对象是下游处理后的投影，不是原文。
- **只判文本**：分类器只接收投影中的文本，不接收图片块；含图片的结果按其文本判定，图片内容不参与隐私判断，README 明确写出这一点。运行在本插件**外层**的其他监听器可能在我们的决策之后追加附加上下文，那部分不被判断。
- **不设附加消息上限**：隐私模式请求把完整投影交给本地 route；长度上限只约束摘要模式。
- **合并请求**：隐私模式固定返回 `privacyVerdict: safe | sensitive | uncertain`、`action: 'summarize' | 'keep'` 与 `summary: string | null` 三个字段。`action` 与 verdict 正交：`safe` + `summarize` 替换正文，`safe` + `keep` 保留原文；判定为 `sensitive` 或 `uncertain` 时 `action` 无意义，提示词要求 `summary` 为空，程序始终忽略该字段。**`uncertain` 因此连带取消摘要**：该结果既不摘要也不拦截，按失败策略放行原文。这是有意选择——不在未判断成功的前提下继续加工内容；代价是本地模型常拿不准时摘要收益下降。已否决「不确定时再单独发一次摘要请求」，它会在这种情况下稳定翻倍调用。
- **隐私这条路的独立性（裁决，2026-10-05）**：隐私请求**不读摘要提示词**，判定与摘要是同一次请求的两个字段，所以**摘要总开关与规则摘要开关都不作用于它**——隐私开着时判 `safe` + `summarize` 照旧替换正文，`summarize: false` 也一样（否则这一次请求的输出白付、判 `safe` 的正文也白白留着）。两个摘要开关只管摘要提示词那条路：总开关关掉时那条路不发请求也不替换（记 `summary-off`），规则摘要关掉时没声明 `extract` 的候选结果透传（记 `rule-summary-off`）。修正前的实现让隐私路径也要求总开关，与本节冲突，票 26 已改。
- **失败策略**（全局配置）：`sensitive` 始终拒绝；`uncertain` 与技术失败按 `passthrough`（**默认**）或 `block` 处理。默认选择 fail-open，因此**失效必须可见**（见下）。
- **窗口不足单列**：本地 route 的服务窗口可能小于投给它的投影长度（中文下 spill 的 12500 估算单位约合 3 万真实 token）。**不做超窗预检、不预先跳过请求**；底层报告上下文溢出时按「窗口不足」单独归类，在会话提醒与 debug 日志里与普通判断失败区分开，README 给出本地窗口的建议下限（32k 起步，中文场景 48k 更稳）。
- **拒绝形状**：使用原生 `{kind:'block', feedback:[固定文案]}`。结果按失败标记，反馈为固定、不可编辑的文案，工具附带的上下文一并丢弃；失败策略 `block` 与 `sensitive` 使用同一形状。模型只看到这段文本：DSH 不追加任何系统提示，`error.info` 也不持久化，所以下一步指引必须写在文本里。
- **拒绝文案三段**：① 陈述该结果经本地隐私判断被拦下、原文未提供，并带上工具名；② 明确不要重试，也不要换工具或改参数再取同一内容；③ 给出允许的下一步——确需该内容时用 `ask_user_question` 请用户决定，或在回复中说明。文案不写参数与正文，也不依赖 `error.info`。措辞照 DSH 既有模式（工具描述里的策略拒绝、会话修复消息都是「陈述事实 + 禁止盲重试 + 给出允许的下一步」）。
- **本地 route**：复用 DSH provider route；摘要、摘要准入判断与隐私闸门三个角色各有自己的 route，后两者未配置时跟随摘要 route。隐私模式要求用户在页面**明确确认隐私 route** 是本地的；插件只提交 `provider` 与 `model`，读不到端点的 `baseURL`，因此既无法自动证明，也不通过 `baseURL` 猜测。未确认视为配置失败，按失败策略处理并显示警告。该确认是对**具体 route** 的声明：隐私组的 provider 或 model 一改，确认随即作废（见「配置面与设置座位」一节），不会跟着新 route 继续放行。
- **失效可见性**：设置页插件卡片常驻警告只覆盖**静态配置状态**——隐私 route 未被用户确认为本地；该状态可从设置读取，不依赖运行期推送。运行期的失效放行**不**进卡片警告（设计文档不要求新增 host→client 瞬时状态通道）：按 `passthrough` 放行时，同一会话内**每类原因各交回一条**插件提醒（至多三条：未能判断 / 判断失败 / 窗口不足），同一类原因只提醒一次，文案按原因区分、不含任何正文。提醒以**附加上下文**交回：插件只在这次工具结果的决策上挂 `additionalContexts`，由 Agent 循环在该结果提交后、下一步边界追加成 user 消息（`CONTEXT.md` 的「附加上下文」）。插件自己 `append` 会话事件时，提醒落在 waterfall 中间——它会排在被它指的那次工具结果**之前**，而且不属于该步的输入（循环的 `inbox` 只认 `agent/inbox/spliced`，`additionalContexts` 才走 `next-step` 收件箱）。合成用户消息与真实用户消息在请求里形状相同，模型侧看不到 `source`，所以提醒正文带 `[dsh-result-clipper]` 前缀，让模型能分辨它不是用户发言；该消息本身不得伪装成真实用户消息——多个 DSH 消费方按 `source.kind === 'user'` 判定真实用户介入。（交付方式与台账由票 13 修订。）
- **误拦的恢复**：拦截在对话里天然可见（一次失败的工具调用加拒绝文案）。用户在设置页关掉隐私开关即恢复；开关与参数用 volatile 声明，**保存后立即生效，不需要重启**。首版不做拦截记录面，也不做「本会话临时放行」按钮。
- **代价**：隐私判断不设长度门槛，所以**每个标准工具结果**都会加一次本地模型往返（不只目标工具；`grep`、`edit`、`ask_user_question` 的结果同样会过闸），`web_fetch` 默认除外（`webFetchPrivacyGate`，2026-10-05）。超时固定 45s（票 42 从 20s 抬起：exp10 探针采到的两次中止精确落在 20,015/20,047ms 上，当时只写出 193 字符——时间耗在首 token 之前）；默认 fail-open 时超时等于静默放行，只由会话提醒与 debug 记录可见——同一类原因在该会话只提醒一次，之后的同类失效不再重复提醒。这代价是「不漏大结果」这一取舍的直接结果：缩短超时只会漏得更多，所以超时不开放配置，慢的部署应当换更快的本地模型。
- **memo 与隐私判断的先后（裁决 B，2026-10-02）**：「摘要」的重复读取判重条与上一条代价条对齐后的裁定是——**隐私开启时 memo 不参与判重**：程序在隐私模式下不查找、不写入 memo，每个标准工具结果都照常走一次隐私判断（请求形状见「合并请求」条），代价条因此逐条成立；隐私关闭时的 memo 语义不变（在准入判断之前查找、命中即整条摘要路径短路）。对齐依据：合并请求一次产出 `privacyVerdict` 与 `summary`，memo 命中若短路该请求就必然连带跳过本次隐私判断，与「每个标准工具结果各得一次隐私判断」冲突；若命中仍照发该请求，memo 便不省下任何一次调用。唯一能让两者并存的写法是命中时改发一次只要判断、复用 memo 摘要的请求——它只为省下摘要输出那段 token，却要新增第二种请求形状、并改「固定输出」的契约，按 `AGENTS.md` 的复杂度控制原则不采纳。**用例（本票固定，票 05 / 07 落地）**：隐私开启、同一工具同一正文连续出现两次时，断言两次各发一次隐私判断请求（假 route 计数为 2），第二次仍可被拦；隐私关闭时同一对结果只发一次摘要请求、第二次命中 memo。**适用范围**：票 05 的 memo 只在隐私关闭时生效，票 07 的隐私判断逐条进行。

## 监听器位置、PTC 与观察面

- **监听器位置**：注册为 `prepend`，并且**必须装载在 spill-policy 之后**。两个 `prepend` 监听器之间后注册的先跑，因此本插件这时位于 spill 外层：先 `await next()` 让 spill 完成截断，再对模型将看到的内容做判断。若装载顺序相反，行为退化为对原文判断——拦截偏保守、请求可能超出本地窗口，**退化方向是安全而非损坏**，但这是已知的装载顺序影响。
- **双视图**：监听器的第二个参数 `result` 是未经 post-execute 链处理的原始投影，用于**摘要资格判断**（原文长度必须 ≥ `minInlineTokens`，`bash`/`web_fetch` 还要 < `maxSummarizeTokens`）；`await next()` 的决策用于**隐私判断**。不这样分，一条超大结果在后 spill 视图里只剩头尾，会被误判为摘要候选，于是去摘要 spill 的预览、再把预览存一份，形成双重落盘。
- `exec.parent !== undefined` 是当前唯一可用的「非模型直连派发」判据：全仓唯一的产品级生产者是 PTC，仓库自身多处用同一谓词表达同一含义，也没有更精确的「不进模型」标志。残余风险是演化性的——若将来有别的复合工具转发该标记，那些结果会被静默跳过。
- **必须跳过 PTC 子派发**：子派发与普通派发走同一条 `tools/post-execute`，用 `exec.parent !== undefined` 识别后直接 `next()`（spill 使用同一判据）。理由是子派发的结果只是程序内部的中途值：对它返回 `block` 会让沙箱程序抛错，带 `value` 的决策会替换程序收到的值，替换 `content` 则会改写持久日志副本。插件只处理外层最终结果。
- **隐私判断覆盖 PTC 的外层 `run_code` 结果**：它是普通派发，走 `tools/post-execute`，是模型唯一能看到的 PTC 内容；子调用延迟给外层的图片与附加上下文也并入该结果的投影。只有 prepare、pre-execute 或守卫失败才走 `final-result` 旁路。
- 首版**不注册** `tools/ptc-dispatch-log`：那条接缝只改持久日志副本，不影响程序与模型，属于“不介入中途过程”。因此 PTC 中途子调用的正文仍会作为 `tool/ptc-dispatch` 事件进入会话日志并可能被上传——这是写进 README 的保护面缺口，不当作遗漏。
- 我们返回的决策是最终决策，spill 已在 `next()` 内跑完。因此判为敏感时，**spill 可能已经把全文写入本地存储**——`SpillStore` 只有 `saveText`、没有删除接口，插件撤不回。这些文件私有、按会话分组、只受后端保留期约束；模型看不到内容，也拿不到 locator。`read` 被 spill 硬编码豁免，因此不涉及。
- `finalizeContent` 在 `tools/post-execute` 之后执行，且是模型可见的最后一跳；只有 `terminal_*`、`job_*` 定义它，这正是目标工具必须逐个确认的原因。
- **诚实边界**：可观察范围是普通派发（含外层 `run_code`）的 `tools/post-execute` 结果；`final-result` 旁路（prepare、pre-execute、守卫失败）与 PTC 中途日志副本不保证；普通 `tool/result` 的 session-log 继承已经替换过的投影。这是尽力而为的保护目标，不是安全承诺。
- `final-result` 旁路产生的错误结果**会进入模型但本插件收不到**，其中常回显工具参数。本设计接受该缺口；若上游将来提供覆盖这些结果的接缝，插件可零结构改动接入——记为上游备忘，不阻塞首版，也不作为本插件的依赖。
- 元数据 `meta` 会进入持久化、界面或会话日志，不属于模型可见内容，插件不改动它。文档**不得宣称降低上下文占用**——`contextBreakdown` 没有工具结果这一维。

## 与默认组合的共存

默认 bundle 已启用 `ptc-runtime`、`workflow-ptc`、`spill-local`、`spill-policy`（`maxInlineTokens: 12500`）和 `dsh-compaction-tool-result-pruner`（`packages/bundle/base/cordis.patch.yml:390-421`）。

- 与 `dsh-reasoning-pruner` **正交**：它只读助手消息的重放信封与当前表面位置，不依赖任何工具结果内容，也不注册 `tools/post-execute` 或 `tool/result`；本插件只改工具结果 `content`，不会使它的裁剪目标失效。
- 与 `dsh-compaction-tool-result-pruner` 的交互只有一处：它只处理超过 `thresholdChars`（默认 8192）字符的当前工具结果，因此摘要通常不被改写；入口说明接在摘要正文之后、并守住长度约束（见「原结果入口与保留」）。
- 与 `spill-policy` 的相对位置是行为的一部分：本插件在它外层运行（两者都 `prepend`，本插件后注册），所以隐私判断看到的是 spill 截断后的正文。装载顺序相反时退化为判断原文，方向保守。
- 不检测、不读取其他插件的配置：共存约束以上述静态规则表达，不引入对别的插件配置的依赖。

## 配置面与设置座位

- **设置只有一个座位，入口另有一个**（2026-10-05 定）：「设置 → 内置插件」里保留一个页签，但它**只指路**——一句「设置在哪、那里能设什么」，没有任何控件、也不注入业务面；真正的设置全在装它的那个包自己的详情页配置区。页面上**不写这个界面为什么这样安排**（第一版那句话的尾巴是「这一页不放开关——它们离开自己那条 route 或日志路径按不动」，那是写给开发者看的，按 `AGENTS.md`「插件页面文案」删掉；理由就是下面这段）。依据：插件自己的开关就是「设置某项能力」本身——摘要与隐私的开关离开它们要用的 route 按不动，debug 与干跑离开日志路径什么也不写，开关与它们要用的设置在同一页上才读得懂、才用得起来（第一版把那四个开关放在这个页签里，用户看到的是一排按了没反应的开关）。页签留着的理由是**发现路径**：用户会先去「设置 → 内置插件」找插件设置，那里什么都没有会让人以为插件没装上。
- 座位：插件自身的 profile 条目即 settings 命名空间（`SettingsNamespace`，Host 侧由 `ctx.settings.describe()` 投影出表单）+ 浏览器半注册**一个** `plugins.bundle.config` 配置区（keyed 槽位，键是包名 `@dsh-clipclop/dsh-result-clipper`；`view: 'page'`，经 `ctx.configForms.get(ns)` 取得该命名空间）+ **一个只指路的 `settings.plugins.tab` 页签**（`id: 'result-clipper'`、`order: 30`，`label` 是 locale thunk；不带 `inject`，所以它读不到也写不了任何 settings 字段；它与配置区一样包在 `whileServed([ns])` 里——宿主没 serve 这个命名空间时页签也不出现，否则那句话会指向一个不存在的页面）。本插件按 profile bundle 装载（`dsh.bundle.patch` + `dsh.profile.bundles`），插件管理器给它的卡片是包卡片，而包详情页只渲染按包名索引的 `plugins.bundle.config`；注册到 `plugins.item` 会落在分组里的另一张「官方插件」卡片上，包卡片详情页仍是空的（`@deepseek-ai/dsh-client-ui-settings-web-search` 那条先例是内置插件、不按 profile bundle 装载，所以它的 `plugins.item` 座位不适用于本插件）。恢复默认按字段分两种语义：推理档位、摘要下限、摘要上限与三份提示词规则正文回到 schema 的内置默认（提示词以 `op: 'unset'` 清掉覆盖），其余字段回到上一次保存的值。需要「保存即生效」的字段在 schema 上声明 `volatile`。不需要 YAML 兼容路径。
- **固定常量**（页面只读展示，不开放配置）：摘要模型请求的超时 45s；相关摘要 ≤3 条、每条 ≤600 字符；`additionalContexts` ≤2,000 估算器单位；摘要输出预算 1,024–1,984 token（按输入估算大小取值，见「摘要」；下限给准入请求，上限由长度约束反推）；重复读取 memo 上限 200 条。固定前缀的字段与长度上限由程序控制，页面不开放任意扩大上下文。
- **可配**：两项能力开关（摘要、隐私闸门；**各在它自己那一组之上，未启用时整组收起**）；摘要准入判断开关（默认关闭；**在准入组之上勾选，未启用时整组收起**）；摘要 route 选择（`routeProvider` / `routeModel`）与准入、隐私两个角色的 route 选择（留空跟随摘要 route；**换 provider 时不属于新 provider 的 model 会被清空**）；「隐私 route 已确认为本地」确认位（仅隐私模式要求）；`minInlineTokens`（1024，按 token 估算）；`maxSummarizeTokens`（12500，只作用于 `bash`/`web_fetch`，按 token 估算）；失败策略（`passthrough` | `block`）；三类请求各自的推理档位（留空＝不推理，候选与可用性都来自该 route 声明的档位表，见「推理档位的取值与降级」）；摘要/隐私/准入提示词的规则正文；诊断组里的 debug 开关与路径、干跑（默认都关闭）。端点的 `baseURL`、协议与凭据不在插件配置里：它们由 LLM 适配器按 route 持有，「设置 → 模型」是配置入口；本插件只提交 `provider` 与 `model`。
- **provider 与 model 的候选来自 DSH 自己的模型目录**：卡片用 `remote.session.modelCatalog()`（「设置 → 模型」那一页的同一来源）填两个 `<select>`——provider 候选是目录里的 route，model 候选是该 route 的模型（换 provider 就换一批）。卡片每次挂载重读一次目录（用户通常是先去模型页建 route、再回来选它），装载时也读一次。**这层「读不到就用不上候选」只覆盖读失败**：`remote` 与 `remote.session` 是按 DSH 惯例硬声明的依赖（读某个 namespace 的业务包要自己同时声明 `remote` 与 `remote.<namespace>`，`docs/api-gateway.zh.md:60`；第一方先例 `ui-model-selection/src/client/index.ts:107` 同款），服务缺席时整个客户端半不装载（配置区不出现），走不到这里的退化路径。插件不为这次读新增客户端依赖：只用到一个方法、一个返回形状，就地声明最小结构（与 `ResultClipperSettingOp` 同一取舍）。
- **候选之外的值不丢，也不把部署锁死**：候选是 `<select>` 而不是 `datalist`——`datalist` 只按输入内容过滤，选好之后展开只剩当前那一项（票 12 跟进 #6 的实测反馈）；而纯 `<select>` 会把「目录暂不可用 / 目录查失败 / 私有 model id」这三种情况变成不可配置，所以每一行另有「自定义…」入口切到文本输入，再从「从目录里选」切回来。目录读不到（候选为空）时控件直接是文本输入，与加入候选前逐字相同；当前值不在目录里时它作为一条带「（不在目录里）」后缀的选项保留，不会因为渲染而被清掉。**目录外的值也能清掉**：置空项与「不在目录里」那条选项并存，前者永远在第一位。
- **一行放得下，控件照搬「设置 → 模型 → 提供商」那一页**：每个角色分组的 route 行是三格——provider、model 与推理档位并排；摘要的两个阈值是独立的两格一行。输入类控件（单行输入、下拉、文本域）共用一份 `INPUT_STYLE`，取值逐条抄 `ModelsSection.module.css` 的 `.input`：`height: 32px`、`0.5px solid var(--dsw-alias-border-l4)`、`var(--dsw-radius-md)`、`var(--dsw-alias-bg-layer-1)`、`14px/22px`。下拉另加 `.selectInput` 那三样：`appearance: none`（替掉系统箭头）、`background-image` 用同一枚 12px 雪佛龙数据 URI 内缩到 `right 12px center`、`max-width: 240px`（枚举值都短，整格宽的枚举框读起来像待填文本框）。**这是本卡片唯一一处抄外部样式的决定**，理由是用户直接点名那一页好看，控件长得像同一套卡片才不像半成品。两处已知代价：① 没有 CSS 管线，伪类（`:focus` / `::placeholder`）内联不了，焦点态留给浏览器的默认焦点圈（那一页是用 `border-color` 换来的，本卡片拿不到）；② jsdom 不保留 `background-position: right 12px center`（cssstyle 不支持「关键字 + 长度 + 关键字」），所以「雪佛龙内缩 12px」只能对着那一页的 CSS 逐字核对，测试里断言不到。**按钮不在这两处代价里**：四个按钮（每组的「保存 / 恢复默认」与两处「自定义… / 从目录里选」）用 `ui-primitives` 的 `Button` 原子（两处动作 `outline` + `md`，两处小入口 `outline` + `sm`——`ghost` 没有边框，用户看不出那是一个按钮，2026-10-05 改），`:hover` / `:active` / `:disabled` 由包里那份 CSS module 提供，`.button` 与输入框同一档圆角（`--dsw-radius-md`）——它与 DSH 内置插件页签里的 `Switch` 是同一条路：同一个平台模块表，不是本插件新增的依赖。分组标题下的说明是**用户逐字定死的三段原文**，只讲这个设置带来什么（摘要：节省缓存计费、上下文更干净、可提升模型效果，清空等于请求不发、结果原样透传；准入：省下不值得摘要的结果的 token 费用、强烈建议跟随摘要模型、不启用会直接走摘要模型；隐私：判定敏感在进主模型之前拦下、敏感内容不会发往外部网络、应该设成本地模型）——不再有「好处：/怎么设：」这类层级，「只留」是用户的原话。provider 与 model 的下拉第一项是**置空项**（摘要组「不设置（清空）」、准入与隐私组「跟随摘要模型（清空）」）：选中它、点该组「保存」，字段回空串——准入与隐私回空串即回到跟随摘要模型，摘要回空串即摘要不生效（`src/index.ts:249` 的 `provider === '' || model === ''` 直接 `unchanged('failed')`：请求不发、结果原样透传，这与 `failurePolicy` 无关，那是隐私路径的字段），没有单独的「撤销」通道。
- **换 provider 时 model 跟着走，隐私组的确认位跟着 route 作废**：model 属于某一对 (provider, model)，换 provider 后旧的 model id 通常在新 route 上不存在——那样会留下一个「（不在目录里）」的孤儿取值，host 侧只会当失败路径处理。所以 provider 改动时若当前 model 不在新 provider 的候选里就清空它（provider 被清空时同样清空）；目录读不到（候选为空）时不猜，保留手填值，免得把「手工填 provider + model」的部署变成不可配置。同一条 helper 还负责隐私组的「已确认为本地」：那个确认是对**具体 route** 的声明，而 host 侧只读这个裸布尔（`src/index.ts:313`，不校验它对应哪条 route），所以隐私组 provider 或 model 一变，确认位就在草稿里清掉、必须重新勾选——否则换一条没确认过的 route 会沿用旧确认继续放行，把敏感正文发往外部网络。判据在 `card.tsx` 的 `changeRoute`（三个角色共用一份；`confirm` 只有隐私组传）。写入用的是同一次原子保存：确认位与被改的 route 一起落库，不存在「route 生效了、确认还没失效」的中间态。
- **端点与凭据为什么不进插件配置**（票 12 核实）：`GenerateOptions` 只有 `provider`、`model`、`reasoningEffort` 等字段，**没有 `baseURL` 或 `apiKey`**（`packages/llm/llm/src/types.ts:511-553`），所以插件无法把一个端点塞进某次请求；route 由适配器按自己的 profile 建立，pi-ai 适配器的 profile 才带 `baseURL`、`api` 与 `apiKeyEnv`（`packages/llm/llm-pi-ai/src/config.ts` 的 profile schema；`packages/llm/llm-pi-ai/src/index.ts` 的 `resolveApiKey` 走 credentials seam），而 GUI 的「设置 → 模型」页就是给自定义 route 填 `baseURL` 与 API key 的入口（`packages/client/ui-settings-models/src/client/CustomProviderCard.tsx`）。要三个角色用不同端点，就在那里建三条 route，再在插件里按角色各选一条。
- **三个角色各自成组**：配置区按「摘要模型 / 摘要准入判断模型 / 隐私闸门模型 / 诊断」分组，每个角色的 route（`provider` 与 `model` 并排）、推理档位与提示词规则正文同属该组；摘要的两个阈值也归摘要组，组间用一条横线隔开。分组是座位约定的一部分：看一个角色的设置不需要跨组找控件。
- **工具结果精简的两个开关在配置区最下面、最后一条横线之后**（2026-10-17，票 19）：「工具结果精简」（总开关，默认开）与它下面一级的「按命令语义精简」（默认开）都是**保存即生效**的单字段写入——它们不折叠任何承载「保存」按钮的组，这一层也没有别的参数需要草稿。总开关关掉时子开关收起（它只在这一层已经介入时才有意义），并保留这一层自己的说明。**这一层只有这两个字段上页面**：六个通用参数与三族的开关和参数都是非 volatile，页面不注入它们的读数、也没有任何控件（见下面「落在配置面」）。
- **摘要准入判断的启用位在准入组之上、且保存即生效**（2026-10-05 改）：它是「先有一条 route 才有意义」的开关，但**不能放进它自己折叠的那一组**——取消勾选会把承载「保存」按钮的那一组一起收起，那次改动就永远存不下去。所以它单独一行、在那一组之上，走与摘要、隐私两个能力开关同一条立即写入路径（`saveFields` 的单字段 `mutate`）；同一字段仍只有一条写入路径。未启用时整组（标题、route、档位、提示词、保存 / 恢复默认）都不渲染，勾选后展开。**规则摘要开关（`ruleSummary`）留在摘要组里当第一个勾选**：它折叠的是同一组内的两个控件（规则正文），组本身与它的保存按钮还在，走草稿没有上面那个问题。**debug 与干跑留在诊断组的草稿里**：它们不折叠任何东西，与同组的日志路径一起点「保存」写回；判断干跑生不生效的那句提示读的是**已保存**的取值。
- **缩排表示从属关系，每级 32px（2026-10-05）**：「摘要模型」与「隐私闸门模型」两组各比它们上面那个能力开关退 32px；「启用摘要准入判断」与摘要组同层（退 32px），它下面的准入组再退 32px（合计 64px）。16px 在真机上几乎看不出层级，所以每级加到两格。诊断组没有上级开关，保持顶格。
- **现在用不到的规则正文只读，且是灰字（2026-10-05）**：「自动摘要大内容」不勾时「摘要提示词规则正文」不会被用到，控件 `disabled`、字色换 `--dsw-alias-label-tertiary`、指针换 `not-allowed`，并在框下写一句为什么。**只改字色不改底色**：浅色主题下 `--dsw-alias-bg-layer-2` 与 `--dsw-alias-bg-layer-1` 是同一个值，换底色在浅色下根本看不出来。
- **每组是「草稿 + 保存」**：控件只改本组草稿，点该组的「保存」才把**该组全部改动**作为一次原子写入提交——底层是 `ConfigForm.mutate(ops)`，多个 op 共用一个 revision 栅栏、一次 Host 校验与一次持久化决定，所以不存在「一半字段生效」；被拒时整组不生效、该组显示失败，草稿保留（用户改完可以直接重试）。三个能力开关（摘要、准入启用位、隐私闸门）是单字段的立即写：它们是折叠自己那一组的开关，不是参数。
- **「恢复默认」的两种语义**：推理档位、摘要下限、摘要上限与三份提示词规则正文回到**内置默认**（提示词的默认是内置规则正文，草稿回到它时保存以 `unset` 清掉覆盖，不写一条与内置正文逐字相同的覆盖）；provider、model、隐私确认位、失败策略、debug、干跑与 debug 路径回到**上一次保存的值**（即丢弃未保存的改动）。前者不能「回落到已存值」，否则改坏的阈值与提示词没有一键恢复的路径；后者不能「回落到空」，否则确认位与 route 会被清掉。草稿在 Host 侧取值变化时（保存被接受，或别处写入）整体重新播种。
- **推理档位的取值来自 route，插件不内置候选词表**：档位 id 由每条 route 声明（DSH 的 `LlmModelReasoningInfo { efforts, defaultEffort? }`；适配器只承诺"展示顺序"，不承诺升序）。配置里**留空＝「不推理」**，请求前按该 route 的档位表解析：`off` → `none` → 已知次序（`off`/`none` < `minimal` < `low` < `medium` < `high` < `xhigh` < `max`）里最低的那一档 → 声明的第一个（表里全是未知 id 时才走这一档）。显式值在表里就下发；不在表里时它发出去只会被拒，所以按「不推理」解析（与卡片上显示的生效档位一致，而不是留一个发不出去的值）。档位表按 provider+model 缓存（`src/efforts.ts`）：一条 route 每进程只成功解析一次，之后都是内存查表；解析失败**不缓存失败**（下次再试）；设置写入清空缓存。**表读不到时**显式值原样下发，并保留票 09 的一次性重试（`UNSUPPORTED_REASONING_EFFORT` 在 provider I/O 之前抛出 → 去掉该字段重发，即按该 route 的默认档位发；route 声明了 `defaultEffort` 时就是这个默认档位，这是「去掉字段 ≠ 一定不推理」的固有边界）。卡片的候选来自模型目录里的 `reasoning.efforts`（与「设置 → 模型」同源），标签直接用 route 给的名字，所以用户看不到也不需理解各家词表的差异（cline-pass 是 `none`、deepseek 是 `off`）。根因与实测见 `.scratch/dsh-result-clipper/design-draft-reasoning-effort.md`。
- 页面加一句静态警告：摘要与隐私分别把工具正文发送给各自所选 route。

## 干跑与诊断

- **干跑**：走完整条流水线（准入、隐私、摘要），但绝不替换任何内容、绝不交回提醒、**也不动提醒台账**（放回「漏填」名额同样是会改变随后真实运行行为的写入）、**也不调用 `saveText`**（写盘同样是改变状态，且会在共享存储里留下无人引用的文件）、**也不写 memo**（否则会改变随后真实运行的行为）、**也不查找 memo**（查找会刷新最近使用次序，同样是会改变随后真实运行行为的写入），只在 debug 日志里记录「本应发生什么」（本应替换 / 本应拦截 / 本应跳过及原因）。干跑记录在 debug 的字段形状上多一个 `dryRun: true` 标记，动作与原因就是预报值——同一个日志里真实记录与干跑记录因此可分辨，且真实记录的字段形状不变。干跑记录受 debug 的同一条禁写约束，所以「本应替换」只记动作与原因，不记摘要文本，也不记入口（入口由 `saveText` 产生，干跑不调用它）。它要求 debug 开关已开启且路径已配置：两者缺一时干跑不生效并在页面提示，因为干跑的产出就是这条日志（这条同时也保住了「debug 关闭时零写盘」的不变量——干跑不是它的例外）。
- **debug** 默认关闭。开启后路径必填，插件创建父目录并以追加方式写入 metadata JSONL（**插件版本**、工具名、结果大小、准入结论——隐私模式跳过准入时记为不适用、结果取值、调用耗时、缓存观测、判断器输入 token 数）。**插件版本字段的口径**：每条记录（含 `kind: "mount"` 那条）带一个 `pluginVersion`，取值是本包 `package.json` 的 `version`（每次进程启动现读一次，读不到时记 `unknown`）。**为什么要它**：日志按追加写，同一个文件里混着多个版本的记录，而取值的词表是累加的（`not-candidate` 这类取值哪个版本都会写），事后只能靠提交时间和文案改版去猜观测属于哪个构建——0.1.4 之前真实日志上就发生过这种考古。版本现读而不是抄成源码常量：抄一份会和 `package.json` 漂移，漂移的版本号比没有版本号更糟。**两个观测字段的口径**：`缓存观测` 记这条结果的各次模型请求里命中前缀缓存的输入 token 数之和（没发请求或底层没报告用量时为 `0`）；`判断器输入 token 数` 记准入判断那次请求的输入规模（未缓存、缓存读、缓存写三种输入 token 之和；没发准入请求时为 `null`）。**结果取值是封闭的两段式**：动作取 `summarized` / `rejected` / `unmodified` 之一，`unmodified` 必须附原因（`not-candidate` / `admission-no` / `kept` / `not-shorter` / `read-back` / `uncertain` / `summary-off` / `rule-summary-off` / `failed` / `failed-window` / `exact-text` / `whole-result` / `truncated`）；**输出被预算截断（`truncated`）与请求失败（`failed`）必须是不同取值**：前者说明预算不够、后者说明模型或 route 出了问题，两者都按原文透传。隐私路是例外：那一次请求的输出里除摘要还有判定字段，被截断时判定本身也不可信，所以整条按 `failed` 处理（保持「失效必须可见」那条提醒）。**窗口不足与普通失败必须是不同取值**，判断结果与故障也不得合并；`kept`（摘要模型要求保留全文）与 `read-back`（插件识别出按入口读回而主动跳过摘要）也不得合并。不写原文、摘要正文、完整提示词、凭据；不自动切换到临时路径。

## 当前范围与非目标

- 首版只做固定的目标工具（`bash`、`pwsh`、`web_fetch`、`read`；`pwsh` 是 Windows 上 shell 的注册名，2026-10-05 补入）；不做按工具声明的可重取性（需要 DSH 新接口）。
- 不做「同一会话内记住已判敏感的调用并确定性重拦」。分类器是概率性的，重试可能改变结果，但尚无证据表明模型会靠重试绕过；先用拒绝文案的「不要重试」约束，实测出现重试钓鱼再加。
- 不在**读取层面**做去重（即不因为「这段区间此前读过」就跳过读取或省掉隐私判断）。若以后要做，判据是「本次区间被同一文件版本的已读区间**完全覆盖**」（参数相同只是特例），且那次已读记录必须仍在模型可见历史里且未被改写，并且绝不跳过 `fs/observed` 的真实 version 发射。摘要本身的复用是另一件事，按正文 hash 判重（见「摘要」）。
- 不改造 spill-policy，不修改 DSH 源码或公开契约。
- 不做隐私请求的超窗预检，也不分块判断：超窗按「窗口不足」这一类失效处理并提醒，替代方案（用 route 的 `contextWindow` 预先跳过、或分块判断）留作后续项。
- 不把敏感内容从已落盘的 spill 存储里撤回：后端没有删除接口，本设计接受这一后果并写明。
- 提示词的具体措辞不在验收范围内，只验收「固定外壳与 schema 改不掉、可编辑段只替换规则正文与 few-shot」的拼接方式。
- 不额外做界面徽标：被拦截的可见面就是原生失败反馈，被摘要的可见面就是正文里的入口说明。

## 验收要点

- 目标工具逐个确认不定义 `finalizeContent`，并有守护测试（`pwsh` 的工具包只在 Windows 部署里存在，所以守护测试覆盖本机装得到的那几个）。
- **PTC 子派发被跳过**：用带父派发的夹具断言监听器不改变子派发结果，程序不会因 `block` 抛错。
- **双视图生效**：原文 ≥ `maxSummarizeTokens` 且被 spill 截断的结果不被判为摘要候选，不发生双重落盘；`read` 的大结果（无插件上界）正常进入候选。
- **重复读取判重按（工具名, 正文 hash）**：隐私关闭时同内容复用同一条摘要、不额外调用模型；文件被修改后 hash 变化、重新摘要；隐私开启时不查 memo，每条结果各判一次（裁决 B）。
- **摘要没有缩短**（含入口说明也不短于原文）时原文透传，且不发生 spill 写入。
- **`action: 'keep'` 生效**：模型要求保留全文时正文逐字不变、不写 spill；`keep` 的结果不进 memo，再次读取照常重新判断。
- **必填与哨兵（票 40）**：`extendedDefinition` / `extendInPlace` 两处都把 `extract` 标进必填表且**保留原生已有的必填项**（`['file_path','extract']`）；候选结果带 `WHOLE_RESULT`（大小写不敏感）时一个请求都不发、结果逐字不变、记 `whole-result`、不发提醒，规则摘要开着也一样；漏填或空串时按默认处理（`ruleSummary: false` → `rule-summary-off`）并交回一条含 `WHOLE_RESULT` 的提醒，同会话只发一次（模型填对一次后名额放回），低于下限的结果不提醒。隐私模式下哨兵**照做判定**（闸门先于一切），但提示词里既没有哨兵也没有目标那一段，结果按原文透传。
- **输出预算与截断（票 40）**：预算是输入估算的八分之一、夹在 [1,024, 1,984] 之间（8,192 估算单位以下等于 1,024）；`上限 × 4 + 入口预留 ≤ 8192`；终止原因为 `max-tokens` 时按原文透传并记 `truncated`（即便那条答复的形状刚好能被抢救）。
- **解析失败抢救（票 40）**：内容写完、只少收尾 `}` 的输出被抢救成摘要并照常替换（记 `summarized`）；引号没闭合、别的动作、别的形状一律不抢救，按原文透传。
- **逐字目标（票 39）**：`verbatim` / `character-for-character` / `exactly as written` / `exact text|lines|wording` / `逐字` / `一字不差` / `原样` 按原文透传、记 `exact-text`、发一条指向 `offset/limit` 的提醒；裸 `exact` 与"exact conditions and codes"这类概念型目标不命中。
- **`extract` 路径不提供 `keep`（票 26）**：带提取目标的摘要请求与隐私请求里，输出契约只出现 `summarize` 形态、规则正文不含保留全文的说法（阴性对照：不带目标的同一份提示词的对应位置仍是 `summarize|keep`）；带目标且结果低于 `minInlineTokens` 时一个模型请求都不发（隐私模式只发那一次隐私判断），原样透传并记 `not-candidate`。
- **规则摘要开关（票 26）**：`ruleSummary: false`（**默认**）时没声明 `extract` 的候选结果不发请求、原样透传并记 `rule-summary-off`（阳性对照：同一配置下带 `extract` 的调用照常摘要；同一个 `false` 值在两个方向上都可观察——勾上变成 `true` 后没声明 `extract` 的结果照旧摘要）；非候选结果仍记 `not-candidate`，所以这个取值恰好是"本该摘要却没摘"的那批。
- **启用位折叠自己那一组时不能走草稿（票 27）**：准入的启用位在组之上、保存即生效；勾上/取消勾选各写一次 `set admissionJudge`，组随它渲染或消失；`ruleSummary` 留在摘要组的草稿里（它折叠的控件与保存按钮同组，不存在存不下去的问题），且它不勾时摘要提示词规则正文只读、并给出原因。
- **只有一个设置座位、三个能力开关各就各位（票 28）**：「设置 → 内置插件」里的页签只指路——注册条目在、页签名随语言切换，页面上一个控件都没有、`options.inject` 缺席（阳性对照：页签上挂回一个开关，这两条就会变红）；页面文案只回答「去哪设」（断言它点明侧边栏「插件」页与详情页，且不含解释这一页取舍的句子）。摘要、准入启用位、隐私闸门三个开关分别在各自那一组之上，点一下当场写一次单字段 `mutate`，关掉时整组（含该组的保存 / 恢复默认）不在页面上、开关本身仍在；隐私开关与页签时代是**同一个键**，不新增字段。debug 与干跑在诊断组的草稿里，与该组的日志路径一起点「保存」写回；「干跑未生效」的提示读**已保存**的 debug、干跑与路径三个取值。不勾「自动摘要大内容」时摘要提示词正文只读，且它的字色是 `--dsw-alias-label-tertiary`（阳性对照：勾上后字色回 `--dsw-alias-label-primary`、可编辑）。
- **隐私路不受两个摘要开关约束（票 26 修正）**：`summarize: false` 且隐私开着时，判 `safe` + `summarize` 照旧替换正文（只发那一次隐私请求），判 `uncertain` 仍按失败策略放行原文；`ruleSummary: false` 且隐私开着时同样照旧替换，记录里不出现 `summary-off` / `rule-summary-off`。
- **去向与原因取值互不相同**：准入判 `no`、`keep`、按入口读回、摘要没变短、未进入候选、`uncertain` 放行、普通失败与窗口不足在 debug 记录里可分辨；动作与原因的两段式取值覆盖 privacy 路径的放行、`rejected` 拦截与摘要关闭。
- **准入前缀与摘要前缀逐字相同**（含调用形态与结果大小那两行）。
- **窗口不足可区分**：底层报告上下文溢出时，归类为「窗口不足」而不是普通判断失败，并按失败策略处理。
- 摘要失败、空结果、非法结果、超时一律原文透传；任何路径都不得抛出。
- `sensitive` 一律拒绝；失败策略 `passthrough` 与 `block` 各自生效。
- `read` 的两种顺序都不出现 `FS_NOT_OBSERVED`；按入口读回（路径命中本会话写出的 `locator`）时不再次摘要但仍过隐私判断，会话失效后同一路径按普通 `read` 处理。
- spill 后端缺失或 `saveText` 失败时透传且不留入口。
- **替换后的落盘内容被 token 计量器读到**，自动压缩的触发随之推迟（旧调研把它列为必须验证的一项）。
- 干跑不改变任何模型可见内容、不交回提醒、不调用 `saveText`，并在 debug 日志里留下「本应发生什么」的记录；debug 开关关闭或路径为空时干跑不生效。
- debug 日志不含原文、摘要正文、完整提示词与凭据。

## 工具结果精简

**定位**：把工具结果里的机械形状（格式控制序列、进度条的刷新过程、成片重复行）与超长正文的固定形态（只留头尾/窗口头尾）按确定性规则压掉。**不调用模型、不改内容的语义、每次都能说明被删掉的是什么**；不读 `spillPath`、不做 I/O、不新增会话事件（计划 §3.3）。

**插在哪**（票 15 落地）：`tools/post-execute` 里 `await next()` → `block` 判定之后 → **精简** → 隐私判断 → 摘要路。隐私判的是精简后的正文，因为它必须等于模型真正会看到的投影；下游已 `block` 的结果没有正文可改，照旧记 `not-candidate`。判定顺序、四个去向与所有例外在 `docs/dsh-result-clipper-pipeline.md` §1.0.1、§4.10、§4.11 写死，本节只写机制与参数。

**工具集**：`bash` / `grep`(native) / `pwsh`。这是本层自己的集合，与摘要的 `TARGET_TOOLS` 无关——`grep` 只吃精简、不进摘要；`glob` 全池 144,180 token、已自带 `GLOB_MAX_RESULTS = 100` 与位置说明，不值得一条 handler；`read` / `web_fetch` 一个字不动；`pwsh` 只吃通用变换（按内容判定，对它是免费的）。

**通用形状变换（链，按内容判定，无损在前有损在后，各自幂等）**：

| 顺序 | 规则 | 参数 | 有损 |
| --- | --- | --- | --- |
| 1 | 剥 ANSI 转义序列（CSI / OSC / 字符集选择 / 两字符转义 + 裸 `ESC` 兜底） | — | 否 |
| 2 | 去 `\r` 覆盖行（CRLF 先归一，每行只留最后一个 `\r` 之后的） | — | 否 |
| 3 | 相邻游程去重（仅相邻、不跨距离；空行游程豁免） | `MIN_RUN = 3`，命中留一行 + `[xN]` | 否 |
| 4 | 尾部偏置封顶（错误通常在末尾，所以尾部配额更大） | 头 50 / 尾 200 / **触发** 300 行 / 单行 2000 字符 | **是** |

这四条在 `src/condense.ts`，都是纯函数。计划 §4.2 的「首个命中者胜」管的是命令族 handler 的单选（票 16/17），**不是**这一组——不写开这条，实施者会套错，于是剥了 ANSI 就不去重。剥 ANSI 的兜底分支保证第一遍之后正文里再没有 `ESC`，幂等是构造出来的。

**封顶的触发读法（票 15 写死）**：计划 §4.3 的「头 50 / 尾 200 / 总 300 行」里 50 + 200 = 250 ≠ 300，唯一自洽的读法是 300 为**触发阈值**。所以是「>300 行触发，裁后保留头 50 + 尾 200」。

**分派层（票 16 落地）**：命令族 handler 是**分派后单选一个**，与上面那条链不是一回事——「首个命中者胜」管的是这一层。分派只读一份**扁平事实 map**（`command` / `exitCode` / `truncated` / `format` / `bytes` / `lines` / `estimated`）与一张**有序规则表**：**首个命中者胜**、**缺失的事实不匹配**（缺失是「没有这一项」，不是空值）。装载时对命令正则做**行首锚定校验**（按顶层 `|` 拆分支，每个分支都必须以 `^` 开头，否则整条规则被拒绝并告警）；命令链按**首个实质命令**分派，脚手架成分（目录切换、纯变量赋值、标题回显）与管道右侧不参与。**两条旧守卫在票 20 放宽**：输入已被工具自身截断只阻止 `compactDiff`（跨文件聚合量在残文上是假事实，由规则自己的 `facts: { truncated: false }` 拒绝），`sedWindow` / `rawDump` 照常接手；非零退出码不再整族挡下（`git diff --exit-code` 这类合法 diff 也会返回非 0），交给各族的正文守卫判断，`exitCode` 仍进事实 map 供 debug 观察。**平台面**：命令族规则只认 unix 命令串，因而**只在 `bash` 结果上求值**；`pwsh` 即使命令串就是 `git diff` 也不进分派（票 14 原型把规则注册在 `("bash","pwsh")` 上是测量产物，不是生产门禁）。实现在 `src/dispatch.ts`（纯函数，规则表按数据传入，夹具可注入）。

**层序（票 16 写死，票 17 沿用）**：**分派在先，且分派与族 handler 判的都是下游正文。** 命中某一族时**只跑那一族**、不再叠一遍通用链；未命中（或该族关着、被族守卫放弃、`compactDiff` 的截断事实不满足）才落通用链。四个理由：① 票 14 的三个数（`compact_diff` 37.0% / `sed` 69.0% / 原始转储 68.7%）都是在**下游正文**上测的；② 通用链先跑会把 >300 行的窗口先裁到 251 行，票 17 的「≥101 行大窗口」与「不丢窗口内的内容」在残文上无从判定；③ 用户故事 76 的「叠加生效」指的是**打开命令族开关不会把通用链这个能力关掉**（未命中的调用照旧走它），不是同一条结果上跑两遍；④ 命中之后再叠一遍通用链，这条链里**唯一的有损规则**（>300 行的尾部封顶）会把 `+`/`-` 行整段丢掉，直接破坏「不丢任何增删行」——所以命中时不再叠链不是图省事，是这一族的忠实性要求。

**命令族 handler（激进，默认开，按族开关）**：票 16 只落一族 **`compactDiff`**（`git diff`；`git show` 半边实测触发 0 次，因而**明确记为只覆盖 `git diff`**）。形态与参数照计划 §4.4 第 1 行：每文件累计 `+N -M`；保留**完整** `@@` 头（含尾部函数/符号上下文）；每 hunk 明细封顶 `max_hunk_lines = 100` 行；整体行数上限 `max_lines = 200`；前导上下文**每 hunk ≤3 行**、全 diff ≤ `max_lines / 10`，两者都**不计入** `max_lines`。两处与票 14 原型**有意不同**：① **无 hunk 的文件不得被压成空壳**——只有权限变更（`old mode` / `new mode`）、重命名或复制（`rename from` / `rename to` / `copy from` / `copy to` / `similarity index`）、二进制变更（`Binary files … differ`）的文件，收窄后至少留下那一行变化类型，**有 hunk 的文件同样适用**（同一文件既改权限又改正文时权限行也必须在）；② `diff --git` 的**引号路径**必须无歧义还原成真实路径——Git 默认 `core.quotepath`，中文文件名必然带引号，形态是 `"a/\344\270\255"` 这样的 UTF-8 八进制转义，观察面是**呈现出来的文件名逐字等于真实路径**；引号不闭合、转义非法或切分有歧义时保留完整原文件头，不把那段增减量归到别的文件名下。守卫不满足（不是 unified diff、hunk 外有无法识别的行、hunk 未耗尽）即整次放弃、退回通用链。实现在 `src/gitdiff.ts`（纯函数，守卫放弃交回 `undefined`）。

`sedWindow`（`sed` 大窗口）与 `rawDump`（`cat` / `ls` / `head` / `tail` / `nl`）两族的**名字与命名法**在此定死，规则、字段与实测读数已随**票 17** 落地，见下。

**票 17 再加两族**（形态与参数同样照票 14 原型 `transforms_sed_dump.py`，规则表顺序 `compactDiff` → `sedWindow` → `rawDump`，命中即只跑那一族）：

- **`sedWindow`（大窗口 `sed`）**：`^sed` 且**这次调用请求打印的窗口 ≥101 行**——脚本的操作数里带 `-n` / `--quiet` / `--silent`，且在**命令开头的地址部分**出现 `1,101p` 这种范围打印（`$` 当无限大）。**「只在地址部分取窗口」是相对原型的有意修正**：原型 `_RANGE`（`transforms_sed_dump.py:97`）扫的是整段命令串，于是 `sed -n 's/x/1,200p/p' f` 这类把范围写在**替换文本**里的调用会被误判成大窗口。落实这条要一个**最小的 sed 命令走查器**（`src/glance.ts`）：逐条命令先读地址（`\d+` / `$` / `/re/`，正则里的 `\` 转义不算收尾 `/`）、再认命令字母，命令字母是 `s` / `y` 时按**它后面那个字符**当定界符跳过两段参数（`\` 转义不算定界符）、再把 flags 推到 `;` / 换行 / `}` / 串尾——**flags 里出现 `w` 时直接跳到行尾**（`w` 后面那个文件名同样吃到行尾，`sed -n 's/x/y/pw /tmp/out;1,200p' f` 的文件名就带这个分号）；**其余命令字母推进到下一个命令边界**，命令的**自由文本**里不再读地址；`#`（注释）与 `a` / `i` / `c`（文本）、`r` / `w`（文件名）整行都是自由文本、直接跳到行尾——这几条命令的参数在 sed 里本就吃到行尾（BSD sed 实测 `sed -n 'w /tmp/t4.out;1,2p'` 生成的文件名就是 `/tmp/t4.out;1,2p`）。只有命令开头的 `\d+,\d+p` 与 `\d+,\$p` 才计入窗口（单地址、`/start/,/end/p`、倒序区间都不算）。`-f` / `--file` 是唯一的例外：脚本在**文件**里、命令行上没有脚本可看，这一族**不表态**（否则 `-f` 的操作数——脚本文件名——会被当脚本读：`sed -n -f '1,200p' f` 里的 `1,200p` 就是一个文件名）；同一条命令里另有 `-e` 时，`-e` 的脚本照常算（与 `-e` 在 `-f` 之前还是之后无关），因为命令行上确实有一个真脚本。所以替换文本里**连分号带范围**的写法（`sed -n 's/x/;1,200p/p' f`）也不再被误判——按 `;` 裸切脚本会把替换文本里的分号当命令边界，那正是这条要修的假阳性。收窄形态照原型——头 20 行 + `…[中段省略 N 行]…` + 尾 20 行（`N` 按整份输入数出，不是按保留数）。**命中门槛与应用期守卫是两个量**：门槛是请求的 101 行，守卫是正文实际 ≥60 行（不足即放弃这次收窄、交回通用链）——`sed` 窗口中位数才 110 行，请求 101 行却常常只兑现几十行。
- **`rawDump`（原始转储）**：命令名是 `cat` / `ls` / `head` / `tail` / `nl` 之一即命中（**族名只作为参数或文件名出现不算**，`grep cat f` 与 `git diff -- cat` 都不进这一族），形态是计划 §4.4 #3 的「glance 兜底」——头 15 行 + 最多 20 条「有意思的行」+ `…[中段省略 N 行]…` + 尾 15 行。有意思的行逐字取 `序号: 原行`（序号从 1 数起，便于回到输入里定位），只从头尾之外的行里挑、按内容去重；命中词表照原型 `INTERESTING`（`error` / `exception` / `traceback` / `fail` / `fatal` / `warn` / `denied` / `refused` / `timeout` / `not found` 与 `✗` / `✘` / `✖`，忽略大小写）。**应用期守卫同样是 60 行**：低于它就是 glance 尺寸，不值得为它付一次入口写入。
- 两族都 `lossy: true`，因而每次替换都必须有一条可回退入口——正文里没有可复用的上游入口时由本层写（安全层，票 15；票 20 起有上游入口就不再写第二条）；两族的**收窄都是有损的**这一点是它们各自的忠实性要求，与 `compactDiff` 同理。
- **窗口计数需要一条命令正则之外的判定**：`FamilyRule` 因此增一个可选纯谓词 `match?(command)`（与命令正则同域：都在**首个实质命令**上求值，返回 false 表示这条规则不命中、继续看下一条）。`sed` 的 ≥101 行窗口落在它上面——正则表达不了「地址部分的数字加起来 ≥101」。实现在 `src/glance.ts`（纯函数：`sedWindowLines` / `compactSedWindow` / `compactRawDump`，守卫放弃交回 `undefined`）。
- **「压成一行成功消息」的错误保全（`unless`）在这一层仍挂空**：计划 §4.4 的约束是「涉及该形态的精简必须在同一份输出同时命中错误模式时不做，成功短路不得把错误行盖掉」（`.scratch/dsh-result-clipper/doc/tool-result-trimming-plan.md:164`；规格「测试决定 · 错误保全」）。`compactDiff` / `sedWindow` / `rawDump` 三族都**不属于这个形态**（都是保留头尾与明细，不是把成功输出压成一行），而它要的是「按输出内容匹配」这整个维度——分派事实里没有输出这一维。所以约束**原样留在这里、不落代码**：哪一族第一个引入该形态，`unless` 与规格那两条断言**随那一票交付**。

**三个取舍（安全层，票 15 落地）**：

1. **尺寸下限 128 估算单位**（≈512 B）：低于它一个都不触发、也不写回退入口。不沿用 1024——那是为「值不值得发一次模型请求」设的下限，纯函数几乎零成本。
2. **净收益闸门，不可配置关闭**：比较的一侧是「精简结果 + 本层入口说明的预留上界」（`ENTRY_RESERVE = 256` 字符；正文已有上游入口时不加这条预留），另一侧是**下游正文**（ADR 0005）。省不到 **24 估算单位**就交回下游正文。两把尺子是一把——都用 `@deepseek-ai/dsh-token-meter/estimate`，不引入第二套估算口径。
3. **有损必须有一条可回退入口，写不成且没有上游入口即返回原文**：本层写入口时，先把替换前的完整正文写进 spill（入口说明用「精简」措辞，`composeEntry` 的 `condense` 分支），写不成（没有后端 / `saveText` 失败 / 没有会话归属）就交回下游正文；正文里已有上游入口（spill 位置说明或带路径的截断说明）时不再写第二条（票 20）。

**忠实性守卫（放弃 ≠ 失败）**：族 handler 抛异常、或自己判定正文形态不满足（不是 unified diff、hunk 未耗尽、窗口/转储低于应用期下限）时，那一族放弃、交回通用链；通用链自己的规则抛异常仍按整层放弃记（计划 §4.1 #8）。通用链本身**不再**因为上游位置说明整层放弃（票 20）：说明留在尾部、不参与单行截断，由入口归属判定跳过本层入口。`failed` 仍然只表示模型或 route 出了问题，两者不得混同。

**四个去向与诊断**：动作 `condensed` 与 `summarized` / `rejected` / `unmodified` 并列；`unmodified` 新增 `condense-off`（总开关关）/ `condense-abstained`（守卫放弃）/ `condense-not-shorter`（改了但过不了闸门）。本层「一处都没改动」时不表态，交给既有词表。记录里另有 `condense` 字段：`rules`（真正改动了正文的规则 id，票 16 起也可能是**命令族 id**）与 `truncated`（输入是否已被工具自身截断，取自 `bash`/`pwsh` 结果的 `value.stdout` / `stderr`）；票 16 再加两项——`family`（本次**选中的命令族**）与 `facts`（分派事实的扁平 map，**缺的事实不在里面**）。没有族接手时 `family` 不存在：未命中、该族关着、`compactDiff` 因截断事实不满足而被规则拒绝，三种在诊断里是同一个样子，要分开看结果取值与 `facts` 里那条决定性的事实；族被选中但**它的守卫放弃了**时 `family` 在、`rules` 记的是随后通用链里真正改动正文的 id（守卫放弃落通用链，见层序）。

**干跑**：判定照算、取值照写，但不替换正文、不写回退入口、不记台账，交回下游决策。它不是可选项——用来在打开或调整这一层之前看清会发生什么；票 21 起「按命令语义精简」默认开，干跑仍是排查单条结果与 A/B 的观察面。

**与摘要的关系（规格「共存」）**：精简过的结果**不再进摘要路**（不再判候选、不查 memo、不发准入与摘要请求），隐私路照跑。同一份结果不该被程序削一遍、再被模型改写一遍；这同时消掉「摘要的 `replace` 把精简后的正文当原文写进存储、于是有损封顶的入口变成无人引用的副本」这个矛盾。

**落在配置面**：总开关 `condense`（**默认开**，volatile，票 19 已上设置页：配置区最下面的第一个勾选、保存即生效）与六个**非 volatile** 参数（`condenseMinUnits` / `condenseMinNetGainUnits` / `condenseHeadLines` / `condenseTailLines` / `condenseMaxLines` / `condenseMaxLineChars`）：写在配置文件里可读、改值即按其取值生效、设置页完全看不见。票 16 再加五项——**「按命令语义精简」`condenseByCommand`（默认开，volatile，票 19 已上设置页：总开关开着时在它下面一级、同样是保存即生效的勾选；总开关关掉就收起）**，以及四个**非 volatile** 字段：族开关 `condenseGitDiff` 与它的三个封顶参数 `condenseGitDiffMaxHunkLines`（100）/ `condenseGitDiffMaxLines`（200）/ `condenseGitDiffLeadingContext`（3）。**族参数一律按 `condense<族名><参数名>` 平铺**（与 `condenseMinUnits` 同一批、同一命名法），不新增嵌套容器；两个 `maxLines` 是不同层的量（一个是通用链的封顶触发行数，一个是这一族的整体行数上限），靠前缀区分。**票 17 再加九项**，仍是非 volatile：两族开关 `condenseSedWindow` / `condenseRawDump`（**默认都开**，理由与 `condenseGitDiff` 同：总开关打开就该有族接手，这两个开关是给逐个 A/B 用的）与七个数——`condenseSedWindowHeadLines`（20）/ `condenseSedWindowTailLines`（20）/ `condenseSedWindowMinLines`（60）/ `condenseRawDumpHeadLines`（15）/ `condenseRawDumpTailLines`（15）/ `condenseRawDumpMinLines`（60）/ `condenseRawDumpHits`（20）。**参数只到原型 CLI 能拧的那几个**：单行字符上限（2000）原型写死在 `all_rules` 的 `cap_line` 里、不是可拧的量，因而不做成配置项。

**依赖的外部假设**：正文尾部元数据的文案是识别依据，不是契约——上游位置说明（spill-policy / native `grep` / native `glob` 共用 ` stored at: `）、bash 的截断说明 `[output truncated; full output: …]`、退出标记 `[exit code: N]`。上游改文案时这里会漏认：位置说明漏认的后果是本层追加第二条入口；截断说明漏认的后果是把 `(unavailable)` 当可用入口；退出标记漏认的后果是 `compactDiff` 放弃、落通用链。假设写在 `src/notice.ts` 的 `POSITION_NOTICE_MARKER` / `TRUNCATED_NOTICE` 与 `src/condense.ts` 的 `EXIT_MARKER` 上；上游说明行的单行截断豁免（通用链与两族共用）也在 `src/notice.ts`。
