# dsh-result-clipper 设计

状态：设计树已收敛并逐项确认（2026-10-01 复核）。

`dsh-result-clipper` 同时提供工具结果摘要与隐私闸门。两项能力分别开关，默认关闭；摘要是主能力，隐私闸门是可选的尽力而为保护模式。两项同时开启时，隐私判断先于摘要。为摘要、隐私判断和摘要准入提供请求的模型统称**摘要模型**，它不执行主会话工具调用。

**作用范围**：两种模式都只介入本来会进入模型的工具结果内容。会话日志不是目标，只是继承已经替换过的投影的副作用；只进日志、不进模型的内容（例如 PTC 中途子调用副本）不处理。

## 摘要

摘要发生在工具结果进入主模型上下文之前。插件用程序结构化生成局部任务上下文（当前用户目标、当前步骤的助手意图、工具身份与参数、有上限的相关摘要），不复制整个主会话。

- **目标工具**：首版硬编码 `bash`、`web_fetch`、`read`（三者覆盖约 95% 的工具结果）。前提是目标工具**不得定义 `finalizeContent`**——已核实这三者都没有；`terminal_*`、`job_*` 定义了它，永久排除。
- **候选范围**：正文为文本、且估算长度落在 `[minInlineTokens, maxSummarizeTokens)` 的结果。含图片等非文本块的结果透传，不参与摘要与替换。
- **阈值单位**：DSH 估算器单位（4 字符/token）。沿用它是为了与 spill 的 `maxInlineTokens` 及既有阈值统计同单位；该启发式对中文低估约 2.5–3 倍，所以 1024 单位对纯中文正文大约相当于 2,500–3,000 个真实 token。`minInlineTokens` 默认 `1024`、可配，`0` 表示不设下限；`maxSummarizeTokens` 默认 `12500`、可配。上界是本插件自己的字段，**不读取 spill 的配置**；改它等于改谁来处理超大结果，部署把 spill 阈值改小时两者的交互必须在 README 写明。
- **摘要准入判断**（独立开关，默认关闭）：命中候选范围且隐私模式关闭时，先用不含工具正文的固定前缀请求一次只返回严格 `yes`/`no` 的判断。`yes` 才发起带正文的摘要请求；`no` 透传；其他输出、超时或失败按失败处理，直接发起带正文的摘要请求。隐私模式开启时跳过准入，直接走一次同时返回隐私结论与摘要字段的请求。
- **准入与摘要的固定前缀缓存**只是性能观测，不是正确性前提；两次请求在语义上必须各自独立成立。
- **请求形态**：固定安全外壳 + 代码固定的结构化输出 schema；工具内容始终作为不可信数据分隔输入；页面只编辑规则正文与 few-shot 示例，安全外壳与 schema 改不掉。
- **失败语义**：模型不可用、超时、空结果、非法结果一律**原文透传**。任何路径都**绝不能抛**——`tools/post-execute` 抛错会把整个工具调用变成错误结果。
- **并发**：每条工具结果独立处理，不共享状态、不做全局串行；DSH 自己的工具调用并发池已经限制总数。

## 原文入口与保留

- 被摘要的结果在替换前调用 `ctx.get('spillStore').saveText(...)`（`owner.sessionId`、`source{tool, toolName, callId}`、`suggestedName`、完整正文），把返回的 `locator` 与 `retrievalHint` 作为固定的入口说明写进摘要正文。
- **保留与清理全部由 DSH 的 spill 后端负责**（本机后端：`cleanupPeriodDays` 默认 30 天、进程启动时扫一次，`0` 关闭）。插件不设条数上限、不自行清理、不解析 locator。
- 后端缺失或写入失败 → 该结果**透传不摘要**，以保住「没有入口就不摘要」的不变量。
- `read` 读取摘要保存的入口时只跳过再次摘要，仍经过隐私判断。重读不得跳过 `fs/observed` 的真实 version 发射；验收覆盖「同一 turn 先 read 后 edit」与「read 被摘要后再 edit」两种顺序，都不得出现 `FS_NOT_OBSERVED`。

## 隐私闸门

- **判断面**：`content + additionalContexts` 在 spill 之前的原始投影，含 PTC 子调用递延到外层结果的图片与附加上下文。它是最终进入模型内容的**超集**（spill 只会删、不会加），因此判定只会更保守。
- **只判文本**：分类器只接收投影中的文本，不接收图片块；含图片的结果按其文本判定，图片内容不参与隐私判断，README 明确写出这一点。运行在本插件外层的其他非 `prepend` 监听器可能在决策返回之后追加附加上下文，那部分不被判断。
- **不设附加消息上限**：隐私模式请求把完整投影交给本地 route；长度上限只约束摘要模式。
- **合并请求**：隐私模式固定返回 `privacyVerdict: safe | sensitive | uncertain` 与 `summary: string | null` 两个字段；判定为 `sensitive` 或 `uncertain` 时提示词要求 `summary` 为空，程序始终忽略该字段。
- **失败策略**（全局配置）：`sensitive` 始终拒绝；`uncertain` 与技术失败按 `passthrough`（**默认**）或 `block` 处理。默认选择 fail-open，因此**失效必须可见**（见下）。
- **拒绝形状**：使用原生 `{kind:'block', feedback:[固定文案]}`。结果按失败标记，反馈为固定、不可编辑的文案（含工具名，不含参数与正文），工具附带的上下文一并丢弃；文案写明不要重试。失败策略 `block` 与 `sensitive` 使用同一形状。
- **本地 route**：复用 DSH provider route；主 route 同时用于摘要与隐私，准入可单独选择 route、未配置时跟随主 route。隐私模式要求用户在页面**明确确认**主 route 是本地的；DSH 的 provider 信息只有 `{id, name}`，插件无法自动证明，也不通过 `baseURL` 猜测。未确认视为配置失败，按失败策略处理并显示警告。
- **失效可见性**：设置页插件卡片常驻警告（route 未确认本地、最近一次失败放行）；运行期发生失败放行时，每次会话追加**一条**插件 user 消息（不含任何正文，每次会话只提醒一次）。DSH 目前没有 host→client 的瞬时状态通道，因此「不进会话日志、模型也看不到」的运行期警告需要新增 DSH 接缝，本设计不要求它。

## 监听器位置、PTC 与观察面

- 监听器注册为**默认（非 `prepend`）**：确定性地看到 spill 之前的原始结果，不依赖插件装载顺序（两个 `prepend` 监听器之间是后注册先跑）。
- **必须跳过 PTC 子派发**：子派发与普通派发走同一条 `tools/post-execute`，用 `exec.parent !== undefined` 识别后直接 `next()`（spill 使用同一判据）。理由是子派发的结果只是程序内部的中途值：对它返回 `block` 会让沙箱程序抛错，带 `value` 的决策会替换程序收到的值，替换 `content` 则会改写持久日志副本。插件只处理外层最终结果。
- **隐私判断覆盖 PTC 的外层 `run_code` 结果**：它是普通派发，走 `tools/post-execute`，是模型唯一能看到的 PTC 内容；子调用延迟给外层的图片与附加上下文也并入该结果的投影。只有 prepare、pre-execute 或守卫失败才走 `final-result` 旁路。
- 首版**不注册** `tools/ptc-dispatch-log`：那条接缝只改持久日志副本，不影响程序与模型，属于“不介入中途过程”。因此 PTC 中途子调用的正文仍会作为 `tool/ptc-dispatch` 事件进入会话日志并可能被上传——这是写进 README 的保护面缺口，不当作遗漏。
- 敏感时返回的 `block` 会原样穿过 spill——spill 只加工 `kind:'accept'` 且不带 `value` 的决策。
- `finalizeContent` 在 `tools/post-execute` 之后执行，且是模型可见的最后一跳；只有 `terminal_*`、`job_*` 定义它，这正是目标工具必须逐个确认的原因。
- **诚实边界**：可观察范围是普通派发（含外层 `run_code`）的 `tools/post-execute` 结果；`final-result` 旁路（prepare、pre-execute、守卫失败）与 PTC 中途日志副本不保证；普通 `tool/result` 的 session-log 继承已经替换过的投影。这是尽力而为的保护目标，不是安全承诺。
- `final-result` 旁路产生的错误结果**会进入模型但本插件收不到**，其中常回显工具参数。本设计接受该缺口；若上游将来提供覆盖这些结果的接缝，插件可零结构改动接入——记为上游备忘，不阻塞首版，也不作为本插件的依赖。
- 元数据 `meta` 会进入持久化、界面或会话日志，不属于模型可见内容，插件不改动它。文档**不得宣称降低上下文占用**——`contextBreakdown` 没有工具结果这一维。

## 配置面与设置座位

- 开关放在「设置 → 内置插件」；参数放在插件自己的详情卡片。
- 座位：注册 Host settings 命名空间 + 一个 `plugins.item` 卡片（`view: 'page'`），照 `@deepseek-ai/dsh-client-ui-settings-web-search` 的先例；逐字段恢复默认用 `resetField`（底层是 `op: 'unset'` 回落到 schema/base 默认）。提示词恢复默认通过清除用户覆盖实现。不需要 YAML 兼容路径。
- **可配**：两项能力开关；`minInlineTokens`（1024）；`maxSummarizeTokens`（12500）；失败策略（`passthrough` | `block`）；准入、摘要、隐私三类请求各自的「关闭推理」开关（默认都关闭推理）；摘要/隐私/准入提示词的规则正文；debug 开关与路径；干跑。
- **固定常量**（页面只读展示，不开放配置）：辅助请求超时 20s；相关摘要 ≤3 条、每条 ≤600 字符；`additionalContexts` ≤2,000 估算器单位；摘要输出 ≤512 token。固定前缀的字段与长度上限由程序控制，页面不开放任意扩大上下文。
- 页面加一句静态警告：摘要会把工具正文发送给所选 route。

## 干跑与诊断

- **干跑**：走完整条流水线（准入、隐私、摘要），但绝不替换任何内容、绝不 append 会话事件，只在 debug 日志里记录「本应发生什么」；要求 debug 路径已配置。
- **debug** 默认关闭。开启后路径必填，插件创建父目录并以追加方式写入 metadata JSONL（工具名、结果大小、准入结论、摘要是否生效、调用耗时、缓存观测、判断器输入 token 数）。不写原文、摘要正文、完整提示词、凭据；不自动切换到临时路径。

## 当前范围与非目标

- 首版只做三个目标工具；不做按工具声明的可重取性（需要 DSH 新接口）。
- 不做 `read` 重复读取的去重或复用。若以后要做，判据是「本次区间被同一文件版本的已读区间**完全覆盖**」（参数相同只是特例），且那次已读记录必须仍在模型可见历史里且未被改写，并且绝不跳过 `fs/observed` 的真实 version 发射。
- 不改造 spill-policy，不修改 DSH 源码或公开契约。
- 提示词的具体措辞不在验收范围内，只验收「固定外壳与 schema 改不掉、可编辑段只替换规则正文与 few-shot」的拼接方式。
- 不额外做界面徽标：被拦截的可见面就是原生失败反馈，被摘要的可见面就是正文里的入口说明。

## 验收要点

- 三个目标工具逐个确认不定义 `finalizeContent`，并有守护测试。
- **PTC 子派发被跳过**：用带父派发的夹具断言监听器不改变子派发结果，程序不会因 `block` 抛错。
- 摘要失败、空结果、非法结果、超时一律原文透传；任何路径都不得抛出。
- `sensitive` 一律拒绝；失败策略 `passthrough` 与 `block` 各自生效。
- `read` 的两种顺序都不出现 `FS_NOT_OBSERVED`。
- spill 后端缺失或 `saveText` 失败时透传且不留入口。
- **替换后的落盘内容被 token 计量器读到**，自动压缩的触发随之推迟（旧调研把它列为必须验证的一项）。
- 干跑不改变任何模型可见内容、不 append 会话事件。
- debug 日志不含原文、摘要正文、完整提示词与凭据。
