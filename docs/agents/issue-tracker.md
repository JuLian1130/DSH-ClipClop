# Issue Tracker: Local Markdown

本仓库的规格和任务保存在 `.scratch/`。

## Conventions

- 每个功能使用一个目录：`.scratch/<feature-slug>/`。
- 功能规格保存为 `.scratch/<feature-slug>/spec.md`。
- 规格顶部使用 `Status:` 记录状态：`ready-for-agent` 表示可交由编码代理实施；`implemented` 表示规格的验收标准已全部落地——每条判据都有可跑用例、门禁全绿，且没有判据仍挂在未验证的机制上。规格之后再改，状态跟着回退，不在文档里留一句与仓库现状不符的状态。
- 拆分实施任务的票在 `.scratch/<feature-slug>/issues/` 下按 `01-<slug>.md` 顺序创建：一张票一个文件，编号按依赖顺序（阻塞者在前），每票的 Blocked by 写明它依赖的票。

当技能要求发布到 issue tracker 时，按以上约定创建或更新对应 Markdown 文件。

## 复审与收敛

票面写判据，机制写在 `docs/<feature>-design.md`：复审只该在票里找**判据层**（验收项是否可观察、是否引到规格出处、层级是否放错、前置是否漏）与**机制断言层**（票面新引入的机制结论是否有误、是否与源码或现状冲突）两类问题；措辞、编号、出处、记账这类只影响可读性的项按低严重度处理，不单独开一轮。

- 一轮复审**算收敛**，当且仅当它没有判据层发现、也没有机制断言层发现。只剩低严重度项时不再补一轮解释，而是把「已决定不改」的条目连同理由写进票面，供下一轮直接跳过。
- 连续两轮的发现集中在同一段落，说明问题不在措辞而在结构：改写票面（把机制移进设计文档、把说明降级为缩进段、合并过碎的勾选项），而不是再补一轮解释。
- 机制描述只留一处。票面只写判据 + 规格出处 + 观察面（加上「形状即决定」时才内联的形状）；DSH 机制、源码依据、实测与源码核对的分界都写进设计文档的机制节与「验证状态」，票面用章节名指过去。

## 票面落修的取证纪律

改票面时，下一轮复审打的正是这些新写的句子，所以每一句都要**当场取证**——落笔的同一次就把依据取到手，不要凭印象写，更不要事后再补核。三类话最容易写错：

- **数字**：token 数、行数、比例、默认值、计数——**连同口径一起写**（哪把尺子、分母是什么、行口径还是调用口径）；两个数之间的百分比要写明按哪个量算的。
- **源码能力断言**：任何「某个函数拿不到 X」「某个提交只枚举 Y」「某个工具不能跑 Z」——打开那段代码确认，并写出 `path:line`。
- **测试断言**：任何「既有测试断言了它／没断言它」——grep 到具体用例再写；引用**用例名**或「文件 + `it(...)` 标题」，不写行号。用例数、文件数这类命令输出不抄进文档，写「`pnpm test` 全绿」即可——副本会在下一次改动后过期。

同一纪律也管跨文档同步：一处口径改掉后，把引用同一口径的落点（票面、计划、`ticket-plan.md`、规格）**一次列全再逐处改**，别留副本——副本漏改是复审里最常见的返工来源。

## 代码复审的收敛判据

上一节管票据平面；对**已实现代码**的复审（code review）审的是标准轴（是否违反本仓文档化的写法）与规格轴（是否忠实实现票据）。这个循环同样需要停表条件，否则会把判断项当成欠账一直修下去。

- **只有两类发现进本轮修复**：① 硬性的**代码/行为**标准违规（引得出本仓文档里的规则原文，且能说明在什么可观察行为上出错）；② 与票面某一句冲突或漏了它。两类都要能引出出处。
- **取证与记账类缺陷不进修复**：测试引用行号、抄用例数/文件数、计数缺分母、编号与出处形式，由 `pnpm check` 的文档 lint 或一次文档卫生提交处理；只剩这类项时按「已决定不改」收口，不补轮。
- **基线嗅探与措辞偏好不进修复**：命名、重复、数据泥团这类启发式对任何规模合理的改动都会开火，属判断项。与票据平面同样处理——写「已决定不改 + 理由」，不补轮解释。
- **与票面不变量冲突的实测反例不得进「已决定不改」**：台账只冻结判断项（方向、口味、启发式）；某条登记一旦被实测证明会让真实命中被删，它要么按票面改成「明确不承诺的子集」，要么修，不能停在登记上。
- **复审默认只判不修**：落修需发起方明确要求；落修后只对代码/行为改动再复审，文档记账项由 lint 兜底。
- **结构性改动单独立项**：复审里冒出来的抽象、共享层、构建与门禁配置，若超出本票交付范围（尤其要动其它已关闭票据的文件），另开一张票或一个独立提交，不折进当前票——否则票外表面被拉进本票的复审面，发现数只增不减。
- **一条发现只修一次，且修在判据上**：先把它服务的判据写成一句可判断的话（「这条断言必须证明什么」），再改代码。追着评审建议的措辞改，会在几轮里来回震荡。判据句必须是**类**的：覆盖「哪一类构造、在什么条件下不裁」，不能把当轮发现的**那一个**构造抄成一句——单构造判据下一轮换个构造照样开火。
- **复审循环没有记忆**：每轮都是新上下文，不记得上一轮拒过什么，所以「拒掉」不会让下一轮少报一条。收口靠上面的规则判断，不等发现数自然降到零。
- **复审 prompt 必须携带本节判据与票面「已决定不改」台账**：每轮开始前先读本节与台账；reviewer 只报两类进修复的发现，判断项与取证/记账形式类缺陷写进台账或登记区，供下一轮跳过。
- **行为类判据写成不变量 × 覆盖矩阵**：判据要能回答「所有族 × 所有形态 × 哪些配置边界」都成立，而不是单点例子；同一张矩阵落成表驱动用例，实现与复审共用。单点例子会让复审退化成对抗式探针，每轮换一个边角。
- **一轮复审算收敛，当且仅当**规格轴无「缺失/部分」、无「实现错误」，且标准轴无**行为类**硬性违规。此后不再补轮。
- **承诺面必须可枚举**：行为判据若量化在开放语法面上（例如「所有 grep 调用」），票面必须写明承诺子集；子集外的行为是「整次不表态」，不承诺等价。
- **同一文件 / 同一层连续两轮出现新发现，判为结构问题**：停审，改结构（例如把默认翻成「未证明等价一律不表态」）或缩承诺面，并在票面写一句「为何不按结构改」；不再逐条补轮。
