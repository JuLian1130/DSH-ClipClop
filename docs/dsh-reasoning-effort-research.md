# dsh-reasoning-effort 调研：轮边界注入 effort 文本对推理长度的影响

状态：**调研完成，结论有实测支撑**；官方 API 与 cline-pass 两条通道各自独立复现，**未做跨任务、跨前缀复现**。**距离效应已用修正装置重测**（证据 F）：注入的效应**只覆盖紧邻的那一轮**，隔 1 轮起就不可靠。第一版距离实验（证据 E）因探针重复导致基线地板化，**其"持续到第 10 轮"的结论已被推翻，保留作方法教训**。原始数据与探针在 `.scratch/probes/effort-*`。本文件只记录实测结论与机制依据，不含插件设计。

## 调研问题

1. 能否在**不改变已缓存前缀**的前提下，改变某一步的推理长度？
2. 走请求参数 `reasoning_effort`（前端渲染）与走"把 `Reasoning Effort` 模板当文本注入"这两条路，各自表现如何？

## 结论

| 场景 | 结论 | 关键证据 |
| --- | --- | --- |
| **长上下文（≈3.9k token 前缀）+ 最新 user 轮前插入 system 消息** | **有效，且必须贴着那一轮** | 证据 F（n=20/格）：紧邻轮 `inject-100` 5194 vs 中性文本 2940，z=3.46，p=0.001；隔 1 轮 z=0.87 |
| **注入的数值被当作刻度读取（1 与 100 分档）** | **有效（仅紧邻轮）** | 证据 F d=0：`inject-100` 显著高于其余全部（vs padding 3.46、vs inject-1 3.87、vs inject-50 4.98）；`inject-1`、`inject-50`、中性文本、基线四者互相不可区分 |
| **"多塞文字"本身** | **无效** | 证据 F 每个距离上 中性文本 ≈ 基线（d=0 z=0.24；d=10 中位数 2704 vs 2609）；短上下文亦然 |
| **短上下文（单轮、距 system ≈40 token）** | **无效** | 协议内注入 6/40 vs 中性文本 6/40，p=1.00 |
| **请求参数 `reasoning_effort`（cline-pass，pin 到 deepseek）** | **有效，且是唯一能拉量的通道** | `minimal` 441 < `low` 569 < `max` 966（紧邻轮）；证据 F 的 `max`+注入是唯一把零推理压到 0/20 的组合 |
| **请求参数（官方 API，low→high）** | **未测出差异** | 长上下文下 median 718 vs 613.5，z=0.56，与中性文本无差别 |
| **注入的效应持续到第 3/10 轮之后** | **不成立（第一版结论已推翻）** | 证据 F：d=1 z=0.87、d=5 z=0.11、d=10 z=0.05；把 d≥1 并起来 z=1.84（p=0.066）。第一版"持续到第 10 轮"是基线地板化造成的假象 |
| **注入一次、随后从上下文移除** | **无效** | 只保留它产生的答案：k=10 median 0 ≈ 基线（z=1.33），k=3 显著低于保留组（z=−2.75） |

一句话：**注入是一条"贴着当前轮才有效"的通道**。在最新一轮前插一条 `Reasoning Effort: N`（N=100 这种明显高于前端值的数）的 system 消息，能把这一步的推理长度从 ~2900 拉到 ~5200（中位数 +77%），代价约 27 token，此前前缀的缓存不受影响；**但隔一轮就掉到噪声水平**，所以"注入一次影响后面几轮"不成立——要影响哪一轮，就在那一轮之前注入。要稳定拉长推理，仍应优先用请求参数 `reasoning_effort`（cline-pass 上 pin 到 `deepseek`）；要压低推理用 `minimal`。它对短上下文没有证据支持，也不是精确档位。

## 实验装置

- **冻结前缀**：system（编码 agent 规则）+ user（修 CI 失败）+ 10 组 `tool_call` / `tool_result`（含 `reasoning_content`，按 DeepSeek「tools + thinking 必须回传」的要求），合计 3959 prompt token（含 tools 定义）。末端接一条规划型 user 轮（"先给诊断与方案，不要调用工具"）。
- **注入**：在末端 user 轮**之前**追加一条 `role: "system"` 的消息，内容为
  `Reasoning Effort: {N} (range 1-100, the higher the value, the more thorough the reasoning)\n\n`。
- **观测量**：`completion_tokens_details.reasoning_tokens`（推理长度），另记 `finish_reason` 与 `prompt_cache_hit_tokens`。
- **顺序**：每轮把各臂顺序打乱后各发一次，避免固定位置效应。

## 证据 E：距离持续性（第一版，**已被证据 F 取代**）

> **方法缺陷（保留作教训）**：本版把注入固定在第 10 步后、让测量点往后挪，于是每个深度都要在历史里重复同一句探针提问。到 k≥3 时历史里已含有它自己的答案，模型直接复述，**基线自己地板化**（A 的零推理率 1/20 → 9/20 → 15/20）。因此本节"注入效应持续到第 10 轮""任何轮边界 system 消息都能阻止塌陷"两条结论都不成立——它们是地板化产生的假象。证据 F 用"测量点固定、注入位置后移"的装置重测，结论相反。

装置：10 步冻结前缀之后放第一次"探针提问"，注入点紧随前缀（即探针之前）。测量点距离注入 k 个助手轮，中间的回放轮为冻结内容，**所有臂逐字节相同**；k=1 就是证据 B 的紧邻轮。参数 pin 到 `deepseek`，`max_tokens: 16384`，每格 20 样本，6 臂共 340 请求，0 截断，1 条路由漂移已剔除。

| P-low-keep | **中性文本**（同位置同形状） | low |
| B-low-keep | effort 模板（N=100） | low |
| C-max-base | 无 | max |
| D-max-keep | effort 模板（N=100） | max |
| E-low-drop | 注入过，测量时**已从上下文移除**（只留下它产生的答案） | low |

| 臂 | k=1 中位数 / 均值 / 会推理的样本 | k=3 | k=10 |
| --- | --- | --- | --- |
| A-low-base | 861.5 / 855 / 19·20 | 312.5 / 460 / 11·20 | **0 / 141 / 5·20** |

k=1   D>A 2.16‡   D>P 2.89‡   其余全部 |z|<1.8（B>P 1.76，B>A 0.95，C>A 1.42）

三条读数：

1. **效应不衰减，因为基线在远距离自己塌掉了。** 无任何轮边界消息时，第 10 轮之后 75% 的样本**完全不推理**（median 0，mean 141），注入组仍保持 mean 741–2975。塌陷率：A 5·20 → P 15·20（Fisher p=0.010）。
2. **远距离上 effort 文本退化成"一条多余的系统消息"。** k=10 注入组与中性文本组中位数 412 vs 425.5（z=0.14），k=3 是 978.5 vs 634（z=0.46）——**内容不贡献**。内容效应只在紧邻轮可见，且本批只有边缘显著性（B>P p=0.079）。
3. **量级由请求参数决定，不在提示词里。** k=10 排序 `D ≥ C > P ≈ B > A ≈ E`；把参数换成 `max` 净增 4 倍（C vs P 1683 vs 425.5；D vs P z=3.49）。把两条通道叠加（D）是唯一把"不推理"压到 0·20 的组合（D vs B z=3.47，D vs C 不显著）。

补充（探索性，按 `reasoning>0` 分层后看"真的推理时写多少"）：k=10 的 A 549(n=5) / P 589(n=15) / B 998(n=14) / C 2368(n=14) / D 2089(n=20)。即中性文本只提高"会不会推理"，effort 文本与参数才提高"写多长"——但该分层是事后切分，只作解释用，不作判据。

E 臂的含义：**注入的效应必须靠那段文本留在上下文里**。把 literal 删掉、只留下它产生的答案，行为退回基线（k=10 z=1.33；k=3 z=−1.23），并显著低于保留组（k=3 z=−2.75）。所以"插一次就够了、后面让模型自己带"不成立。

## 证据 F：距离效应（修正装置，n=20/格，420 样本）

装置把变量翻转：**历史固定 19 轮，测量轮固定在最后，只把注入块的位置往前挪**。

- 历史 = 证据 E 的 10 步前缀 + 9 轮冻结续写；测量轮是**一句全新的取舍题**（"该动 lexer 还是该动 stream 契约、最危险的假设、证伪命令"），在所有条件里逐字相同，且**历史里从未出现过**。
- 距离 d = 注入与测量轮之间隔的助手轮数：d=0 表示紧贴在测量轮之前；d=10 表示在历史第 9 轮之后。
- 因为测量轮只有一句、且只问一次，"历史里有自己的答案"从根上消失。**基线不再地板化**：无注入条件 20/20 都推理，中位数 2609，sd 1517。
- 4 个注入值 × 5 个距离 + 1 个无注入基线 = 21 条件；pin 到 `deepseek`，`max_tokens 16384`，**420/420 可用、0 截断、0 路由漂移**，`prompt_tokens` 逐条件恒定（5048 / 5074–5077）。

| 条件 | d=0 | d=1 | d=3 | d=5 | d=10 |
| --- | --- | --- | --- | --- | --- |
| 无注入（基线） | 2609（与 d 无关） | | | | |
| padding | 2940 | 3286 | 2494 | 2947 | 2704 |
| inject-1 | 3505 | 2394 | 3067 | 2691 | 2668 |
| inject-50 | 2260 | 2861 | 2916 | 2261 | 2606 |
| **inject-100** | **5194** | 4082 | 3768 | 3072 | 2470 |

（中位数；全部条件零推理率 0/20）

`inject-100` vs `padding`：

```
d= 0   5194 vs 2940   z=3.46  p=0.001   ΔCI[-3399,-640]
d= 1   4082 vs 3286   z=0.87  p=0.387
d= 3   3768 vs 2494   z=2.14  p=0.033   （去极值后 z=2.76，不是离群点）
d= 5   3072 vs 2947   z=0.11  p=0.914
d=10   2470 vs 2704   z=0.05  p=0.957
把 d>=1 合并： z=1.84  p=0.066
```

`inject-100` 自身随 d 递减的 Jonckheere–Terpstra 趋势 z=5.55（padding 无趋势）。

三条读数：

1. **效应只覆盖紧邻那一轮。** d=0 是唯一稳健的点（p=0.001，中位数 +77%，还是唯一显著高于基线、padding、inject-1、inject-50 四者的条件）。隔 1 轮就掉到 p=0.39；d=5、d=10 完全归零。d=3 有一个名义命中（p=0.033），但它在 5 次比较里不校正多重比较，也不构成单调衰减（d=3 高于 d=1），不能作为"可以隔 3 轮"的依据。
2. **第一版的"持续到第 10 轮"被证伪。** 旧装置里 d=10 的 A=0 / B=412 全部来自基线地板化；修正装置里 d=10 是 2470 vs 2609，毫无差别。
3. **数值方向可复现。** d=0 上 `inject-100` 显著高于一切；`inject-1`、`inject-50`、`padding`、基线四者两两 |z|≤1.95、全部不显著。即：**只有明显高于前端的值才起作用**；把前端同一个值（50）再念一遍等于没说。

### 有效间隔

| 间隔 d | 结论 |
| --- | --- |
| **0**（紧贴测量轮之前） | **有效**：5194 vs 2940，z=3.46，p=0.001 |
| 1 | 不可靠：z=0.87，p=0.39（d≥1 合并 p=0.066） |
| 2 | **未测** |
| 3 | 名义命中（z=2.14，p=0.033），但不单调、不校正多重比较，不能作为依据 |
| 5 / 10 | 无效应：z=0.11 / 0.05 |

**注入的有效间隔是 0**：要在哪一轮起作用，就必须在那一轮之前注入。不存在"每 k 轮补一次"的省法——不注入的轮回到基线水平（d=10 时 2470 vs 基线 2609）。按每轮注入算，缓存代价是每轮 +27 输入 token（注入点在最新轮之前，此前的字节逐字不变，`cache_read` 照常命中）；已注入的文本不能撤回，撤回会挪位置、打破缓存。

该间隔结论来自 cline-pass（`reasoning_effort` 在那边是引擎侧参数）；官方 DeepSeek API 上注入与"提示词前端参数"的竞争关系不同，**未测距离**。

## 机制依据

- vLLM `vllm/tokenizers/deepseek_v41_encoding.py:179-190` 与 sglang `python/sglang/srt/entrypoints/openai/encoding_dsv41.py:63-74` 使用同一套模板与映射（`low=50 / high=75 / xhigh=75 / max=100`），且都只在 **index 0、thinking 模式**下渲染（`render_reasoning_effort` 的 `if index == 0 and thinking_mode == "thinking"`）。V4 另有一套 `preview` / `official` profile，`low` 是空字符串——档位在训练格式里就是提示词文本。
- 官方 API 与实测一致：切 thinking 时提示词 +25 token，改档位只换数字。
- **cline-pass 的 deepseek 通道不改提示词**：此前缓存实验中 `none/low/high/max` 互切时 `prompt_tokens` 与 `cache_read` 完全不变，但本次实测推理长度差异显著（minimal 441 vs max 966）。因此该通道的档位是**引擎侧参数**，与官方 API 的"提示词前端"不是同一条机制。
- **注入在紧邻轮的作用方式是普通文本语义，且随距离迅速消失**：模型读到 `Reasoning Effort: 100 … the more thorough the reasoning` 并据此调节推理长度；`1` 回到中性、`100` 拉高、`1000` 与 `100` 同档（饱和）。但它走的是模型对文本的服从，不是 API 的档位通道，而且只在紧邻轮成立（证据 F）。
- **不存在"中间插一条 system 消息"的通用效应**：证据 F 里 padding 在每个距离上都与基线不可区分（d=0 z=0.24；d=10 中位数 2704 vs 2609），零推理率全部 0/20。第一版"轮边界消息会阻止模型放弃推理"的说法是探针重复造成的假象，已撤回。

## 对 dsh-reasoning-effort 插件的含义

- **优先用请求参数，不要在提示词里许诺档位**：cline-pass 上 `reasoning_effort` 是提示词之外的真实通道，`minimal` 压低、`max` 抬高；注入文本的效果量与它不可比，而且只覆盖紧邻一轮。
- **注入形状**：一条 `role: "system"` 的消息，插在**最新真实用户轮之前**（轮边界）。内容用模板原文，`N` 取 1–100。这段文本不改变注入点之前的前缀。
- **注入的粒度就是"每一轮"**：效应在 d=1 已不可靠（p=0.39），d≥5 归零。所以不存在"每几轮补一次"的省法——**要在哪一轮起作用，就在那一轮注入**；不注入的轮回到基线水平。按每轮注入算，缓存代价是每轮 +27 输入 token（注入点在最新轮之前，之前的内容逐字节不变）。**不要撤回**已注入的文本：位置一变，缓存即失效。
- **只有明显高于前端的值才有效**：d=0 上 `inject-100` 显著，`inject-1` 与 `inject-50` 都与中性文本不可区分（把前端同一个值再念一遍等于没说）。要压低推理不要靠注入，用请求参数 `minimal`（中位数 441、sd 234，最稳的一档）。
- **缓存**：注入点在最新轮之前，此前前缀逐字节不变，实测 `cache_read` 照常命中；代价约 27 token。
- **路由**：走 cline-pass 必须 pin 到 `deepseek`，否则托管方漂移会淹没效果（同一档位差异可达数倍）。官方 API 无此问题。
- **触发策略**：注入应作为"这一步临时抬高"的手段，按轮开关；不要指望一次注入在后续轮次留下余温。
- **成本**：官方 flash 谷价下，走官方 API 的那部分（长上下文 200 次 + 短上下文 200 次）合计约 $0.2；cline-pass 的 175 + 340 + 420 次按其自身低费率另计。单次注入请求的成本增量只有 27 输入 token。

## 未决问题（实现前应补的验证）

1. **跨任务、跨前缀复现**：目前只有一个冻结前缀、一类任务（代码诊断规划步）。
2. **效应的精确距离**：d=0 稳、d=1 不可靠、d=3 名义命中但不单调。d=1 与 d=3 之间到底有没有一个稳定的小效应，需要更大 n（把 d≥1 合并后 p=0.066，方向仍偏正）。
3. **d=3 的命中是不是假阳性**：5 个距离独立检验，名义 p=0.033 不校正多重比较；要确认需要独立批次复现。
4. **低于前端的注入**：`inject-1` 与中性文本不可区分，说明注入只能往上推。`0`、负数、非数字（如 `max`）未测。
5. **合成历史的影响**：第 11–19 轮是手写冻结轮而非模型生成；换成真实自回归轨迹后效应距离是否变化未测。
6. **两条通道叠加的形状**：`max` + 注入是唯一把零推理压到 0/20 的组合，但样本量不足以判定叠加量。
7. **语义等价性**：换成中文或改写措辞是否等效——若等效，说明是纯语义施压而非训练格式回放。
8. **对结果质量的影响**：全部实验只测推理长度，未测答案正确率与任务成功率。

# 附录：工具结果「该摘要还是保留全文」闸门的实测

状态：**追加的旁证数据**，来自 `dsh-result-clipper` 的离线测量（与本文主体的 effort 注入无机制关联，只是同源会话数据 + 同一 route 上的独立测量）。**结论有实测支撑**：模型 + 上下文判不准（49% ≈ 抛硬币），同一批字段用程序按行为迹象判更准（61%、精确率 61%）。含真实会话文本的样本已删，判定与脚本留档。本附录同样只记录实测结论与机制依据，不含插件设计。

## 调研问题

1. 给摘要模型加「本步上下文」（本步意图头/尾、调用形态、本会话已产出的摘要）并改写规则正文，能不能让它准确地在 **keep（保留全文）** 与 **summarize（改写成短说明）** 之间选？
2. 同样的字段交给程序自己判，准确率如何？

## 结论

| 问题 | 结论 | 数字 |
| --- | --- | --- |
| 现行默认规则的触发条件（「用户明确要求逐字/逐行/完整查看」）在受保护案例里出现吗 | **不出现** | 人类会话里「摘要后又被读回原文」的 31 条案例中，最近一条与会话开头第一句用户消息命中数均为 **0/31**；按"每条用户消息"算是 82/492 = 16.67%（其中含 agent 写的委派简报，非用户原话） |
| 旧规则 + 最全上下文 | **等于「一律摘要」** | 60 条上 30/60、**0 条 keep**（与一律摘要逐条相同） |
| 新规则 + 最全上下文（150 条） | **不如「一律摘要」** | 73/150 = 49%（基线 75/150 = 50%），判 keep 精确率 **48%**，召回 33% |
| 把规则里三处歧义收紧（v1 → v2） | **无效** | 净 −1 条，McNemar p = 1.000 |
| 加大上下文（全字段 vs 只有意图头尾） | **无效** | 净 −1 条，p = 1.000；只是让模型多判 keep（52 条 → 29 条），精确率不动（48% vs 48%） |
| 程序规则「会话内有过摘要 且 本次非 bash」 | **最平衡** | 92/150 = **61%**，精确率 61%，命中真 keep 63% |
| 程序规则「同一 `file_path` 曾被摘过 且 本次整文件读」 | **几乎零误伤但极少触发** | 79/150 = 53%，精确率 **100%**，150 条里只触发 4 条 |
| 同会话内控制（剥掉会话级混淆） | **程序规则的优势仍在** | 11 个会话 / 107 条：会话内「一律摘要」基线 36%，程序规则 65%（精确率 75%），逐会话 **7 胜 / 2 负 / 2 平** |

一句话：**「这段内容要不要逐字保留」这个判断，用模型 + 上下文问不准（49%，低于一律摘要）；同样的字段用程序按行为迹象判更准（61%、精确率 61%），而且不花任何模型调用。** 原因见「机制依据」：模型被问的是语义问题，而标签衡量的是行为。

## 实验装置

- **数据**：`~/.dsh/sessions/<项目桶>/<session-id>/session.v4.jsonl.zstd`（zstd JSONL，与本仓其它探针同源）。
- **标签用真实行为，不用模型判断**：某条工具结果被插件摘要（替换后的正文含 `原结果入口：`）后 **≤2 次调用内** 又出现 `read` 命中该入口路径 → 记为 keep；从未读回 → 记为 summarize。可用池 111 keep / 125 summarize，取 **75 / 75** 平衡样本（150 条）。
- **判决输入＝生产会发出的那条完整提示词**：上下文块 + 规则正文 + 固定外壳 + 工具正文分隔；每份 **< 3,872 字符**——必须低于本插件 `minInlineTokens = 1024` 估算单位（估计器是 `text.length / 4`），否则判官读到的会是插件自己生成的摘要。
- **判官**：`cline-pass/cline-pass/deepseek-v4.1-flash`（与生产 route 同一模型），12 路盲判（3 臂 × 4 块，每块 36–38 条），覆盖 150/150、无重复 id；判官各自只读自己那一块的提示词文件。
- **统计**：与「一律摘要」基线做配对 McNemar 精确检验。

## 数据 1：判决时可见字段的在场率（150 条，keep/summarize 各 75）

| 字段 | keep 组 | summarize 组 | 差 |
| --- | --- | --- | --- |
| 同一 `file_path` 之前已经被摘过一次 | 12 | 5 | +9 条 |
| 本次是 `read` 整文件（无 offset/limit） | 36 | 24 | **+16pp** |

字段是有信号的，但都是 15pp 级的弱信号；模型没能把它们变成准确率（见数据 2）。

| --- | --- | --- | --- | --- | --- | --- |

显著性：E / D 对基线净 +17 / +14（McNemar p = 0.068 / 0.070）；对最好的 LLM 臂（T-C）净 +19 / +16（p = 0.048 / 0.097）。**代价模型**：命中时省下一次模型调用与一次输出，但被保留的正文**永久留在上下文**（本插件存在的意义正是避免这件事），所以错 keep 就是白留——E/D 的精确率 61–63% 意味着约 37–39% 的 keep 是白留的；B 几乎不白留但触发量极低。

## 机制依据

- **模型答的不是我们量的问题**：请求要模型回答语义问题（"这段内容对当前任务要不要逐字完整"），而标签衡量的是行为（"这条结果会不会被读回"）。给更多语义上下文只提高"判 keep 的倾向"（T-B 29 条 → T-C 52 条），精确率停在 48%。
- **可行的是"重复出现"这一行为**：同一路径之前摘过、现在又来取它的正文 → 上次那条摘要不够用；整文件读取 → 结果是"正本"，摘要掉之后要拿回来就得整份读回。这两条都由程序从字段直接读出。
- **现行规则不可触发是结构性的**：它要求模型证明"用户明确要求过逐字/逐行/完整查看"，而按设计（无 goal 时不发任何用户文本）请求里没有用户原话；实测该触发在受保护案例里 0/31。

## 局限与未决

1. **标签口径**：把"读回"等同于"本应保留全文"，可能把"后续任务恰好需要原文"混进来；离线无法证伪，需产品侧重新定义目标才能重测。
2. **会话级混淆已排除但不充分**：同会话配对只覆盖 11 个会话 / 107 条。
3. **判决输入被压缩**：正文只给了头 1,000 + 尾 300 字符（生产会给全文），长正文中段对判官不可见。
4. **样本量与判官形态**：n = 150（规则对基线的效应 p ≈ 0.01–0.09 视档而定）；判官是走同一 route 的独立 subagent，不是管线内的真实调用。
5. **执行偏差**：一轮里同一个结果文件被两路判官并发写入（一度出现重复 id），已用唯一路径重跑替换；另有一路判官事后读了设计稿（污染已登记）。
6. **未测**：keep 对上下文成本的实际影响、keep 与准入判断的交互、非 read/bash 工具、真实基率下的净收益。
