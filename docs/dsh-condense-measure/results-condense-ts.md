# 票 15：TS 实现的真语料验证（幂等 + 闸门口径与报数口径同号）

**一句话**：两条判据都在真实语料上过了——无损变换幂等**违反 0**，口径同号**反例 0**；而且 TS 实现与票 14 的已测量原型逐条等价，所以票 14 的那些读数可以搬到发布版。

- 判据 6（幂等）→ 零违反即结论。
- 判据 12（口径同号）→ **零反例即结案**。
- 等价性 → 1,006 条逐条一致，0 出入。

三个数、闸门与「触发数」的口径全部来自 `harness.py` 的 docstring；本报告不另立一套。

## 怎么重跑

```bash
# ① TS 侧：逐调用幂等断言 + 导出「会被替换」的调用（语料在的时候，实测 6.5 秒）
cd packages/dsh-result-clipper
DSH_CONDENSE_CORPUS=/tmp/dsh-condense PATH=/tmp/pm-shim:$PATH \
  pnpm vitest run tests/condense-corpus.spec.ts

# ② 原型侧：等价比对 + 口径同号（实测 19 秒）
cd ../..
python3 docs/dsh-condense-measure/condense_ts_verify.py \
  --out /tmp/dsh-condense --dump /tmp/dsh-condense-ts/ts-condense.jsonl
```

`tests/condense-corpus.spec.ts` **语料在场就一定跑**（`DSH_CONDENSE_CORPUS` 优先，其次本目录抽取脚本的默认输出路径 `/tmp/dsh-condense`；两处都没有才整文件 skip）。所以本机 `pnpm test` 会把这条实语料断言一起跑掉（22 文件 / 372 用例，6.8 秒）。

## 判据 6：无损变换幂等——违反 0

语料 `/tmp/dsh-condense`（769 MB、2,093 个会话目录、2,129 份日志）本次实测完整，不是重抽的。

| 口径 | 行数 |
|---|---:|
| 全部调用 / 其中有正文 | 177,551 / 177,546 |
| 目标工具（`bash` / `grep` / `pwsh`）/ 其中有正文 | 109,458 / 109,453 |
| 低于尺寸下限（128 估算单位） | 42,338 |
| 进闸门（≥128） | 67,115 |

- 四条规则各自 `f(f(x)) == f(x)`：在 109,453 行上**违反 0**。
- 整链 `chain(chain(x)) == chain(x)`：**违反 0**。
- `tail-cap` 的忠实性守卫放弃 151 行；整链放弃也是 151 行（放弃的链没有第二遍可比，单独计数，不算违反）。

每条规则单独作用在原始正文上的改动数：`strip-ansi` 132、`strip-cr` 228、`dedup-adjacent` 166、`tail-cap` 1,014；整链改动过 1,510 行。

`condenseText` 的四个判定：`condensed` **1,006**、`unchanged` 107,884（含 42,338 行低于下限）、`abstained` 151、`not-shorter` 412（合计 109,453）。

## 等价性：TS 实现 == 票 14 已测量原型

把 TS 导出的 1,006 条「会被替换」的调用逐条重跑 `transforms_general.py` 的原型链，比 sha256（精简后正文）、长度（UTF-16 码元，与 TS 的 `chars` 同口径）、命中规则、`lossy`：

| 比对项 | 不一致条数 |
|---|---:|
| `sha256` | 0 |
| 长度（UTF-16 码元） | 0 |
| 命中规则（去掉 `13-`…`16-` 前缀后同名） | 0 |
| `lossy` | 0 |
| 原型会替换、TS 没导出 | 148（**全部**由票 15 新增的守卫解释，未解释 **0**） |
| TS 导出、原型闸门却不替换 | **0** |

**结论：等价成立，票 14 的读数（尾部偏置封顶触发 2,714 次 / 触发口径 49.4% 等）可以搬到发布版。**

那 148 行不是不一致：票 15 给封顶加了一条原型没有的守卫——正文末尾**已经有一条上游位置说明**（spill / `grep` / `glob` 写的）时放弃整层（判据 5「至多一个可下钻入口」）。脚本用与 `condense.ts` 同一个判据逐条归因，148 条全部命中，方向也对（TS `abstained` 151 行里，148 行本来能过原型闸门）。

## 判据 12：口径同号——反例 0，零反例即结案

口径：对每条被替换的调用，用 `o200k_base` 算 `len(encode_ordinary(原文))` 与 `len(encode_ordinary(精简后正文 + 入口预留))`，断言前者严格更大。入口预留取 `src/entry.ts` 的 `ENTRY_RESERVE = 256` 字符（脚本从源码正则读回，不写第二份常数），**只对有损替换计**——无损替换不写入口。

| 读数 | 值 |
|---|---:|
| 被替换调用 | 1,006 |
| **反例** | **0** |
| 最小省幅 | 0.085%（1 token，`call_00_ET_fYHGnqlbDjhL42Bte3A56977`） |
| `triggered` 口径省幅 | **46.0%**（Σbefore 5,990,000 → Σafter 3,231,657） |
| `all` 口径省幅 | **4.43%**（分母 = 进闸门的 67,115 行，Σbefore 62,318,083） |
| 敏感性：预留换成 harness 的约 30 字符说明 | 46.2% |

三条要一起读的话：

1. **零反例即结案**。「估算单位减少 ⟹ 真 token 减少」在本语料上**没有例外**，所以不需要运行期守卫。最薄的边际是 1 token（省幅 0.085%），也仍然严格为正。
2. **预留按 256 字符上界算，比真实入口说明更贵**（真实说明约 30 字符），所以这个读数是**保守**的：真写入口后省幅只会更大。
3. 46.0% 与票 14 的 49.4% **不是同一件事**，别对号：49.4% 是封顶单条、全工具口径、按约 30 字符说明计价（2,714 次触发）；46.0% 是整链、只算目标工具、且按 256 字符预留计价。

## 生产闸门 vs harness 触发集（行口径）

| 口径 | 行数 |
|---|---:|
| 生产形态（原型 + 生产闸门） | 1,154 |
| harness 口径（`triggered_caliber` 的 `chain` 读法） | 1,192 |
| harness 有、生产没有 | **71** |
| 生产有、harness 没有 | **33** |

- **harness 独有 71 行 = 256 字符预留造成的**：`256 > 约 30 字符` 的占位说明，生产闸门更严。**在「有损替换」这一子集上，生产是 harness 的子集。**
- **生产独有 33 行不是预留造成的**：harness 的 `chain` 读法对**任何**改动都按「+ 回退说明」计价，于是只做无损改动（剥 ANSI / 去 `\r` / 去重）的那些更难过闸门；生产对无损替换不计入口开销，所以它们在生产侧能过。
- 合起来：**两个方向都非空，生产闸门既不是 harness 的子集也不是超集**。票面上「生产触发集是 harness 子集」的说法只在有损替换上成立。
- TS 实际导出 1,006 行 = 生产形态 1,154 − 148（位置说明守卫）。

## 语料本身的一个性质：同一 `callId` 会重复

语料是按**会话快照**抽的：进闸门的 67,115 行只有 33,595 个不同的 `callId`，同一个调用最多重复 **39** 次（多个会话目录各自保存了同一段历史）。这不是缺陷，但意味着「177,551 次调用」实际是「快照里的出现次数」。

**本报告一律用行口径**，与票 14 的读数同口径；`condense_ts_verify.py` 的触发集差异也是行口径。TS 导出的 1,006 行对应 819 个不同 `callId`，原因相同。

## 这次没验证到的部分

- **只跑了纯函数，没跑接线**：`condenseText` / `generalRules` 的行为在语料上钉死了，但 `tools/post-execute` 里的挂接、dryRun 只预报、台账写入这些属于票 15 的其余判据，不在本报告范围。
- **没有测真实写入的回退入口长度**：口径同号用的是 256 字符**预留上界**，不是 `saveText` 返回的真实入口文本。这是生产自己的口径（`condense.ts` 的注释明写用上界），但「真写盘后省幅多少」本次没测。
- **「异常归放弃」这条路径没被触发**：本次语料上四条规则一次都没抛，也没有非 `undefined` 的守卫放弃之外的异常，所以 §4.1 #8 的兜底在这次扫描里没有实证。
- **不是全量线上分布**：只有本机 `~/.dsh/sessions` 的一次快照。「零反例」是对这份快照成立，不是对任意工具输出成立。
- **没有证明数学恒成立**：反例是理论上可构造的（删除可能拆开一个 BPE 合并），本次只是在本语料上没找到。
- **没有测配置字段生效与设置页**（票 19 的范围）。

## 依赖的假设

1. **语料是 `/tmp` 的一次性快照**：769 MB、2,093 个会话目录、177,551 行，随时可能消失，所有读数都绑定这份快照。丢了就用 `docs/dsh-condense-measure/extract_calls.py` 重抽（只读 `~/.dsh/sessions/**`）。
2. **两把尺子**：`o200k_base` 是**报数口径**，闸门用的是插件自己的估算单位（`ceil(字符数/4) + 4`，计划 §4.1 表后「两把尺子必须是一把」）。判据 12 验的正是这两者**同号**，不是相等。
3. **入口预留 256 字符、只对有损替换计**：对齐 `condense.ts` 的闸门口径。比对时用 256 个 `x` 当预留的 token 代理——它比真实说明更贵，方向偏保守。
4. **`chars` 是 UTF-16 码元**：TS 的 `String.length` 与 Python 的 `len()` 码点口径不同，含 emoji 的正文两者不等；脚本按 UTF-16 比对，sha256 不受影响。
5. **原型没有位置说明守卫**：`transforms_general.py` 是票 14 的产物，不代表票 15 新增的守卫；差异全部按这条归因，且 148/148 逐条核过。
