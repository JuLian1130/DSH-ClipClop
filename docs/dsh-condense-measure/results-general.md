# 通用形状变换（计划 §4.3 的 13–16）：实测读数

语料：`/tmp/dsh-condense`（2,093 会话目录 / **177,551 次调用**，其中**有正文 177,546**、
低于尺寸下限 128 估算单位被 harness 跳过的 **83,237**，真正进闸门的 **94,309**）。
三个数的口径完全由 `harness.py` 决定（见其 docstring），本文只记录它算出来的值；
`--triggered` 那一列是本模块补算的，原因见文末「接口缺口」。

## 复现命令

```
# 四条各自 + 整链的三个数（五个进程可并行，各约 30 秒）
python3 docs/dsh-condense-measure/transforms_general.py --run all

# 零命中排查（不过闸门，含被尺寸下限跳过的调用）+ 幂等断言，约 11 秒
python3 docs/dsh-condense-measure/transforms_general.py --scan

# 触发口径省幅（harness 的 saving_triggered 与 saving_all 恒等，读不出这一条），约 17 秒
python3 docs/dsh-condense-measure/transforms_general.py --triggered
```

本机（10 核，2026-10-16）实测耗时：`--scan` 11.2 s、`--triggered` 16.7 s、
`--run all` 串行 151.7 s（拆成五个进程并行则各 29.6–32.9 s）。

## 零命中：**四条全部命中过，零条零命中**——但「命中」和「省幅为零」必须分开看

`--run` 的 `targeted` 已经滤掉了尺寸下限，单看它答不了"一次都没命中"。`--scan` 不过闸门、
覆盖全部 177,546 次有正文的调用：

| --- | ---: | ---: | ---: |
| 13 `strip-ansi` | 132 | 30 | 102 |
| 14 `strip-cr` | 237 | 33 | 204 |
| 15 `dedup-adjacent` | 192 | 33 | 159 |
| 16 `tail-cap` | 2,930 | 0 | 2,930 |
| 整链 13→16 | 3,438 | — | 3,342 |

- **没命中（文本一个字节都没变）：0 条。** 四条在本语料上都命中过。
- **命中了但省幅为零**：13、14、15 三条。13 最有代表性——改动过 132 次，但 102 次过下限的
  命中里 95 次被净收益闸门（<24 估算单位）挡下，最后只触发 **7 次**、省 5,037 token，
  占语料 **0.004%**。也就是说 **ANSI 转义序列在工具结果里基本已被上游剥净**，
  这条在本语料上接近死代码；14（57 次）与 15（109 次）同量级，触发率都在万分之几。
- 只有 16 有决策分量：触发 **2,714** 次，整层省幅 **9.1%**。

## 幂等断言

`--scan` 对 **177,546 次调用逐条**断言 `f(f(x)) == f(x)`，四条变换与整链全部成立，
**违反 0 处**；断言写在代码里（`assert not mismatches`），违反即非零退出。
构造上的保证：① 正则最后一条兜底 `\x1b` 保证第一遍后正文再无 ESC；
② 第一遍把 CRLF 与 `\r` 全部消掉；③ 输出里不会有连续 3 行相同（最多 2 行）；
④ 单行截断把标记算进 2000 字符预算、行封顶后最多 251 行，第二遍不再触发。
验收只要求无损的三条，`④` 顺带也成立。

## ④ 的有损账本

| 口径 | 发生封顶的调用 | 丢掉的行数 | 单行截断数 |
| --- | ---: | ---: | ---: |
| 16 单条（过下限调用） | 2,930 | 597,194 | **910** |
| 整链（过下限调用） | 2,926 | 596,804 | **910** |
| 整链（全部调用） | 2,926 | 596,804 | 910 |

2,930 = 触发 2,714 + 被闸门挡下 216。丢掉的行数是**行封顶**丢的（每次调用 >300 行时
保留头 50 + 尾 200）；单行截断 910 次是**另一回事**——超 2000 字符的单行被截到 2000
（标记计入预算），与行封顶各自计数、不要相加成一个数。
整链比单条少丢 390 行：①②③ 先消掉了部分行/CR。

## 接口缺口（没有改 `harness.py`，都用本模块的最小变通）

1. **`saving_triggered` 与 `saving_all` 恒等。** `_run` 在未触发/被挡下/放弃的分支里把
   `before` 记进 `tokens_after`，于是 `tokens_saved_triggered + tokens_after == tokens_before`
   恒成立，两个比值永远相同（五份报告逐位相同，实测）。docstring 承诺的"两个口径"
   目前只有一个；§4.4 要的 ≥60% 因此读不出来。变通：`--triggered` 用同一套闸门重走一遍
   并核对触发数（见上表）。
2. **`④` 的丢弃行数/单行截断数无法从 harness 读出。** `Report` 只有 token 与计数聚合，
   没有"有损变换丢了多少行"。变通：`tail_cap` 接受一个可选的 `CapStats` 记账对象，
   `Transform` 用闭包持有它，harness 看不见、也不受影响。
3. **"零命中"读不出。** `targeted` 是过下限之后的数，`unchanged` 只统计过下限的调用；
   一条变换可能命中很多次却因尺寸下限一次都进不了闸门。变通：`--scan` 独立遍历。
