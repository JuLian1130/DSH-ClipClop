# dsh-system-one-channel

决策通道：需要判断、选择或评分时，把题面交给一个决策模型，拿回**带概率的答案**，而不是让主模型自己拿主意。这一层只决定、不产出内容，也不替你决定答案怎么用。

它是 `dsh-system-one` 这个 bundle 的第二行，接在接入层的注册表上：用哪个决策模型由本行的配置指名，接入层因此没有「当前 provider」这类全局状态。

## 它提供什么

- **一个工具** `systemone_ask`：参数是 `state`（判断所依据的一切）与 `questions`（一张题单，每题自带 id、题型与说明）。答案按题 id 交回。
- **一个技能** `systemone`：讲什么时候该用、什么时候是类别错误、答案怎么读。随包交付，登记进技能注册表。
- **两档引导**，默认第一档：第一档 = 工具描述 + 技能；第二档 = 第一档 + 一句常驻引导。
- **总开关**，默认开启、在设置页上：没选决策模型或关掉时，工具、它的引导段与技能都不注册；关掉时下面三组设置收起。
- **可选的可信度门槛**，默认不设：开启后每道题多一个 `act`／`abstain` 标记。

## 什么时候用它

- 一个是非判断决定下一步做什么，而「大概是」不够：这段改动能不能直接用、这次失败是不是这次改动引起的、这个请求在不在范围内。
- 答案必须落在几个固定选项里，凭感觉挑会走错分支。
- 要在一个有序量表上打分（严重程度、把握、优先级），要的是数而不是形容词。

**不该用**：让决策模型写正文、写代码、做调研（它只交回类型化答案）；问题没有封闭答案（「下一步该做什么」）；答案要对人拿出处（决策模型只看得到 `state`，看不到这段对话）；想让通道替你动手（它从不改文件、不跑命令）。

## 配置

```yaml
- insert:
    - id: dsh-system-one-channel
      name: '@dsh-clipclop/dsh-system-one-channel'
      config:
        enabled: true
        target: sglang_local      # 接入层那一行里某个条目的 id
        guidance: tool            # tool | context
        threshold: { enabled: false, value: 0.5 }
```

| 字段 | 默认 | 作用 |
| --- | --- | --- |
| `enabled` | `true` | 总开关，设置页上也有同一个开关。默认开启；没选条目时什么也不注册，关掉后工具、引导段与技能都不注册。**改完即生效**，不用重载插件。 |
| `target` | 空 | 用哪个条目（接入层条目页里展开条目后显示的那行 id）。开关打开时必须给，否则加载期报错。 |
| `guidance` | `tool` | 引导档位：`tool` 只用工具描述与技能；`context` 再加一句常驻引导。 |
| `threshold` | `{ enabled: false, value: 0.5 }` | 可信度门槛。`value` 取 0–1，越界在加载期报错。 |

四项**改完即生效**：`enabled` 换掉的是注册哪一批（工具、引导段、技能），另外三项按每次调用／每次组装现读。都不需要重载插件。

单独装载用本包的 `cordis.patch.yml`；接进接入层的 bundle 时同一行由 bundle 那份 patch 提供（见票 07），两者只取其一——同一行装两次会在同名工具上撞车。

## 设置页

设置 → 插件里的「决策通道」页签管四件事，改完马上生效，不用点保存、也不用重载插件：

| 控件 | 作用 |
| --- | --- |
| 总开关 | 默认勾选。打开后主模型才能把判断、选择或评分交给决策模型；关掉时这一层整个不出现，下面三组设置也收起来（存下的值不丢）。要先到「决策模型」那一页登记一条、并在这里选中它，才会真的有工具可用。 |
| 当前应用的决策模型 | 用哪个条目，选项来自接入层那一行的条目。**只对决策通道这一层有效**，不是全局开关：别的插件各自指名自己的决策模型，不受这里影响。 |
| 引导 | 第一档「按需」只用工具描述与技能；第二档「更主动」再加一句常驻提醒。默认第一档。 |
| 可信度门槛 | 勾选「开启」后才出现数值框，填一个 0–1 的数。低于门槛的题标成「拿不准」，答案与概率照样交回。各个决策模型自报可信度的算法不同，**同一个数值在它们之间松紧不同**，换一个模型可能要重新调。 |

条目本身在「决策模型」那一页增删改（接入层的页面），本页只管选。装上插件、还没选条目时开关虽然勾着，但什么也不注册——选中一条之后工具才出现；换条目或删掉条目都按下一次请求现读。

## 工具返回

`answers` 按题 id 组织；**某题没答就不在这里出现**（不要把它当成「否」）。`warnings`、`usage`、`requests`、`modelId` 是决策模型那边自报的项，原样交回。

阈值开着时多一层 `decisions`：每道题 `{ verdict: 'act' | 'abstain', reason? }`。`abstain` 表示**低于你设的可信度门槛**，不是答案错了——答案与概率仍然原样交回。阈值关着时这一层不出现，`answers` 本体两种情况都一样。

## 阈值语义

- 是非题的确定性 = `|probability − 0.5| × 2 × labelMass`（离 0.5 越远越确定；`labelMass` 是答案标签的可见质量，缺席按 1——`deepseek` 报的是 top-20 可见部分的下界，低覆盖时确定性随之下降）。
- 单选题与量表题的确定性 = 决策模型自报的 `confidence`。
- 低于阈值标 `abstain` 并写明原因；**算不出确定性时同样标 `abstain`**（该题没答、或没报 `confidence`）——「判不出来」不等于「放行」。
- **阈值不可跨 provider 比较**：`confidence` 的定义由各家自己给（有的是全词表上的概率，有的是归一化后的集中程度），同一个数值在不同条目上松紧不同。换条目要重新调阈值。
- 阈值只进配置、不进工具参数：模型能自己放宽的闸门不是闸门。

## 实测状态

- **端到端未测**：本包的验收是进程内的假 provider 加真实的工具、提示与技能接缝，没有对真实决策端点跑过一次完整链路。真实端点（vllm／SGLang／OpenAI Decisions）的行为由接入层的 provider 覆盖，端到端列为「有端点才做」。
- **多行 bundle 装载**：真实 profile 里的两行装载与按 id 禁用由票 07 复验，不在本包内。
- 技能子系统是**可选依赖**：profile 没组合它时本插件照常加载、工具照常可用，只是少一个技能。
