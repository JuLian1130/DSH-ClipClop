# dsh-result-clipper

> 设计中，尚未发布。

`dsh-result-clipper` 用一个可配置的摘要模型，把适合继续工作的工具结果改成较短的摘要，并保留取得原结果的入口。它还提供一个可选的本地隐私闸门，在工具结果进入主模型或其他外部处理前判断是否涉及用户定义的隐私或机密。

摘要和隐私闸门默认关闭。隐私闸门是尽力而为的保护机制，不是隐私或机密未泄露的保证。

## 适用范围

两种模式都只介入本来会进入模型的工具结果内容；只写入会话日志、不进入模型的内容不在处理范围内。

首版目标工具是 `bash`、`web_fetch` 和 `read`。摘要只替换工具结果的 `content`；DSH 的 `additionalContexts` 原样保留。`read` 读取摘要保存的原结果入口时只跳过再次摘要，仍经过隐私判断。含图片等非文本块的结果原样透传，不参与摘要与替换。

隐私模式检查所有标准工具结果的正文和附加上下文，不以结果长度为跳过条件，并且只处理外层最终结果。PTC 程序内部的子调用属于中途过程，插件跳过它们——改写子调用会让沙箱程序抛错或改写持久日志副本；PTC 唯一进入模型的内容是外层 `run_code` 结果，它同样经过隐私判断，子调用递延到外层的图片与附加上下文也包含在内。

隐私判断只针对文本：图片块不会送进分类器，含图片的结果按其文本判定，图片内容不参与隐私判断。

保护面边界：`final-result` 旁路（prepare、pre-execute、守卫失败）产生的错误结果会进入模型，但本插件收不到，其中的工具参数不会被判断；PTC 中途子调用的正文仍会作为会话日志事件记录并可能被上传，本插件不介入（它不进入模型）；普通 `tool/result` 的会话日志继承已经替换过的投影。

它不保护用户消息、助手生成的工具参数、工具已经发生的网络副作用，也不保证能识别所有隐私或机密。

## 安装

本包目前未发布到 npm registry。实现完成后，预期使用与本仓其他插件相同的本地 profile 安装流程：先构建插件产物，再将预构建目录或 tarball 加入目标 profile，最后重载或重启 DSH。

```bash
dsh plugin --profile <name> add /absolute/path/to/packages/dsh-result-clipper
```

Desktop profile 由 Electron 管理时，应在该 profile 目录中使用其安装方式。安装前确认 DSH 满足仓库规定的版本下限 `>= 0.2.0-rc.2`；更高版本按兼容处理。

## 配置

配置入口计划放在“设置 → 内置插件 → dsh-result-clipper”。开关放在插件页签；参数放在插件自己的详情卡片中。修改后按 profile 的重载规则生效。页面会静态提示：摘要会把工具正文发送给所选 route。

需要特别注意：

- **摘要模型 route** 同时用于摘要和隐私判断。
- **摘要准入判断器 route** 可以单独配置；留空时跟随摘要模型 route。准入判断器不读取工具正文，只判断是否值得发起摘要请求。
- 启用隐私模式时，页面要求用户明确确认摘要模型 route 是本地 route。插件无法从 `baseURL` 自动证明这一点；未确认时按隐私失败策略处理并显示警告。
- `minInlineTokens` 默认 `1024`，`maxSummarizeTokens` 默认 `12500`，单位是 DSH 的估算器单位（4 字符/token）。两者都只决定本插件处理哪些结果：低于下限的不摘要，超过上限的交给现有 spill 机制。上界是本插件自己的字段，不读取 spill 的配置。
- 摘要和隐私模式均默认关闭。
- 隐私失败策略是全局设置：`sensitive` 始终拒绝；`uncertain`、超时、解析失败和 route 配置失败默认 `passthrough`（放行），也可以配成 `block`（拒绝）。默认放行意味着失效必须可见：设置页卡片常驻警告，运行期每次会话追加一条不含正文的插件消息。
- 摘要提示词、隐私提示词和准入判断提示词只能编辑规则正文与 few-shot 示例。安全外壳和结构化输出 schema 固定，工具结果会被明确标记为不可信数据。恢复默认通过清除用户覆盖实现。
- 准入判断、摘要和隐私三类请求各自有一个“关闭推理”开关，默认都关闭推理。
- 辅助请求超时、相关摘要条数、附加上下文上限和摘要输出上限由程序固定，页面只读展示。

## 摘要准入判断器

默认关闭。开启后，命中长度范围的结果先经过一次不带工具正文的 `yes/no` 判断：

- `yes`：再发起带正文的摘要请求；摘要无效时原文透传。
- `no`：原文透传。
- 判断失败或返回非严格 `yes/no`：直接发起带正文的摘要请求。

隐私模式开启时跳过准入判断，直接发起一次同时返回隐私结论和摘要字段的请求。准入与摘要之间的前缀缓存只是性能优化，未命中不会改变行为。

## 原文入口与保留

摘要替换正文前，插件把完整原文交给 DSH 的 spill 存储，并把返回的位置与取回说明写进摘要正文，模型可以据此重新读取全文。

原文的保留与清理由 DSH 的 spill 后端负责，插件不额外管理：本机后端的默认行为是按 `cleanupPeriodDays`（默认 30 天）在进程启动时清理一次。插件不设条数上限，也不承诺比 DSH 更短的保留期；需要清得更勤时应调整 DSH 侧的 spill 配置。存储后端不可用或写入失败时，该结果原样透传、不摘要。

## Debug 日志与干跑

debug 默认关闭。开启后必须填写日志路径；插件自动创建父目录，并以追加方式向该路径写入 metadata JSONL，例如工具名、结果大小、准入结论、摘要是否生效、调用耗时、缓存观测和判断器输入 token 数。不会自动改用临时目录，也不会覆盖已有文件。

干跑走完整条流水线，但绝不替换任何内容、也不写会话事件，只在 debug 日志里记录“本应发生什么”；它要求 debug 日志路径已配置。

debug 日志不记录工具原文、摘要正文、完整提示词、API key 或其他凭据。请为日志文件选择当前 profile 可写且访问受控的位置，并在共享机器上关闭 debug。

## 使用注意事项

- 摘要模型的判断是任务相关的概率判断。它可能选择透传，也可能摘要不足；原结果入口用于需要细节时重新取得全文。
- `additionalContexts` 不会被摘要；正文摘要与附加消息可能同时存在，后者仍按 DSH 原有顺序进入后续请求。
- 摘要模型请求失败时，摘要模式保留原文；隐私模式按配置的失败策略处理，默认放行。
- 只有本地 route 才适合启用隐私模式。route 的本地性由用户确认，插件不会替用户验证网络边界。
- 关闭摘要准入判断器后，流程恢复为直接把完整结果交给摘要请求；关闭摘要插件后，工具结果保持 DSH 原有行为。
- 首版不对 `read` 的重复读取做去重或复用：即使同一路径此前读过，也会重新读取、重新判断。
