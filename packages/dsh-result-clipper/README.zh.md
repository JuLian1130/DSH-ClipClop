# dsh-result-clipper

> 设计中，尚未发布。

`dsh-result-clipper` 用一个可配置的摘要模型，把适合继续工作的工具结果改成较短的摘要，并保留取得原结果的入口。它还提供一个可选的本地隐私闸门，在工具结果进入主模型或其他外部处理前判断是否涉及用户定义的隐私或机密。

摘要和隐私闸门默认关闭。隐私闸门是尽力而为的保护机制，不是隐私或机密未泄露的保证。

> **核心逻辑在 [`docs/dsh-result-clipper-pipeline.md`](docs/dsh-result-clipper-pipeline.md)**：一次工具结果什么时候发模型请求、什么时候被改写、什么时候原样透传的完整判据（与 debug 记录里的每个取值一一对应）。本 README 讲用法与取舍，那份文件是行为的权威描述。

## 五种收场（速查）

| 收场 | 什么时候 | 模型请求 | 记录里的取值 |
| --- | --- | --- | --- |
| **不走模型，透传原文** | 摘要总开关关；没声明 `extract` 且规则摘要关；没进候选（非目标工具 / 含图片 / 低于下限 / 达到上限）；`read` 按入口读回 | 0 | `summary-off` / `rule-summary-off` / `not-candidate` / `read-back` |
| **走了模型，没产出摘要，透传原文** | 摘要模型返回「保留全文」（不带 `extract` 时契约里才提供它）；隐私判 `uncertain`；请求失败 / 非法输出 / 窗口不足 | 1 | `kept` / `uncertain` / `failed` / `failed-window` |
| **产出了摘要，仍透传原文** | 摘要（含入口说明）不比原文短；存不进去（没有 spill 后端 / 写入失败 / 没有会话归属） | 1 | `not-shorter` / `failed` |
| **产出了摘要，替换正文** | 隐私判 `safe` + `summarize`（两个摘要开关都管不到它）；声明了 `extract` 且模型给了短说明；没声明 `extract`、规则摘要开、模型给了短说明 | 1 | `summarized` |
| **不走模型，直接返回摘要** | memo 命中（摘要提示词路、没声明 `extract`、隐私关闭、同一工具同一正文本会话摘过） | 0 | `summarized` |

四点补充：① 第一行的四种情况都要求**隐私闸门没对这一条生效**——隐私路上「没进候选 / 按入口读回」发生在判定之后，那时已经有 1 次请求；② `failed` 也可能零请求（摘要 route 没配出来）；③ 隐私判 `sensitive`（或 `block` 策略下的失效）**不是透传**：交回固定拒绝文案，记 `rejected`；④ **出厂默认只摘要主模型主动请求的那些结果**（「自动摘要大内容」默认不勾），所以默认部署下第二行与第三行基本不出现、第四行只来自主动请求。隐私开着时 `web_fetch` 默认不进隐私路，照常走摘要提示词路。

## 适用范围

两种模式都只介入本来会进入模型的工具结果内容；只写入会话日志、不进入模型的内容不在处理范围内。

目标工具是 `bash`、`web_fetch` 和 `read`，Windows 上还认 shell 的另一个注册名 `pwsh`（base bundle 在 Windows 上禁用 `tool-bash`、改挂 `tool-pwsh`；它只走 agent 作用域遮蔽，见下）。摘要只替换工具结果的 `content`；DSH 的 `additionalContexts` 原样保留。`read` 读取摘要保存的原结果入口时只跳过再次摘要，仍经过隐私判断。含图片等非文本块的结果原样透传，不参与摘要与替换。

隐私模式检查所有标准工具结果的正文和附加上下文，不以结果长度为跳过条件，并且**判断的是模型即将看到的内容**：插件位于 spill 外层，先让 spill 完成截断，再判断剩下的正文与附加上下文。因此判断结果贴合模型可见面，不会因为原文里一段模型根本看不到的内容而误拦。PTC 程序内部的子调用属于中途过程，插件跳过它们——改写子调用会让沙箱程序抛错或改写持久日志副本；PTC 唯一进入模型的内容是外层 `run_code` 结果，它同样经过隐私判断，子调用递延到外层的图片与附加上下文也包含在内。

隐私判断只针对文本：图片块不会送进分类器，含图片的结果按其文本判定，图片内容不参与隐私判断。

隐私模式不设长度门槛，因此**每个标准工具结果**都会加一次本地模型往返（不只是被摘要的三个工具），只有 `web_fetch` 默认例外（见「配置项」里的 `webFetchPrivacyGate`）。超时固定 20 秒；默认放行时，超时等于这次判断没做成、内容照常进入模型，只有会话提醒会告诉你。慢的部署应换更快的本地模型。

超长结果的原文可能已被 spill 写入本地存储（文件私有、按会话分组、随 spill 保留期清理）。判为敏感时插件不会提供它，但**无法撤回已落盘的副本**——spill 存储没有删除接口。

保护面边界：`final-result` 旁路（prepare、pre-execute、守卫失败）产生的错误结果会进入模型，但本插件收不到，其中的工具参数不会被判断；PTC 中途子调用的正文仍会作为会话日志事件记录并可能被上传，本插件不介入（它不进入模型）；普通 `tool/result` 的会话日志继承已经替换过的投影。

它不保护用户消息、助手生成的工具参数、工具已经发生的网络副作用，也不保证能识别所有隐私或机密。

## 安装

本包目前未发布到 npm registry。实现完成后，预期使用与本仓其他插件相同的本地 profile 安装流程：先构建插件产物，再将预构建目录或 tarball 加入目标 profile，最后重载或重启 DSH。

```bash
dsh plugin --profile <name> add /absolute/path/to/packages/dsh-result-clipper
```

Desktop profile 由 Electron 管理时，应在该 profile 目录中使用其安装方式。安装前确认 DSH 满足仓库规定的版本下限 `>= 0.2.0-rc.2`；更高版本按兼容处理。

## 配置

配置入口只有一处：侧边栏“插件”页里该包卡片详情页的配置区（`plugins.bundle.config`，键是包名）。“设置 → 内置插件”里的“工具结果裁剪”页签**只做指路**——一句话告诉你设置在哪、为什么不在那一页，没有任何开关：插件自己的开关就是“设置某项能力”本身，离开它们要用的 route 或日志路径按不动，所以开关与它们要用的设置放在同一页（摘要、隐私闸门、debug 与干跑都不再单独占一个入口，页签留着只是为了让你找得到）。每个角色的 route、推理档位、提示词与它自己的阈值同属一个分组，组间用一条横线隔开；每组底部是一对“保存 / 恢复默认”。**摘要开关在配置区顶端、「摘要模型」之上**：不勾时「摘要模型」与「摘要准入判断模型」两组连同各自的保存 / 恢复默认一起消失——工具保持原生形态、摘要提示词这条路不覆盖也不发请求（**隐私闸门不受它影响**：隐私开着时每个结果照旧判一次，判安全就用那一次请求给出的摘要替换正文，见「什么时候会透传原文」）。**隐私闸门的开关就在「隐私闸门模型」之上**（与摘要开关同一个键、页签时代就是它）：不勾时这一组整组不显示。**摘要准入判断的启用位在准入组之上、单独一行、保存即生效**：不勾时它下面那一整组（含该组的保存 / 恢复默认）不显示，勾上才展开，而它自己的改动当场写回——否则取消勾选会把承载「保存」按钮的那一组一起收起，改动就再也存不下去。它只在摘要开着时才显示。**「自动摘要大内容」是摘要组里的第一个勾选（默认不勾）**，改动随该组「保存」写回；不勾时它用不到的「摘要提示词规则正文」只读并显示为灰色。**debug 记录与干跑是「诊断」组里的两个勾选**，与同组的日志路径一起点该组「保存」写回；干跑要求 debug 开着且路径非空，两者缺一就在那一组里当场提示。从属关系用缩排表示（每级 32px）：摘要组与隐私组各比自己的开关退一级，准入的启用位与摘要组同层、它下面那一组再退一级。

写入方式分两种：三个能力开关（摘要、隐私闸门、准入启用位）保存即生效；配置区里的其余控件是**分组草稿**——只改本组草稿，点该组的“保存”才把该组全部改动**一次原子写入**，任一条被拒就整组不生效并显示失败，草稿保留可以改完重试。“恢复默认”按字段分两种语义：推理档位、摘要下限、摘要上限与三份提示词规则正文回到**内置默认**（提示词回到内置正文，保存时以清空覆盖的方式落盘）；provider、model、隐私确认位、失败策略、debug、干跑与 debug 路径回到**上一次保存的值**（丢掉未保存的改动）。配置区顶部静态提示：摘要与隐私分别把工具正文发送给各自所选 route，以及模型端点与 API key 在“设置 → 模型 → 自定义提供方”里按 route 配置。

需要特别注意：

- **三个角色各有自己的 route**：摘要、摘要准入判断、隐私闸门可以各选一条，也可以都填同一对 provider/model。准入与隐私的 route 留空时跟随摘要 route。provider 与 model 是下拉框，候选就是“设置 → 模型”里已配好的 route 与它们的模型；下拉第一项是**置空项**（摘要组“不设置（清空）”，准入与隐私组“跟随摘要模型（清空）”），选中并保存后该字段回空串——摘要组清空 route 就等于不摘要（请求不发、结果原样透传），准入与隐私清空即跟随摘要模型。**换 provider 时 model 跟着走**：改 provider（或把 provider 清空）时，当前 model 不在新 provider 的候选里就自动清空，不会留下别的 provider 的 model；只有目录读不到、拿不到候选时才不猜，手填的值原样保留。**隐私组的“已确认为本地”是对具体 route 的声明**：改了这一组的 provider 或 model，确认位就作废、要重新勾选——否则换一条没确认过的 route 会沿用旧确认继续放行。目录里没列出的 id 用每行旁边的“自定义…”切到手填（DSH 的路由接受未列出的 model）。插件的请求只带 `provider` 与 `model`——**baseURL、协议与 API key 归 route 自己持有**，在“设置 → 模型”里配置（自建/本地模型就建一条自定义提供方并在那里填 `baseURL` 与凭据）；插件不保存、也读不到这些值，因此也不通过 `baseURL` 猜测某条 route 是不是本地。
- **摘要准入判断开关**默认关闭，是配置区里准入组**之上**的一个勾选、保存即生效：勾上才展开这一组的 route、档位与提示词并启用它。启用后，命中长度范围的结果先经过一次不带正文的 `yes/no` 判断。准入判断器不读取工具正文，只判断是否值得发起摘要请求；它也可以留空不设 route（跟随摘要模型），作用是省下不值得摘要的结果的 token 费用。
- **「自动摘要大内容」开关**默认**不勾**：这时只有主模型主动请求摘要（在工具调用里声明要拿回什么）的结果会被摘要，其余候选结果原样透传，诊断记录里记 `rule-summary-off`——它是"本该摘要却没摘"的那批的计数。勾上后才对没主动请求的候选结果也按摘要提示词试一次（该开关是量出这份规则正文有没有必要的对照项）。它只管摘要提示词这条路：主动请求的那条路径不受影响，**隐私闸门也不受影响**（它不读摘要提示词，判定与摘要是同一次请求的两个字段）。不勾时「摘要提示词规则正文」在页面上不可编辑（那段正文在那条路上才会用到）。
- 启用隐私模式时，页面要求用户明确确认**隐私 route** 是本地 route：把它设成本地模型并勾选确认，敏感内容就不会发往外部网络。插件无法自动证明这一点；未确认时按隐私失败策略处理并显示警告。
- `minInlineTokens` 默认 `1024`，`maxSummarizeTokens` 默认 `12500`，单位是 **token**（DSH 令牌计量器的估算值，约 4 字符/token，因此页面按估算口径标注）。低于下限的结果不摘要；上限只作用于 `bash` / `pwsh` / `web_fetch`，超过上限的结果交给 spill 接管。`read` 不设上界：`read` 工具自身按 `readMaxBytes`（默认 50 KiB）封顶，而 spill 硬编码豁免 `read`，所以只有被 spill 接管的工具才需要上界。上界是本插件自己的字段，不读取 spill 的配置。
- 摘要和隐私模式均默认关闭。
- **`web_fetch` 默认不过隐私闸门**：它取的多是外网公开信息，所以隐私开启时它不送本地模型判断（照常走摘要）。取内网地址或含机密页面的部署，在配置区隐私组里勾「`web_fetch` 也过隐私闸门」，勾上后它与别的工具一样逐条判断。其余工具不受这个字段影响。
- 隐私失败策略是全局设置：`sensitive` 始终拒绝；`uncertain`、超时、解析失败和 route 配置失败默认 `passthrough`（放行），也可以配成 `block`（拒绝）。默认放行意味着失效必须可见：设置页卡片常驻警告只在隐私 route 未被确认本地时出现（它只反映静态配置，不反映运行期失效）；被放行的失效则在同一会话内按原因各提醒一条不含正文的插件消息（最多三条，分别对应“未能判断”“判断失败”“窗口不足”），同类原因不重复提醒，且配成 `block` 时不发这类提醒（拦截本身在对话里可见）。
- 本地 route 的服务窗口必须容得下投给它的投影。中文下 spill 的 `maxInlineTokens`（默认 12500 估算单位）约合 3 万真实 token，因此建议服务窗口 32k 起步、中文场景 48k 更稳；否则超大结果会持续判不了并按失败策略放行，插件会在会话里以“窗口不足”提醒。插件不做超窗预检，也不会分块判断。
- 判定敏感时，模型收到的是一条失败的工具结果，内容为固定文案：说明该结果被本地隐私判断拦下、原文未提供，要求不要重试、也不要换工具或改参数再取同一内容，并提示可以用 `ask_user_question` 让用户决定。插件不追加原文、参数或摘要片段。
- 如果这是误拦：在设置页把隐私开关关掉即可，开关立即生效。插件不提供拦截记录或临时放行按钮。
- 摘要提示词、隐私提示词和准入判断提示词只能编辑规则正文与 few-shot 示例；文本域里显示的是当前生效的规则正文，没改过时就是内置默认，改完点**所在组**的“保存”才写回。安全外壳和结构化输出 schema 固定，工具结果会被明确标记为不可信数据。该组的“恢复默认”把规则正文送回内置默认，保存时清掉用户覆盖；把文本域改回内置正文再保存同样只会清掉覆盖。
- 摘要、摘要准入判断和隐私三类请求各有自己的推理档位下拉框：**留空＝不推理**，插件按该 route 声明的档位表拼出对应档位（cline-pass 上是 `None`、deepseek 上是 `Off`；两者都不在表里时取该表里已知次序最低的一档）。**候选就是该模型声明的档位**，标签用 route 给的名字——所以留空时下拉里选中的就是插件会落成的那一档（不会出现「不推理（X）」与 `X` 并列，也不会把另一个拼法画成"不接受"），也调不出它不认的值；该模型不提供推理档位时这一行禁用、请求也不带这个字段。档位表按 provider+model 缓存，一条 route 每次启动只查一次表，之后每次判定都是内存查表；表读不到时显式值原样下发（仍有「被拒后去掉该字段重发一次」兜底）。
- 摘要模型请求的超时、相关摘要条数、附加上下文上限和摘要输出上限由程序固定，页面只读展示。

## 摘要准入判断器

默认关闭。开启后，命中长度范围的结果先经过一次不带工具正文的 `yes/no` 判断：

- `yes`：再发起带正文的摘要请求；摘要无效时原文透传。
- `no`：原文透传。
- 判断失败或返回非严格 `yes/no`：直接发起带正文的摘要请求。

隐私模式开启时跳过准入判断，直接发起一次同时返回隐私结论和摘要字段的请求。准入与摘要之间的前缀缓存只是性能优化，未命中不会改变行为。准入判断会看到这次调用的形态（工具名与关键参数，例如 `read：整文件（无 offset/limit）；file_path=/x/y.ts`——命令只留前 120 字符）与结果估算大小，两者都是元数据、不是正文，用于判断值不值得一次摘要调用；它不知道后续还有多少次请求，所以这不是盈亏平衡计算。

隐私模式下判定为“不确定”时不会产出摘要：该结果既不摘要也不拦截，按失败策略放行原文——不在没判断成功的前提下继续加工内容。

摘要模型还可以主动要求保留全文：当它判断这条结果本身就是要用原文的对象时（例如它正要逐行检查、照抄或对照这段内容，或者你点名要逐行逐条看），它会只给一个信号，插件保留原文、不做替换、也不保存副本。它不会把正文重新输出一遍——原文本来就在插件手里。判据写在正文与这次调用的形态上、不问"谁要求看细节"：没有声明提取目标时，请求里只有「本次调用」（工具名与关键参数，例如 `read：整文件（无 offset/limit）；file_path=/x/y.ts`）、结果估算大小、规则正文与工具正文——**没有你的原话**，所以"用户提过要逐行看"这种条件模型根本观察不到。**声明了提取目标的调用没有这个出口**：见「可选参数 `extract`」。

隐私关闭时，同一会话内按（工具名 + 正文内容）判重：同一工具产出过同一份正文时，再次读取直接返回同一条摘要、不再调用模型；文件改动后内容变化、重新摘要。复用的摘要反映生成时的任务上下文。隐私开启时不做这种复用：每条标准工具结果都会各走一次隐私判断（与上文“每个标准工具结果都会加一次本地模型往返”一致）。如果摘要（含入口说明）不比原文短，就保留原文，也不保存副本。

## 可选参数 `extract`（跟着摘要总开关）

摘要打开后，`bash`、`web_fetch`、`read` 的 schema 会多一个可选的 `extract` 字符串：主模型在调用时**自己声明**要拿回什么（例如「只列出含 payment 的行，带行号」），插件据此改写结果，并在摘要规则里用它替换内置规则。**没有单独的开关**——`extract` 就是摘要能力的对外形态：只有"要／不要"两种有意义的取值，拆成两个开关只会造出"摘要开着但工具不带参数"这种没人需要的中间态。

- **总开关就是「摘要」**（配置区顶端那个勾选，就在「摘要模型」之上；关掉时「摘要模型」与「摘要准入判断模型」两组一起收起）。开关按**每个 agent 创建时**读一次：关掉后新建的会话里工具保持原生形态、摘要提示词这条路不覆盖任何工具也不发任何请求；已经在跑的会话保持它创建时的形态。隐私闸门自成一路、不受它影响（判定与摘要是同一次请求的两个字段）。
- **声明了目标就不再问准入模型**：那次调用直接按目标提取；没声明时行为与关闭前一致（照旧走内置规则与准入判断），所以它是可选增益，不是替代品。
- **声明了目标时"透传"只有一种来源**：结果长度**低于摘要下限**。那种结果由程序直接透传、**一个模型请求都不发**（隐私闸门开着时只发那一次隐私判断）；低于下限之外的结果一律交回短说明——那条路径的输出契约里**没有"保留全文"这个动作**，规则正文也不再提它（不带目标时照旧有，判据不变：这条结果本身就是要用原文的对象时才保留全文）。原文有 spill 留档与入口可读回，所以不给这个出口不会丢东西。
- **关闭就是真关闭**：摘要关着时，模型即使自己写了 `extract` 也不认（不跳过准入、不换规则正文）——否则"关闭"只是不宣传，而不是不生效。
- **带目标的调用不查也不写摘要 memo**：memo 的键只有（工具名 + 正文 hash），不含目标；复用会把另一种问法的摘要当答案返回。
- **隐私闸门开着时**，同一份隐私规则正文之外再固定追加一段：目标只决定"要拿回什么"，不降低隐私门槛；模型要按目标**只交回不牵涉隐私的那部分**（涉隐私的值用占位或省略），目标必须依赖隐私内容、脱敏后满足不了时就照旧返回 `sensitive`/`uncertain`，走既有的拦截或失败策略。这一段的文字由插件固定、不另设第二份可编辑提示词；用户的隐私政策仍写在同一份隐私规则正文里，两种模式共用。
- **安装方式按工具分开**（实测见 `.scratch/dsh-result-clipper/exp2/RESULTS.md`）：`read` 与 `pwsh` 只用 agent 作用域遮蔽（`read` 与 `write`/`edit`/`read_image` 同一条目，禁用会连坐；`pwsh` 的工具包不是本包的依赖，运行期 `import` 解析不到，见 `.scratch/dsh-result-clipper/design-draft-local-task-context.md` §22）；`bash` / `web_fetch` 各自独占一个条目，所以部署可以先用 profile patch 关掉原生条目，插件再把它挂回来并**就地**补参数（注册表没有替换 API）；原生还在时自动回落到遮蔽。
- **想让插件成为唯一注册者（"真单关"）**：在保存 preset 的地方关掉 `tool-bash` 的条目、并把 `tool-web` 的取回关掉；插件按平台决定挂哪一个 shell——`bash` 只在非 Windows（判据与 base bundle 的 `!!js process.platform` 同一套），`pwsh` 不接管、由遮蔽补参数：
  ```yaml
        - id: tool-bash
          name: '@deepseek-ai/dsh-tool-bash'
          disabled: true
        - id: tool-pwsh
          name: '@deepseek-ai/dsh-tool-pwsh'
          disabled: !!js process.platform !== 'win32'   # 保持 base bundle 的平台条件：Windows 上留给遮蔽
        - id: tool-web
          name: '@deepseek-ai/dsh-tool-web'
          config:
            fetch: false     # 只关取回；web_search 仍由这一条提供
            search: true
  ```
  这一档的好处是运行期只有一份定义（模型侧 schema 与执行体同源），代价是插件若挂不回来那个工具就缺失；插件在 `agent/created` 上尝试挂载，失败只记一条 warn、不会把 agent 创建弄失败，下一次创建还会再试。`read` 没有这一档，`pwsh` 也不能有——那个包在本包的解析基点上不存在，接管失败在 Windows 上会连唯一的 shell 一起失去。每次装载会往 debug 文件写一行 `kind: "mount"` 的记录（工具名 → `takeover`/`shadow`/`absent`），这就是"真单关到底有没有生效"的观测点：接管成功与"原生还在、只是遮蔽"交出的工具完全一样，只能靠它区分。
- **遮蔽只在"该 agent 本来就看得见这个工具"时才安装**：作用域自有注册不过 `allow`/`deny` 过滤，若是无条件遮蔽，等于把某 agent 的禁用名单悄悄解除。
- 影子工具把 `extract` 摘掉后才委托原生执行；替换仍只作用于**模型可见内容**，规范值不变（`run_code` 里的程序拿到完整值）。
- debug 记录里有一个 `extract` 布尔，表示这次调用有没有声明目标（只记布尔、不记目标正文），用来观察"主模型判断该不该传参数"准不准。

## 原结果入口与保留

摘要替换正文前，插件把完整原文交给 DSH 的 spill 存储；替换后的模型可见内容**先给摘要正文，再跟上入口说明这段兜底**。兜底段自报身份（「以上为本次 … 结果的摘要，够用就不必再读」）并给出位置与取回说明，需要逐字核对时据此重新读取全文。先摘要、后入口是有意的顺序：实测 246 条带入口的真实结果里，取回动作有 67% 落在紧接着的下一次调用、43% 是整文件一把读回，而原来的消息里没有一句说明这是摘要、也没有一句说够用就别读（旧顺序「入口在最前」的依据是旧结果裁剪器只保头 4096 / 尾 1024，而本替换结果只有几百字符，远低于它的 8192 阈值，且裁剪器头尾都留）。本机后端返回的是绝对路径，取回说明提示用 `read` 或 `grep` 打开它；文件读取不受 fs 沙箱限制（沙箱只管写入），所以沙箱部署同样能读回。如果摘要没有比原文短，插件保留原文、也不保存副本。

“按入口读回不再摘要”只在当前会话内有效：插件记住本会话写出的入口位置；重启或 fork 之后这个记忆不再保留，同一入口会被当成一次普通读取、重新摘要一次。

原文的保留与清理由 DSH 的 spill 后端负责，插件不额外管理：本机后端的默认行为是按 `cleanupPeriodDays`（默认 30 天）在进程启动时清理一次。插件不设条数上限，也不承诺比 DSH 更短的保留期；需要清得更勤时应调整 DSH 侧的 spill 配置。存储后端不可用或写入失败时，该结果原样透传、不摘要。

## 与 DSH 默认组合共存

摘要结果足够短，不会被默认启用的旧结果裁剪器（`dsh-compaction-tool-result-pruner`，默认阈值 8192 字符）改写；入口说明接在摘要正文之后（**裁决 C，2026-10-05**：原先在最前），裁剪器保头也保尾，所以放末尾同样不会被裁掉。插件不读取其他插件的配置。

本插件与推理裁剪（`dsh-reasoning-pruner`）互不影响：后者只处理助手消息里的推理块，不读取工具结果内容。

加载顺序影响隐私判断的对象：本插件与 spill-policy 都注册在 `tools/post-execute` 且都要求排在最前，插件需要**装载在 spill-policy 之后**才能看到截断后的内容。顺序相反时，判断对象退化为原文——更保守、可能误拦，而且请求可能超出本地模型窗口；这是已知且可接受的退化方向。

## Debug 日志与干跑

debug 默认关闭。开启后必须填写日志路径；插件自动创建父目录，并以追加方式向该路径写入 metadata JSONL，例如工具名、结果大小、准入结论、结果取值（动作是「已替换 / 已拦截 / 未改动」之一；未改动时附原因：未进入候选、准入判 no、模型要求保留全文、按入口读回、摘要没变短、隐私判定不确定、摘要提示词路径关闭、规则摘要关闭、失败、窗口不足）、调用耗时、缓存观测、判断器输入 token 数，以及这次调用有没有声明提取目标（`extract` 布尔）。每次装载还会先写一行 `kind: "mount"` 的记录：平台，以及 `bash`/`web_fetch`/`read`/`pwsh` 各自走的是 `takeover`（全局接管）、`shadow`（遮蔽原生）还是 `absent`（这个 agent 看不到它）。不会自动改用临时目录，也不会覆盖已有文件。干跑记录写进同一条日志，因此同样不含原文与摘要文本。

干跑走完整条流水线，但绝不替换任何内容、不写会话事件、也不调用存储保存原文，只在 debug 日志里记录“本应发生什么”（本应替换 / 本应拦截 / 本应跳过及原因）。它要求 debug 开关已开启且日志路径已配置：两者缺一时干跑不生效，页面会提示（所以干跑不会绕过“debug 关闭时不写文件”这条）。

debug 日志不记录工具原文、摘要正文、完整提示词、API key 或其他凭据。请为日志文件选择当前 profile 可写且访问受控的位置，并在共享机器上关闭 debug。

## 使用注意事项

- 摘要模型的判断是任务相关的概率判断。它可能选择透传，也可能摘要不足；原结果入口用于需要细节时重新取得全文。
- `additionalContexts` 不会被摘要；正文摘要与附加消息可能同时存在，后者仍按 DSH 原有顺序进入后续请求。
- 摘要模型请求失败时，摘要模式保留原文；隐私模式按配置的失败策略处理，默认放行。
- 只有本地 route 才适合启用隐私模式。route 的本地性由用户确认，插件不会替用户验证网络边界。
- 关闭摘要准入判断器后，流程恢复为直接把完整结果交给摘要请求；关闭摘要插件后，工具结果保持 DSH 原有行为。
- 首版不在读取层面做去重：每次 `read` 仍会真实读取文件、重新做隐私判断；被复用的只有摘要本身（按正文内容判重，且只在隐私关闭时）。
- 首版不记忆已经判过敏感的调用：同一调用再执行会重新判断，结果可能不同。防绕过的第一道手段是拒绝文案本身。
